# 样本基线与 360：2026-10-24 中午的一次实测（含我的两次回退）

> 目的：把"`--release` 现在到底红在哪"钉死，避免下次又从头查。

## 一、360 关掉之后

| 步骤 | 360 开（11:3x） | 360 关（12:4x） |
|---|---|---|
| `release-criterion` | **SKIP**（`Copy-Item vcruntime140.dll ⇒ PermissionDenied`，手动试拷也拒） | **PKG-RELEASE ok**（真跑 `-Dev:$false` 打包链通过） |
| `pkg-platform` | — | **PASS**（包内 qwindows+qoffscreen，产物里真跑自检） |
| `package-pages` | — | **ok**（默认六页 + 抬 `_fixtures` 七页生效） |
| `version-identity` | 未跑 | **PASS**（`exe_sha256` 三处同值） |
| 整档 `--fast` | PASS（2 条未覆盖：真语料文本 + 打包前提） | PASS |

⇒ **AV 只是外部前提**，判据把它记成"环境不具备"是对的（没有伪装成绿）。

## 二、`--release` 现在唯一的红：**文本样本内容漂移**（不是缺失）

```
FAIL 缺少外部前提（release 档零容忍）：真语料文本样本 —— 样本缺失或内容变动（见上）
```
直接跑三个脚本看 rc（**只有 decode 是 2**）：
```
golden_text_extract.py  rc=0  PASS (compared=2 failed=0)        ← 真实样本缺失时走 synth
golden_text_sniff.py    rc=0  PASS (compared=95 failed=0)
golden_text_decode.py   rc=2  PARTIAL (compared=103 failed=0 stale=2)
                              样本内容变了（与基线记录不符）2 个：
                              real/002_character_desc_agroprom.xml, real/069_XR_3DA.exe
```
⇒ 红的原因是 **两个 real 样本的字节与基线记录不一致**，**不是"样本没了"**。

## 三、我试过、又回退的两件事（记下来免得重做）

1. **从 `gamedata.db_base` 解一份到样本根**（用户裁定的两条正路之一）：
   `--unpack-package <GS>/gamedata.db_base "<…>/原件/Golden Sphere" --only <gameplay+scripts 清单>`
   → 成功解出 `gamedata/config/{gameplay,scripts}`（59 + 2095 文件）。
   **但**基线期望的是 **102 个文件**，我们解出 **60** 个 ⇒ `golden-text-extract` 从 SKIP 变成
   **FAIL（产物树不一致 71 处 / strings 1383 vs 1207）**。
   ⇒ **已把解出来的 `gamedata/` 整个删掉、样本根还原**。结论：**DB 里的内容与当初记基线的树不是同一份**，
   解一份出来只会把"缺样本"换成"样本不对"（更糟：看起来像产品 bug）。
2. **把 `golden_text_sniff/decode` 也改成 `samples.find`**：补丁有 `Path` 未导入的顺序错误
   （`sys.path.insert` 用了 `Path` 但它在下面才 import）⇒ 直接 NameError。
   ⇒ **已 `git checkout` 还原这两个文件**，不带走。

## 四、需要你裁定的一件事（我不动基线）

`golden-text-decode` 的 2 个 real 样本与基线不符。三种处置，**都要你点头**：

| 方案 | 做法 | 代价 |
|---|---|---|
| A（推荐） | 把这两个样本**冻结**成副本（换到 `samples/` 下一个只读目录），decode 指向副本 | 基线不动、判据仍有效；多一份 ~小文件副本 |
| B | `--write` 重记这两条的基线 | **改基线**：以后就测不出这两个文件的漂移了 |
| C | 维持现在（release 红） | 每次 `--release` 都红在这一条（已知、可解释） |

★ 我倾向 **A**：你正在做普里皮亚季编年史的汉化，这些 xml 很可能就是**你在改的文件**；
  把"判据用的样本"和"你手里的工作副本"分开，两边都不互相拖累。

## 五、此刻的门禁账

```
--fast     → PASS（0 条未覆盖？见下）
--release  → FAIL（1 处：真语料文本样本 —— 内容漂移 2 个）
```
★ 注意：`--fast` 里 `golden-text-decode` 的 rc=2 会走 `prereq` ⇒ 记 SKIP + 未覆盖；
所以 `--fast` 的"未覆盖"条数随这 2 个样本的状态变，**不代表代码质量变**。
