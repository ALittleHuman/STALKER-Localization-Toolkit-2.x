## A. `extract_tree.h`（258 行）—— 落盘安全与"落点规则只许一份"

### 1. 为什么必须在引擎层（第 4-7 行）
归档条目名是**不可信输入**（本工具主要入口就是"打开网上拿到的 mod 包"），而落盘＝**任意文件写**。
⇒ 这条判据必须和"写文件"绑在同一个函数里，页面只传参。

### 2. `safe_out_path` 的六条拒因（第 9-21、46-54 行）
① 空/非串；② `/` 或 UNC 开头；③ `rel[1]==':'`（盘符）；④ 分段含 `..`；
⑤ 段内冒号（NTFS ADS）；⑥ `commonpath` 兜底复核。

★ **F-1（2026-10-06）**：`..` 的判据从"**字节精确匹配**"改成"**按 Windows 有效名比较**"
（剥掉末尾空格/点）—— 否则 `".. "` / `".. ."` 这种段会**假绿**。
⇒ **这是"判据被输入变体绕过"的经典一例**，与我们判据里"字符串前缀匹配"的坑同族。

### 3. ★★ P17-103：落盘前的**真实文件系统**复核（第 56-62 行）
`safe_out_path` 只看**名字**；`refuse_if_link_traversed` 看**盘**：从输出根到落点父目录逐段查，
任一段是软链接/重解析点、或不是目录 ⇒ 返回非空理由（调用方记进 `failures`，零静默）。
落点**自己**是软链接时也拒绝（跟写＝写到根外；原子重命名＝替换那个链接，另一种静默）。

### 4. ★★ 落点覆盖必须可见（第 127-138 行）
起因（用户报的真实事故）：解包到**默认落点**（＝来源所在目录）时，一次把 **3.9 万个文件**
盖在了模组目录上，而工具**一个字都没说**。
处置：`overwritten` 逐条路径 + `overwritten_size()` 计数；**不弹模态确认框**（不改交互口径）。
判据落点：`overwritten_size()` —— 写回"不检测"（永远 0）即红。

### 5. ★ `paths_carry_shell` 的量词从"全部"改成"**过半**"（第 183-191 行）
真机 9 个 VESSEL 包**每个恰好含一条**根级 `readme.md`（8148 B）、其余条目全在 `壳/…` 下
⇒ "全部"量词把它们判成"不带壳" ⇒ 解出 `ai/ai/alife/…`（违背用户口径"就解出来一个 configs"）。
`IWP\database\config\configs.db`（27/27 带壳，多一条 `a.txt` 就翻转）是同族不稳的现场。

⇒ **这是"量词选错 ⇒ 判据在真实语料上翻转"的样板**。我们判"页是否就绪"时也要问：
  用的是"全部子件"还是"存在一个"？哪个才是用户语义？

### 6. ★ `unique_entry_count`（第 194-199 行）：包内记录数是产物数的 **2 倍 − 1**
`IWP\database\maps\*.db` 的 HEADER 表把**除根记录外每条记录登记了两遍**（同路径/同 offset/同 size）。
分工：协议层（`--dump`）报**包内记录数**（忠实、不去重）；产物层报**产物口径**。
现场：26 条记录 / 实际 13 个文件、4,451,688 B / 实际 2,225,844 B（改前报数正好是真实值的 2 倍 −1）。

⇒ **"同一个数在两个层各有正确含义"** —— 判据必须说清自己报的是哪一层，否则永远对不上。

### 7. ★★ `selection_matches`（第 241-256 行）：两份实现 ⇒ 静默 0 命中
病根：页面把**落点相对路径**（带包名壳）塞进 `only`，而引擎比的是**镜像内路径**
⇒ 不自带壳的包**一条都命中不了** ⇒ 界面"解包：0 个文件"、CLI 退 0，**一个字不说**。
现在规则收到引擎一处，两边都调它（落点路径 **或** 镜像内路径相等都算命中）。

⇒ **这是"同一条规则两份实现"的第三次出现**（前两次：`_is_pack_file`/闸门、落点规则）。
  我们判据里"判断页是否就绪"如果也写了两份（判据一份、产品一份），就会同一个下场。

## B. `link_check.h`（110 行）—— 一个把"实测"写到极致的头

### 1. Windows 上 `std::filesystem` **看不见 junction**（第 9-16 行）
实测：`mklink /J` 造出来的目录，`symlink_status()` 报的是 `directory`。
⇒ Windows 必须走 **`FindFirstFileW`**（一次调用同时给属性与重解析标签 `dwReserved0`）；
`GetFileAttributesW` + `CreateFileW` 那一版**实测判不出来**（junction 被判成 0）。

### 2. ★★ P17-121：判**位**不判清单（第 37-55 行）
修前只认 `IO_REPARSE_TAG_MOUNT_POINT` 与 `IO_REPARSE_TAG_SYMLINK` 两个值 ⇒ 任何别的
"名字代理型"重解析点都漏网（复审计点名 WSL 的 `LX_*` 族）。
现在判**名字代理位** `0x20000000`（置位 ⇒ 路径解析会跟走）；过滤器/元数据型
（WOF `0x80000017`、Dedup `0x80000013`、AppExecLink `0x8000001B`、云端 `0x9000001A`）不置位。

★ 并且**如实标注边界**：本机没装 WSL ⇒ `LX_*` 那类标签**无法实测**，归为 follow 是
**按官方位定义推出来的，不是实测结论**；判据里有自曝。

### 3. ★★ S-06：`StatFailed` 必须与 `NotLink` 分开（第 60-73 行）
修前 `FindFirstFileW` 失败直接 `return false` ⇒ **fail-open**：非法字符、超长路径、权限异常……
任何一种"stat 失败"都被读成"这里没有链接，放心写"，守卫在最需要它的输入上**静默失效**。
现在三态 `NotLink / IsLink / StatFailed`，**只有"路径不存在"才算 NotLink**；
守卫侧（`refuse_if_link_traversed`）选择**拒绝** —— 守卫就该 fail-closed。

⇒ **"判不出来"必须是一个独立状态**。这与 `db.h` 的 `untrusted`、`LooseInfo.truncated` 同族：
  **三态/四态化是本仓的通用手法**，二态（是/否）会把"不知道"塞进"否"里。

## C. `untrusted_limits.h`（81 行）—— 常量收拢与 `static_assert` 钉关系

- LZHUF 声明长度上限 256 MiB（逐字节哈夫曼，按声明长度**一次分配**）；
- DB 单条目解压 512 MiB（覆盖真实语料最大单条目）；
- DB seek 头读取 512 MiB（语义不同，防第二个裸字面量）；
- **退回整包读**上限 512 MiB（P17-111：修前无上限 ⇒ 用户在文件对话框指一个几 GB 文件就被整读）；
- **DB 封包总量** 2 GiB（T-05：峰值 2–3 倍，1.9 GB 包会 OOM；环境变量**只能往小改**）。

两条 `static_assert` 钉住关系（74-78 行）：DB 单条目 ≥ LZHUF 声明；封包总量 ≥ 单条目。
理由写得很清楚："能声明、却过不了 LZHUF 闸 ⇒ 读得进却解不开"。

⇒ **用 `static_assert` 把"数值之间的语义关系"钉死**，比写注释强一个量级。

## D. `compress.h` / `decompress.h` / `lzhuf.h`（81 行合计）

- **零外部 exe** 是硬口径（1.x 血账：外部工具被 360 按哈希拦）。
- xz 参数：`lzma_lzma_preset(6)` 后**覆盖** `dict_size=131072, lc=3, lp=0, pb=2`，check=CRC32，
  过滤器链只有 LZMA2。
- ★ **必须走 `lzma_stream_buffer_encode`（单次、整块）**：它会在块头写
  `compressed_size / uncompressed_size`；流式 API 不写，**产物少 4 字节**（实测参照 664 vs 660）。
- 块语义：**没有容器头**（gzip=zlib 流、xz=xz 流、zstd=帧、lz4=**块格式无帧头**、lzo=lzo1x 原始）。
- LZHUF：位流方向、Huffman 更新顺序（原版是 do-while，**不能写成 while(c)**）、四张常量表
  都必须与 1.x 一致 —— 错一格整包就废；常量表由 `lzhuf_tables.inc` 从 1.x 生成。

## E. 这批给"红点"的可执行结论

1. **二态判据是本仓公认缺陷源**（`LinkProbe` 三态、`LooseInfo.truncated`、`trusted`）。
   ⇒ 我们的 `settle`/`page_ready`/`menu_ready` 也该是**三态或四态**（未发生 / 发生但页不匹配 /
   发生且匹配 / 不该出现），并把"不该出现"写成硬断言。
2. **量词必须与用户语义对齐**（`paths_carry_shell` 的"全部 → 过半"）。
   ⇒ 判"页就绪"时：是"所有子件都在"还是"存在视口"？要选与用户感受一致的那个。
3. **同一规则不许两份实现**（`selection_matches`：两份 ⇒ 静默 0 命中）。
   ⇒ 我们判据里的"页是否占位"目前是**判据自己算的**（找 QLabel 文案），产品那边另有一套
   （`make_placeholder`）—— **这就是两份实现**，必须改成"问 Hub 要状态"（方案 2）。
