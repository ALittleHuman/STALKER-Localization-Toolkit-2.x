# `engine/xml/compare.h`(190) ＋ `engine/fs/db.h`(165)

> 这两个头里各有一条**可以直接搬来修我们 P5/P13/P16 判据**的写法：
> `xml` 的"摘要路径不许调完整明细"计数器；`db` 的"四态真值表"。

---

## A. `engine/xml/compare.h`（190 行）

### 1. 10.6 行数口径（第 63-67 行）—— **必须与 Python 逐值一致**
`split_lines()` 的边界 = `\n \r \r\n \v \f \x1c \x1d \x1e \x85 \u2028 \u2029`；
**结尾是边界不额外多一行**；空串 0 行。
修前 1.x "对结尾换行 +1"，导致"A 有结尾换行、B 没有"被误判成不一致（第 6-7 行）。

⇒ **教训**：凡"与 Python 对拍"的判据，注释里直接写"等价于 `str.splitlines()`"，别自己发明。

### 2. ★ 10.3 的**性能锁**：`DetailCallStats::full_detail_calls`（第 111-121 行）
`inline_detail()`（每行都调的摘要）**绝不调** `full_detail()`；
后者只在"选中一行/双击"时调，并 `++stats.full_detail_calls`。
1.x 实测：1 万行时填充从 89ms 涨到 327ms，就因为每行都调了一次 detail_builder。

⇒ **这是"用计数器把架构约束钉死"的样板**：不是量耗时（那样会假红），而是断言
"摘要路径调用完整明细的次数 == 0"。**我们判 P5/P13 也该用这种结构断言，而不是等时间。**

### 3. 唯一哨兵 `kBuiltinPlugin = "<builtin:xml>"`（第 49-50 行）
1.x 有两套哨兵（`"<builtin:xml>"` 与 `"<builtin>"`）⇒ 插件重名就能顶掉出厂内置模式。
2.0 统一成一个，`registry.h:19-20` 也指这里。

### 4. `XmlTextSide.trusted`（第 131-137 行）
解析失败 ⇒ `ok=false, trusted=false` + warning，**调用方必须告警，不许静默**。
⇒ 与 `DbListing` 的 `untrusted` 同族：**"结果不可信"是一个具名状态**，不是"空结果"。

### 5. CSV 口径（第 181-188 行）
先写 `\ufeff`（Excel 不认无 BOM 的 UTF-8）、行结束符 `\r\n`、需要时按 excel 规则加引号；
写盘**不做换行翻译**（1.x 用 `newline=""`）；`generated_at` **由调用方给**
（引擎不取系统时间，便于对拍）。

⇒ "引擎不取系统时间"这条对判据很重要：**时间戳不该进被测输出**。

## B. `engine/fs/db.h`（165 行）

### 1. ★★ P17-137：`used_seek` / `whole_file_reason` 是**四态真值表**（第 109-124 行）

| used_seek | reason | 含义 |
|---|---|---|
| true | 空 | 正常 seek：只读块头与尾部表，**没有**退回 |
| true | **非空** | 按显式选定的格式**直走** seek（理由说的是"为什么直走"） |
| false | 非空 | **退回**整包读（理由说的是"为什么不得不整包读"） |
| false | 空 | **不该出现**（退回却没理由 ⇒ 那本身是缺陷，页面会喊出来） |

作者还写明：`whole_file_reason` 名字是历史包袱（现在装的是"读取方式的理由"），
**保留名字、把语义写死在这里**。

⇒ **这是我们最该抄的一条写法**：把两个布尔/字符串字段的组合**写成真值表**，
并明确"哪一格不该出现"。我们给 `menu_ready` / `page_ready` / `worker_finished` 加状态时，
也应该写这样的表，而不是散落在 `if` 里。

### 2. T-02：`DbListing::read_path`（第 125-130 行）
没插件解密器命中时 == 入参 `path`；命中时 == **解密产物**路径。
原因：`entries` 里的 `offset` 是**按这份文件**算的；拿原始加密路径去逐条提取
⇒ 「列条目成功、逐条提取报偏移越界/读出垃圾」（修前真实现状）。

⇒ 与本项目当前的 `settle`/`read_path` 类问题同族：**"用哪份文件"必须跟着结果一起传下去**。

### 3. T-05：DB 封包内存闸门（第 71-81 行）
封包全程在内存（`DbPackItem.data` → 拼接的连续 data → 原子写又拷一份）⇒ 峰值 2–3 倍，
修前无上限（1.9 GB 包会 OOM）。现在一条 `XRKIT_DB_MAX_PACK_BYTES`（2 GiB），
环境变量**只能往小改**（下界 >0、上界为默认值）；**两道闸**：调用方读文件之前量一次，
`pack_db` 自己再量一次（公开 API 不许绕过）。

### 4. T-04：两条 4 GiB 窄化检查**无条件**（第 85-91 行）
`error` 是**可选的出错理由，不是开关**：不给它照样检查、照样拒绝；命中时返回空 vector
（调用方不许写盘）。**产物形态不受出参有无影响。**

⇒ 与 `atomic_write.h` 的诚实口径、`db.h` 的四态真值表是一套哲学：
**行为不随"诊断参数"变化**。这条直接对应我们加的 trace/钩子 —— 加了诊断不许改变产品行为。

### 5. 判定口径（第 44-45 行、100 行）
- `auto_detect`：**唯一自洽才返回**，歧义返回 `nullopt`（让调用方显式选）。
- seek 版与内存版**逐值一致**；任何一步对不上**不猜**，直接退回整文件读。

## C. 这两份文件给我们的三条可执行启发

1. **判据要用结构断言，不用耗时**（`full_detail_calls == 0`）。
   ⇒ P5 该断言"页是 `PageBase` 且 `viewport()->fit()==Content`"，而不是等 2000ms。
2. **状态组合写真值表**（`used_seek × reason` 四格，且写明"哪格不该出现"）。
   ⇒ 给 `page_ready` / `menu_ready` 定义 `(signaled, page_matched, actions)` 的合法组合，
   把"不该出现"的格子变成硬断言，而不是靠 note 打印。
3. **行为不随诊断参数变化**（T-04 的 `error` 不是开关）。
   ⇒ 我们 `XRKIT_PAGE_TRACE` 开关必须**只影响是否写 trace**，不许影响任何判定路径
   （这一点目前做到了，但要有判据锁住 —— 可以加一条"trace 开/关两次跑，`checks` 数量一致"）。
