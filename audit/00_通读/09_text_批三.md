## B. `case_fold.h` 其余要点

### 1. 为什么不"用 Windows API 模仿 Python"（第 3-7 行）
全域复核 `0x20..0x2FFFF` 后，Windows invariant 小写与 Python `str.lower()` **单字符内分歧
131276 个码位**（`U+01C5 ǅ` / `U+0524 Ԥ` / `U+03F4 ϴ` …），且 `U+0130 İ` 在 Python 下折成
**两个**码位（`i` + `U+0307`）而 Windows 不动。根因：两边各自一套 Unicode 版本与映射口径。

⇒ **"模仿"这条路本来就跟不上** —— 正确做法是**从本机 CPython 导出表**
（`case_fold_table.inc`，`--check` 与门禁 `case-fold-table` 步逐字节守着"表没漂"）。

★★ 这条对我们是**方法论级**的：**判据要对着"真值来源"对拍，不要对着"另一套近似实现"对拍。**

### 2. 边界如实写（第 14-25 行）
- 只做 `str.lower()` 的单码位/多码位映射，**不做** `str.casefold()`（`ß`→`ss` 那类）；
- ★★ **KNOWN_DIVERGENCE**：上下文相关映射**复现不了**，唯一成员 `U+03A3 Σ`
  （`'ΟΔΟΣ'.lower()` 得 `'οδος'`，本表恒给 `σ`）；实测**只有这 1 个**（Unicode 16.0.0，
  CPython 3.14），**不是"可能还有别的"**；
- 触发条件：语料出现希腊文、或对拍出现 `ς` ⇒ 那时才升 B（引入上下文感知表）；
- 表只覆盖到 `U+2FFFF`（更远原样返回）。

⇒ **"已知分歧"必须写成穷举台账 + 触发条件**，而不是"可能有些差异"。
  这比"我们尽力了"有用一百倍。

### 3. `case_fold_append_one`（第 37-83 行）
① 先查多字符例外（数量极小）；② 区间表按 `first_cp` 升序 **二分**；命中后手写 UTF-8 编码
（注释：比依赖 locale 稳）；无映射返回 0，调用方原样追加。

### 4. `case_fold_lower`（第 86-134 行）：非法字节**原样透传**（不猜、不吞）
截断序列也原样透传。⇒ 与"不假装支持"同一口径。

## C. `extract.h`（103 行）—— 文本提取

### 1. 口径（第 8-13 行，1.x 血账）
- **候选遍历必须排序**：Python set 迭代随哈希随机化，不排序会让**同一份源两次运行得到不同 ID**；
  这里直接产出"排序去重"后的候选表。
- **正则用 PCRE2**（`std::regex` 不支持 lookbehind）；`PCRE2_UTF|PCRE2_UCP` 对齐 Python `re` 的
  Unicode `\s` 语义。
- 源目录名必须是 `gameplay`/`scripts`（只看文件夹自己的名字，不向下查找）。

⇒ **"同一输入两次运行结果不同"是判据最恨的**（不可复现）。排序去重是硬要求。

### 2. ★ `should_stop` 只在**文件边界**轮询（第 35-39 行）
"停下来时已写出的产物都是**完整的单文件产物**，绝不写半个文件
（零静默的反面：**'停是停了，但产物半截' 比不停更糟**）。"

⇒ 这条与我们 P17-1② 的取消位判据直接相关：**取消的验收标准是"产物完整"，不是"停了"**。

### 3. ★★ S1-1（第 50-55 行）：`write_failures` 必须让 `ok=false`
修前两条路（编码失败/写盘失败）只往 `skipped` 塞一条、`ok` 仍 true
⇒ 调用方按 `ok` 判退码时表现为"**产物一个都没落盘却报成功**"
（`--clean` 把源目录删空之后 `files=0` 也照样退 0）。

⇒ **"有失败但 ok=true"是本仓的典型假绿**。我们的判据（`check_..._pages.py` 的 rc）
也必须是"任何一项失败 ⇒ 非 0"，不能"只有整体跑不起来才失败"。

### 4. ★ `repl_skipped`（第 56-65 行）：保护而非无脑替换
两类理由：命中在**注释**里（.ltx 的 `;` 之后）、命中落在**更长标识符内部**。
1.x 是裸 `str.replace`，上面两件事它都做（实测），**破坏是静默的**；
2.0 改成"跳过 + 逐条报出来"，计数进 ASCII 收尾行 `replskip=`。

⇒ **"不破坏语料"优先于"替换得更多"** —— 这是一个产品判断，且**有判据**（replskip）。

### 5. `cancelled` 与 `ok` 的关系（第 68-72 行）
`should_stop` 返回 true ⇒ `cancelled=true`，`ok` 仍 true（没出错）；
**调用方必须先看这个位再报结论**（否则会把"取消"报成"完成"——那就是静默）。

## D. `encodings.h`（21 行）

- 源/目标**共用**一张表（1.x `ENCODING_CHOICES` 与 `convert_app.py:192` 的交集，双字节＋编码侧
  已全量对拍；utf-16/32 六族也于 2026-09-26 对拍过 ⇒ 可以列）；
- **只在目标侧**多一项 `ascii`（源侧不放它 —— 源是"猜"的，塞进去会让人以为工具会猜 ascii）。

⇒ **表项成员资格是产品纪律**（"只列与 Python 逐字节对拍过的编码"），不是界面品味。
  这与 `widget_facade.h` 的"表外无门"是同一条治理思路。
