# font 批：charset(54) / metrics(128) / glyph(40) / package(46) / render(74) / resample(30) / system_dirs(21) / xml_bytes(34)

> 8 个头全部读完（合计 ~427 行）。font 模块是"逐字节复现 Pillow + 1.x"最极端的一块，
> 里面有三条**判据方法论**级别的教训，直接可用。

---

## A. ★★ `xml_bytes.h`：`read_bytes` 写了两份 ⇒ 打不开被当空文件（A1-4）

事实（修前）：`charset.cpp` 与 `package.cpp` **各写了一份** `read_bytes`，打不开就 `return {}`；
而 `decode_xml_bytes({})` **必然成功**（`decode_strict` 对 0 字节不进循环即 `return true`）
⇒ 出包侧**写出空 XML 并记成功**、字符集侧**整份语料的字符被静默丢弃**
（`files_scanned++` 而 `files_undecodable` 不变）。
触发条件：文件被独占锁 / 权限不足 / 超长路径。

⇒ **这是"两份实现 + 空输入合法"叠出来的静默失败**，与我们看过的
`selection_matches`（两份实现 ⇒ 静默 0 命中）、`host_run_process`（字段名不一致 ⇒ 自查恒假）
是同一族的第 4 例。

### `CharsetResult.files_unreadable`（charset.h:28-32）
为空文件与打不开**分开计数**；开不了的文件必须计入失败（调用方据此拒绝出包）。

## B. ★★ `render.h`：**Python 的 `//` 与 C++ 的 `/` 在负数上差 1**

```
★ Python 的 `//` 是**向下取整**，C++ 的 `/` 是向零截断 —— 负数会差 1
  （如 `-3//2 = -2` 而 `-3/2 = -1`）。凡是给 `//` 当分母 2 的地方
  （`bbox_y0//S`、`(asc+desc)//S`）一律走 `floor_div`。
```

⇒ **这是"跨语言对拍"最隐蔽的一类差异**：只在意负数（墨迹 bbox 的 y0 完全可能是负的）。
  我们在判据里做整数除法时也要问：**会不会有负数？**

### 其它照抄要点（第 7-17 行）
- `fit_render_size`：候选 `size..size+13` 取最大的、满足 `墨迹高 ≤ cell−4` 且 `墨迹宽 ≤ min(推进宽, cell)`；
- `vshift = max(0, cell − (asc+desc)//S)`；
- 画布 `tex_w` 1024→2048→4096；`tex_h` = ≥max_y 的 2 幂；
- 宽度裁决顺序 `rect_w_for/advance → punct_box_px → clamp_box_to_ink → 封顶 cell → ink_draw_w`
  （与 metrics.h 的 `adjudicate_box` **共用一处**）；
- ini 行 `f"{cp:05d}= {x}, {y}, {x+rw}, {y+cell}"`；
- `.ini` 里是 **CRLF**（1.x 文本模式落盘），`to_windows_newlines` 把**每一个** `\n` 翻成 `\r\n`
  （不是"已经是 CRLF 就跳过"）。

### ★ 两道守卫（第 60-72 行）：没有它们会"十张图集全是同一个方框，而工具照样报完成"
`font_missing_chars`：**按类别成组抽样**（CJK / 西里尔 / "A"），整组都画不出才算该类别缺失
⇒ 用于**拒绝**废字体；`font_unrenderable`：逐字判定 ⇒ 用于**逐字告警**
（日文字体缺 Є І Ї 这类西里尔扩展是常态，不该拒绝整包）。

⇒ **"拒绝"与"告警"必须分级** —— 这一条在我们判据里也可以照用：
  有些红该判死（页没建出来），有些红只该告警（菜单偶发采集失败）。

## C. ★★ `metrics.h`：判据的"样本"本身是判据的一部分（第 114-117 行）

```
// 判定样本（1.x `CJK_SAMPLE`）——**判据的一部分，不许随手改**：
//   老样本"永你好汉化测"漏了"简体特有"的字，日文字体照样判 ✓ 中文，
//   而预览里那几个字是整字宽的空洞。现在混入简体特有的字，缺一个就 fail-closed。
```

⇒ **"样本选择"决定了判据能不能发现问题**。我们的夹具样本（`门面L2b` 等）同样是判据的一部分：
  如果样本内容太"健全"，就测不出占位页。

### 11.8 四态（第 92-106 行）
`ok / japanese / missing / unknown`，其中 **`unknown` = 检测失败**，与"缺字形"不是一回事。
判据：`ok` 要求**不同 bbox 数 > 1**（全同 = 字体对什么字都画同一个方块）。

★ 并且**如实记录与文档的差异**（第 103-105 行）：对照表写"缺的简体字**全都能**用繁体顶上"，
而 1.x 代码是 `if sample_fallback(path):` —— **非空即可**。**照代码不照文档**，差异记账。

⇒ 这条对我们尤其重要：**用户的验收口径写在文档里，实现可能不一样；判据必须跟实现一致，
  但差异要显式记账**（否则就是你"改"了行为却不自知）。

## D. `package.h`（46 行）：三处"看着一样实则不同"

- 字号表 `SIZES` = 11/13/15（S=1）+ 16/17/18/20/21/23/25（x2）；`render_size = size + offset`，
  但**文件名与 ltx 仍用槽位名**；
- ★ **XML 只扫顶层**（`sorted(os.listdir(xml_dir))`，**不递归**）—— 与 `extract_chars` 的**递归不同**！
- 任一字号失败 ⇒ **把已写出的 gamedata 整个删掉**（否则用户看到半成品以为成功）。

⇒ "两个函数一个递归一个不递归"是**故意的**，照抄才逐字节一致。**判据必须按各自口径写。**

## E. `resample.h`（30 行）：为"孤立对拍"而单独拆模块

x2 档只差这一步，而它是"看着像、实则全错"的高危点（定点系数、边界裁剪、两趟顺序、取整口径
差一点就整片像素不同）⇒ 单独成模块，`xrkit_cli --resample-dump` 直接吃原始 8 位图与 Pillow 逐字节比。

逐句照抄 `Resample.c` 的 8bpc 单通道路径：`PRECISION_BITS = 32−8−2 = 22`；
正数 `(int)(0.5 + v*2^22)`、负数 `(int)(−0.5 + v*2^22)`；累加从 `ss = 1<<21` 起；
`clip8(ss >> 22)`；两趟**先横后竖**；`box` 恒为全图。

⇒ **"高危的一步单独拆出来，给一条独立对拍通道"** —— 这是判据可维护性的关键手法。
  我们的 P5 也可以这样：把"页包装"单独拆成一个可独立调用的函数 + 独立判据。

## F. `system_dirs.h`（21 行）：第三例"两份实现"

这份逻辑原本在 `fontpack_page.cpp` 的匿名命名空间里，而**插件也要用同一份**
（`api.host.system_font_dirs()`）⇒ 搬到引擎。
注释原话："本仓已经因为**'旁边再写一份差不多的'**被门禁拦下过三次（分栏 / 列策略 / 引擎门面住哪层）。"

⇒ **"旁边再写一份"是本仓的头号反模式**，已有 3 次门禁记录 + 我这次数到的 4 例。

## G. 汇总：font 模块给我们的可执行结论

1. **跨语言对拍先查整数除法/取整**（B 节）—— 负数会差 1。
2. **判据样本本身是判据的一部分**（C 节）—— 样本太"健全"就测不出问题。
3. **拒绝与告警要分级**（B 节守卫）—— 不是所有红都该判死。
4. **高危步骤单独拆出并给独立对拍通道**（E 节）。
