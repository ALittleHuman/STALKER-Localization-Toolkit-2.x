### 2026-10-24 batch-2（D2 + E3）✅

- **三格式目录语义**（写进 `DbEntry::malformed`，解析阶段就判）：
  · `xdb/2947`：目录 ⇔ `offset==0 && size_real==0 && size_comp==0`；**文件条目 `offset==0` ⇒ 畸形**；
  · `null 系(2945/2215)`：目录 ⇔ `fields[dir_i]==0`（=offset）**且 size 全零**；否则畸形；
  · `11xx`：目录 ⇔ `offset==0` **且 size==0**；`offset==0 但 size>0` ⇒ 畸形（E3）。
- **自洽判定不再跳过目录**：`entries_fit_size` 先查 `malformed`，再对目录项要求 `offset/size` 全零。
- **显式格式那条路也拦**：`unpack_db` 遇到 `malformed` 直接报"条目表畸形"（修前只有自洽判定在拦，
  用户在下拉里选格式就能绕过）。
- 新增门禁步 `db-dir-consistency`（第 121 步）+ `tests/check_db_dir_consistency.py`：
  手工按格式逐字节拼镜像 —— 正向（xdb/11xx 正常 dump）＋ 反向（11xx 目录带 size、2215 目录标志 0 但
  size≠0、xdb 文件 offset==0，三种都必须被拒、理由点名"畸形/自相矛盾"）。
- 结果：`--fast` **PASS**、`--release` **PASS**（121 步、零未覆盖）。

### 新增（长期，batch-3 / 样本基线整理）：R39

`golden_text_decode.py` 的 `real/<序号>_<名字>` **id 仍是位置序** ⇒ 任何语料根不可达都会让后面的 id 前移；
现在的"名字+尺寸"兜底只是**止血**（同尺寸同名仍可能误配）。
⇒ 根治：baseline id 改成**相对路径**（或 `root_tag/rel`），baseline 只存 `id + size + sha256`；
根不可达 ⇒ 该 id 记未覆盖，**不让后面的 id 前移**。
