# `pages/fs_page.cpp` 中后段（第 901-1400 行）—— 六个"审计原文"级别的缺陷

这一段信息密度极高：每 50 行就有一条真正的缺陷与它的判据。

---

## 1. ★★ 审计 3-3：判重必须用 `core::path_equals`（第 917-941 行）

审计原文：「判重不用 `core::path_equals` ＋ 同层同名覆盖 ⇒ **源消失/计数翻倍**」。

修前 `QString::compare(..., Qt::CaseInsensitive)` ⇒ `E:\a\x.db` 与 `E:/a/x.db`（正/反斜杠）
以及含 `.`/`..` 段的写法**认不出是同一份** ⇒ 重复入源 ⇒ `pkg_build_nodes` 以"同层同名＝同一节点"
把 `it->source_index` 覆盖成后一个 ⇒ **先来的源在左树里没有任何节点**（不能选、没有 ✕），
却仍在 `sources_` 里参与合并与计数（`loaded_entry_count` 翻倍、与 CLI `--dump entries=` 对不上）。

判据（审计给的）：用 `E:\a\x` 与 `E:/a/x` 各加一次 ⇒ **只 1 个源、左树有节点**。

## 2. ★★ 审计 3-1：`rebuild_tree()` 丢整棵树 ⇒ 勾选被静默清空（第 1035-1086 行）

修前直接 `tree_ = MergeTree{}`，而勾选态**只活在树里**（`Source`/`EntryInfo` 都没有这个字段）
⇒ "加载选中/取消加载/移除/清空/加包"任何一次源集合变化都**把用户勾过的全部静默清空**；
`merge()` 里那句"6.1 勾选态跟随原节点"只在**增量**合并时成立，而本函数每次从空树重放 ⇒
**永远走不到那条保护**。

修法：**重建之前按路径快照、重放之后按路径回灌**（路径＝"原节点"的身份），
而且**必须在全部源重放完之后**回灌（合并期间胜者会换）。
判据：**勾 3 项 → 加一个包 ⇒ `checked_file_count()` 必须仍为 3**。

## 3. ★★ 审计 3-2：搜索"无命中"退化成"不过滤"（第 1363-1397 行）

审计原文：「把'没查询'与'查询无命中'编码成**同一个空集**」。
修前 `filter_keep_.isEmpty() || filter_keep_.contains(...)`：查询没命中时集合也是空
⇒ 与"没查询"同形 ⇒ **显示整棵树 + 计数全量**。

修法：`filter_active_` 说"这一轮到底有没有在过滤"；空集合在过滤态下就是 **0 行**。
判据：搜一个不存在的名字 ⇒ **0 行且计数为 0**。

★ 这条与我们一直在说的"**二态编码丢三态**"是同一族（`StatFailed` / `truncated` / `NotProbed`）。

## 4. ★ 计数与"树上显示几行"必须同一条判据（第 1118-1130 行）
修前 `refresh_counts` 用 `!filter_keep_.isEmpty() && ...` ⇒ 搜不存在的名字时计数**全量**
（"39374 文件"而树上一行都没有）。现在计数也走 `entry_visible(*node)`。

## 5. ★★ `check_all()` 不许刷状态（第 1005-1027 行，2026-10-05 #4 回归锁）

修前是 `refresh_rows()`（＝ `clear()` + 整棵重建）⇒ 展开态、item 指针、滚动位置**全被抹掉**
（自检实测：指针 0/0、展开 0/0、滚动 2→0）。

修法：走**同一条"就地刷状态"**的路 —— `rebuild_dir_states()` 重算模型 + `sync_entry_states()`
只改 `setCheckState`（不碰控件树、不碰展开态）。

★ 并且注释明确否掉了一个诱人的补丁：
> 为什么不是"重建后恢复展开态"：那等于把重建留在热路径上，大包（3.9 万条）每点一次就重建一次，
> 而且 item 指针必然变 ⇒ 判据照样红。

## 6. ★ 三态要沿**整条祖先链**累加（第 1155-1175 行）

用户 2026-09-30 报：「三层的结构，最里面的文件之一被选中，第二层的文件夹正常显示部分勾选，
但**最外面的还是显示未选中**」。
根因：只把文件计入**直接父目录**（`meshes/actors/actor_models/x.ogf` 只记到 `…/actor_models`）
⇒ `actors/`、`meshes/` 恒为 0/0 ⇒ 显示未选中。
修法：**沿祖先链逐级累加**。

## 7. ★ 行尾 ✕ / 三态 / 搜索的三处"同一份实现"
- `click_on_indicator(...)`：两棵树共用（第 1321-1322、1338 行）；
- `package_tree` 与 `entry_tree` 的单击语义**唯一差别**是"包树多一个是否加载"
  （用户 2026-10-02 原话，第 1333-1336 行）；
- 过滤：`name_matches` **按"这一项自己的名字"**匹配（修前拿整条路径 contains ⇒ `ai` 会命中
  `crouch_down_aim.anm`，而目录名永不参与匹配 ⇒ "看起来和输入无关"）。

## 8. `note_package_read()`：四态真值表的落地（第 968-998 行）
按 `db.h` 的四态：
| used_seek | reason | 行为 |
|---|---|---|
| true | 空 | **两个字都不打**（最常见，打了就是噪音） |
| true | 非空 | 打「未整包读（seek 解析）：…」 |
| false | 非空 | 打「整包读 N 字节：为什么」 |
| false | 空 | **仍然打**，并骂一句"没有给出理由"（那是缺陷，不许静默） |

## 9. 两个"我第一版写反了"（第 1198、1227-1231 行）
- `entry_built_file_count`：`UserRole+1` 存的是 `is_dir` ⇒ 只有 `false` 才是文件
  （"我第一版写反了，把目录当文件数"）；
- 程序化 `setExpanded()` **不发 `itemExpanded`** ⇒ `expand_entry` 里**显式**补一次懒建
  （`populate_entry_children` 幂等，两条路都走也不会重复建）。

## 10. 新增检查项

| 检查 | 为什么 |
|---|---|
| 判重是否用 `path_equals` | 否则源消失/计数翻倍 |
| 重建前是否快照勾选态 | 否则用户勾选被静默清空 |
| 过滤态是否有独立布尔 | 否则"无命中"退化成"不过滤" |
| 计数与可见行是否同一判据 | 否则"39374 文件"而树上是空的 |
| 全选按钮是否走"就地刷状态" | 否则展开态/指针/滚动全丢 |
| 三态是否沿祖先链累加 | 否则最外层恒未选中 |
| 搜索是否按"自己的名字"匹配 | 否则看起来与输入无关 |
