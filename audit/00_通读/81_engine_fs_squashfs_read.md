# 通读台账 04：`src/engine/fs/squashfs.cpp`（**860 行**，读侧 parser）

> 2026-10-24。只记录：问题 / 调用关系 / 风险 / 证据。**不重构**。BETA.2 保持可比。
> 五个检查点按用户给的组织；结尾与台账 03（`squashfs_write.cpp`）、台账 02（`db.cpp`）对照。

## 一、职责

SquashFS **读侧**：超块解析（LE/BE 双魔数）、元数据块缓存与跨块读取、inode 解析（DIR/DIR_X/REG/LREG/SLINK）、
目录遍历（环检测 + 三条上限）、按条目提取（数据块 / 稀疏 / fragment）、以及一个**线程局部读会话**
（`ReadSessionScope`，让 `--unpack-tree` 只列一次目录树）。

## 二、检查点 1：名字长度 / 空名 / NUL / 非 UTF-8 / 路径遍历 / 超长路径

| 项 | 实现 | 结论 |
|---|---|---|
| 名字长度字段 | `nsz = rd16(...) + 1` ⇒ **1..65536** 字节，再 `i + nsz > dir.size()` 越界即拒 | ✔ 读侧能表示到 65536 |
| 空名 | `+1` ⇒ 长度 ≥1，**不可能为空** | ✔ |
| **超长路径** | `kMaxPathLen = 4096`，但检查**只在"目录条目"那一支**（`:526-531`） | **R9（中）**：文件条目的路径 = 目录前缀(≤4096) + 文件名字节(≤65536) ⇒ **最大约 69 KB 无任何检查** |
| **NUL / 控制字符** | 名字是**原样字节**，不校验 | **R10（中）**：名字里的 `\0` 会让下游路径 API **截断**（写出到意外路径）；控制字符也不拒 |
| 非 UTF-8 | 原样字节（不转码） | 信息：界面可能乱码，但非安全问题 |
| **路径遍历** | 本文件**不判** `..` / 绝对路径 / `C:` | **R11（低-中）**：`extract_tree.cpp` 有专门拒因（含 Windows 尾点/空格变体，见其注释），但 **`list_entries()` 对外仍交出 `..` 路径** ⇒ 非 extract 的消费者（插件/GUI 列表）得自己防 |

## 三、检查点 2：表边界

| 表 | 校验 | 结论 |
|---|---|---|
| 超块 | 96 字节、LE/BE 魔数、`block_size` 4096..1 MiB 且 2 的幂、`block_log` 与之一致（≥32 拒）、`s_major == 4` | ✔（P17-2/P17-100 的成果） |
| **`inodes` / `bytes_used` / `no_ids` / `flags` / `id_table_start`** | **只解析、从不校验/使用** | **R16（信息）**：`inodes` 与实际 inode 数无对账；`bytes_used` 与文件大小无对账 |
| **export 表** | **超块里第 8 个 u64（@88）根本没解析** | R16（信息）：写侧写 `kNoTable`，读侧等于没有 |
| inode 表 | 按 `ref>>16` / `ref&0xFFFF` 经 `meta_read` 读前缀（DIR 32 / DIR_X 36 / REG 32 / LREG 56 / SLINK 24） | ✔ |
| 目录表 | 组头 12 字节 + `count+1` 条；每条 `i+8`、`i+nsz` 双重越界检查 | ✔ 但 `count` 是 u32，**靠"读到越界就报错"收敛**，不是先验上限 |
| **fragment 表** | 只判 `sb_.fragments == 0`；**`index` 与 `sb_.fragments` 不比对** | **R12（中）**：越界索引会读到"文件内合法偏移但错块"，靠 `read_at` 兜底 |
| `block_sizes` 数组 | `nblocks*4` 先按 64 位算，>64 MiB 直接拒（P17-12 自证） | ✔ |
| 所有读盘 | `FileReader::read_at` 统一 `off > size_ \|\| n > size_ - off` ⇒ 拒 | ✔（这是最硬的一层） |
| 目录遍历 | 环检测（`visited_dirs`）+ 深度 256 + 条目 4 Mi + 路径 4096（**仅目录**） | ✔（`dir_loop.sqfs` 判据） |

## 四、检查点 3：解压

| 项 | 实现 | 结论 |
|---|---|---|
| 每块上限 | 数据块 `want = min(bs, 剩余)`；fragment 容量 = `bs`（已被超块校验到 ≤1 MiB） | ✔ |
| 单文件上限 | `ino.size > 512 MiB` ⇒ **拒绝分配**（H-7） | ✔ |
| 目录表上限 | `meta_read(len)` 先判 512 MiB 再 `reserve` | ✔ |
| 元数据块声明 | 未压缩块 `comp_size > 8192` ⇒ 拒（**先判声明再读**） | ✔ |
| 跨块跳 | `hops > 4096` ⇒ 拒（"offset 是跨块逻辑偏移"的真机教训） | ✔ |
| gzip 截断 | 由 `read_at` 的整段读 + `decompress_block` 的 zlib 错误兜 | ✔（本文件外，未见反例） |
| **失败半状态** | `read_file_data` 直接写调用方的 `out`（= `res.data`）⇒ 失败时**留着半截** | **R13（低）**：靠 `res.ok=false` 兜；调用方若只看 `data` 不看 `ok` 就会拿到半截 |
| fragment 缓存 | 读侧只有元数据块缓存（`kCacheBlocks=256`，满了整体 `clear`） | ✔ 无界增长 |

## 五、检查点 4：目录

| 项 | 实现 | 结论 |
|---|---|---|
| **重名** | `list` 把**重复条目全输出**；`entry_paths_` 用 `emplace` ⇒ **只留第一个** | **R14（中）**：提取同名后者被**静默忽略**；与写侧"拒绝重名"**口径相反** |
| 空目录 | `ino.size == 0` ⇒ 目录表 0 字节、一条都不读 | ✔ |
| 嵌套深度 | 256 上限 | ✔ |
| **is_dir 判法** | 用**目录项的 `e_type`**（1/8 = 目录），写侧也写 `e_type` | ✔ **读写一致**（对比 `db.cpp` 的 D2：那里是从尺寸/标志反推） |
| **SLINK** | `kTypeSlink/kTypeSlinkX` 只在 `read_inode` 里读了 size；`Entry` **没有类型字段**，`read_entry_file` **无类型分派** | **R15（中）**：软链接条目会被当普通文件去读数据块 ⇒ 报"长度不符"或读出垃圾；`list` 也无法告诉调用方"这是链接" |

## 六、检查点 5：总量 / 峰值

- **读侧**：单文件 ≤512 MiB、单块 ≤1 MiB、`block_sizes` 数组 ≤64 MiB、目录表单次 ≤512 MiB、
  条目 ≤4 Mi、深度 ≤256 —— **但没有任何"累计/总量"上限**（一个包可以有很多 512 MiB 条目）。
- **写侧**（台账 03）：`pack_squashfs` **完全没有总量闸门**。
- ⇒ **R8 确认：两侧都没有总量上限**，按用户裁定"写侧和读侧一起补"。
- 峰值：读单文件 ≈ `out`(512 MiB) + `plain` + `rawbuf`（各 ≤1 MiB）≈ **1.0×**；
  写侧 ≈ 3× 总量（`items` → `data` → `db`）—— 两侧峰值模型不同，预算表要分开写。

## 七、其余发现

| # | 位置 | 现象 | 严重度 |

| R16 | `parse_superblock` | `inodes`/`bytes_used`/`no_ids`/`flags`/`id_table_start` 只解析不校验；**export 表 @88 未解析** | 信息 |
