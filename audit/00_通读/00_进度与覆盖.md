## 已确认的硬事实（可直接引用，均带行号）

- `version.h:16/23`：`kPrerelease = "ALPHA.252"`、`kBuildCount = 252` —— 当前工作副本就是这个值。
- `version.h:21-22`：`version.json` 的 tree 里**故意缺 17 与 107 号**，是历史断号，不许补。
- `check.h:39`：自检收尾行是 **ASCII**：`SELFTEST pass=<n> fail=<m>`；退出码 0=全绿、1=有失败。
  （⇒ 这与 `--smoke` 的 `SHELL-SMOKE ok checks=935 failed=0` 是两套不同的收尾行，别混。）
- `log.h:23-28`：`log_block()` 是"C-13 镜像"，**只写文件不写 stderr**，按 LogBox 的 80ms 批量走
  （⇒ 判据里"日志长度 849/893"这类读数，增量就可能来自这里，而不是 `log()`）。
- `log.h:30-40`：`prune_log_files(dir, keep, protect_path)` 保留 50 份，`protect_path` 永不删。
- `path.h:19-22`：`path_equals` 只做词法规范化、**Windows 大小写不敏感**（Python `normcase` 同语义）。
- `atomic_write.h:39-45`：`WriteVerify{Streamed, Readback}`；默认 `Streamed`。
- `atomic_write.h:21-29`：**诚实口径**——默认档只保证"防进程内短写 + 写后检测落点大小"，
  **不承诺断电/崩溃**（没有 `FlushFileBuffers`）。这条是 T-03 审计后特意改的措辞，别改回去。
- `atomic_write.h:90-96`：Windows 保留设备名（`CON`/`NUL`/`COM1`…）直接拒绝写。
- `theme.h:71-78`：用户配置是 **`xrkit_user.ltx`**（不是游戏的 `user.ltx`）；旧名只在"有条件迁移"时读。
- `theme.h:8-9`：主题令牌表由 `tools/gen_theme_tables.py` 从 1.x **按 AST 生成**到
  `src/core/theme_tables.inc`，改主题只能改 1.x 那份真值来源（门禁 `--check` 锁住）。
- `build_version.h:5-9`：**唯一事实来源 = `version.json`**；"下一个序号 = 该版本+标记下 max+1"。
- `build_version.h:58-76`：`version.h` 是 `version.json` 的**派生**；写回时机＝写 `version.json` 之后、
  `build.ps1` 之前；失败必须回滚（序号不被吃掉）；判据**只对包内 exe** 断言，不对 build 目录 exe 断言。
