# 新思路（2026-10-23，通读 40 轮之后）

> 40 轮通读的结论是"三个红都在判据与被判对象的接口上"。
> 但**接下来该做什么**，我原先的方案（A/B/C）还不是最优 —— 下面是重排后的想法。
> 标 **〔假设〕** 的，都配了**判决性实验**（能证伪）。

---

## 思路 1（最重要）：把"间歇红"改成"确定性覆盖"

**现状**：20 次是**近乎相同**的 20 次（同一包、同一页序、同一 TEMP）。
它采的是**同一个分布**，所以只能"撞运气"撞到竞态 —— 这解释了为什么**同一份代码 13~25/30 漂**。

**新做法**：不再重复跑同一状态，而是**枚举前置状态**，每个状态跑一次：

| 维度 | 取值 |
|---|---|
| 起始页 | `0`（fs）/ `5`（fontpack）/ 插件页 index |
| 是否先切页再断言 | 是 / 否 |
| `XRKIT_PAGE_TRACE` | 0 / 1 |
| 私有 TEMP | 仓库内（默认）/ `%TEMP%`（`XRKIT_PKTMP_DIR=system`） |
| 是否冷启（首次 import） | 是 / 否（同一进程第二次建 Hub） |

⇒ 5×2×2×2×2 = **32 个格**，跑一轮 ≈ 现在的 1.5 倍时间。

**收益**：
1. 现在"偶发"的三个红，在**某个格里会变成确定性红** ⇒ 有了可复现的失败 ⇒ 能修、能验；
2. 修完之后，**同一套格子全绿**才是真的稳 —— 比"20 次都绿"强得多（20 次绿可能只是没扫到那个状态）；
3. 顺带回答了"到底是不是杀软"：`TEMP=system` 那一半格子的红率对比**就是**答案。

**代价**：一轮变长（估 1.5×）。**建议**：BETA 闸门仍按 20 次，但**跑的是"32 格"的抽样**，
而不是 20 次同一格。

## 思路 2：用**内置页当对照组**，把"环境红"与"产品红"分开

**现状**：⑭ 在 `fontpack`（内置页）上扫 `field_row`；P5 在插件页上查视口。
两者失败时**无法区分**：
- 是"这个页没建好"（产品）；
- 还是"页没切到/没显示/被杀软拖慢"（环境或判据）。

**新做法**：**同一条断言先在对照组上跑一次**：
```cpp
// 对照组：内置 fs 页（永远存在、永远有 field_row、永远有视口）
const bool control_ok = scan_field_rows(style_hub, /*page=*/0) > 0 && viewport_of(page0) != nullptr;
check(control_ok, "对照组（内置 fs 页）先成立 —— 否则本轮判据没有意义");
if (!control_ok) return;          // 记 NOTE，不判产品红
// 实验组：插件页 / fontpack 页
```
⇒ **对照组红 ⇒ 环境/判据问题（NOTE）；对照组绿而实验组红 ⇒ 真产品问题（红）**。

**为什么这条便宜**：不改产品代码，只改判据的**前置**；而且对照组本身就是"判据自证样本"
（B1-5 那条纪律的自然延伸）。

## 思路 3：**5 分钟判决性实验** —— 先证伪我最不确定的那条

我在 `68_项目真相` 里给了 P5 三条候选成因，其中"`unwrap` 地址复用"是**推断**。
它要么是主因，要么完全是噪音。**判决方法**（不改产品行为）：

```cpp
// widget_facade_qt.cpp 的 place() 开头，加一行（只在 XRKIT_PAGE_TRACE=1 时生效）
if (parent == nullptr) trace_page_event("place_null_parent", "child=… kind=…");
// 并且 sync_pages 里：trace_page_event("container_created", "addr=0x… stale=%d",
//     handle_registry().count(container));
```
跑 30 次读 trace：
- `place_null_parent` **0 次** ⇒ 我的假设**错**，立刻停止追它（省下一轮无效工作）；
- **≥1 次**且伴随 `stale=1` ⇒ 假设成立，修法＝**1 行**（见思路 5）。

⇒ **这是"该先做的事"**：它把"最不确定的假设"变成"已证实/已证伪"，成本 5 分钟。

## 思路 4：分层 fail-fast —— 一个前提失败，别产生 6 条红

**现状**：插件页没建出来 ⇒ `P5 视口` / `⑭ 底板` / `P16-3c 菜单` / `P4 各条` **同时红**。
20 次计数里，**一次环境抖动会吃掉 5~6 条红** ⇒ 数字失真（8/20 里可能只有 2 次是真的）。

**新做法**：给每个"页块"一个**前置判定**：
```cpp
enum class Prereq { Ok, PageMissing, PageNotShown, BuildFailed };
if (prereq != Prereq::Ok) { NOTE("该块的 N 条断言未执行：precondition=" + name); return; }
```
⇒ 一次抖动只记 **1 条 NOTE**，而不是 6 条红。
⇒ 20 次的数字才反映"产品失败次数"，而不是"抖动次数 × 6"。

## 思路 5：P5 的修法换一行写法（比 `erase` 更干净）

原想法：`sync_pages` 里 `handle_registry().erase(container)`。
**更好的写法**：**把容器登记成句柄**——
```cpp
const plug::UiHandle root_handle = handle_of(container);   // 让地址"在册且活着"
UiPanelScope scope(root_handle, page_key, &registry_);
```
理由：容器的地址从此**不会被当成死项**（它的 `QPointer` 活着）；页析构后它自然变死项，
语义与其它句柄一致。**副作用分析**：插件拿到页根句柄后，页销毁时 `alive()` 变 false —— **这正是对的**。

## 思路 6：把"诊断口径"也纳入 BETA 闸门

现在闸门判的是 `failed==0`。但三个红里有两个**报错词是错的**（P5 说"没被套上视口"、⑭ 说"有涂底"）。
⇒ **闸门应该同时判"红的名字对不对"**：
- `SHELL-SMOKE fail` 的行里，若含"底板有涂"但 trace 里 `field_row` 计数为 0 ⇒ **判据自身错**（不是产品红）；
- 这类"判据自指的错"应单独成一条 `GATE-SELF fail`，**不进 20 次计数**。

⇒ 收益：20 次的分子只统计"真产品红"。

## 如果只给我 2 小时（推荐顺序）

| 分钟 | 做什么 | 产出 |
|---|---|---|
| 0–20 | **思路 3**：`place(nullptr)` + `container_created(stale=)` 两条 trace，跑 30 次 | 证实/证伪地址复用假设 |
| 20–50 | **思路 4**：给 P5/⑭/P16-3c 三个块加 `Prereq` 前置 | 一次抖动只记 1 条 NOTE |
| 50–80 | **思路 2**：⑭ 与 P5 各加一条"对照组（内置页）" | 红/环境红可归因 |

⇒ 2 小时后无论假设真假，我们都能回答一个**确定的问题**："这次红是产品、环境、还是判据？"
—— 而这正是 40 轮通读换来的最大结论。
