## 1. 架构真相

### 1.1 三层，但边界是"约定"不是"机制"
```
core      (9 文件 / 1330 行)   日志、路径、原子写、主题、版本
engine    (33+8 文件 / 19334 行)  fs / text / xml / font / video / process / plugin
shell     (57 文件 / 23121 行)  Hub + 六页 + 门面 + 自检(11989) + 主题
```
★ 边界靠"**引擎不许碰 Qt**"这条纪律维持 —— 它**有判据**（`check_engine_contract.py`），
但**没有机制**：`engine/plugin/widget_facade.h` 只是个函数指针表，谁都能塞。

### 1.2 两条输入通道，三条判据通道
- **GUI**：`xrkit_app.exe` → `Hub` → `PageRegistry` → 六个内置页（或插件页 `replaces` 顶替）；
- **CLI**：`xrkit_cli.exe` → 同一引擎（"**GUI 的功能 CLI 肯定要全部拥有**" —— 这句原话在
  `fs_page.cpp:3387`、`smoke.cpp:8367`、`check_package_fixture_pages.py` 里各出现一次）；
- **判据**：`--smoke`（进程内 900+ 条 check）、`tests/*.py`（122 个脚本）、`package.ps1` 的包内自检。

★★ 这三条通道**共用同一份实现**是本项目的核心承诺，也是最脆弱的地方：
`xrkit_app.exe --smoke` 既是产品又是判据（`main.cpp:70-127`）。

### 1.3 页的一生（这是所有"空页"问题的舞台）
```

  ↓ 校验：身份边界(P17-88) / id 非空 / title 非空 / builder 非空 / 不重复 / 不替换自己 / 同目标只一个替换者

  ↓ container = new QWidget;  UiPanelScope(container, page_key, &registry)
```

## 2. 三个开放红的根因（每条都有行号）

### 2.1 P5「插件页的宿主外壳不对 / 没被套上宿主视口」

**判据本体**（`smoke.cpp:7264-7273`）：
```cpp
auto* page_base = dynamic_cast<PageBase*>(page_widget);
if (page_base) check(viewport && fit==Content && minsize_ok(), "宿主外壳不对");
else           check(dynamic_cast<ScrollViewport*>(page_widget), "没被套上宿主视口");
```
⇒ 这条红 **⇔ `page_widget` 既不是 `PageBase` 也不是 `ScrollViewport`** ⇔ **它是占位页**。

**占位页的两条成因**（`hub.cpp:632-677`）：
1. **builder 抛了**（`builder_threw=true`）；
2. **`anything_built == false`**（没抛，但一件控件都没挂上）。

**而 `smoke.cpp:6207-6220` 记着一条确切的、天然偶发的成因**：
> 修前**每个 provider 行都 `open(...,'a')` 一次**（200 行 = 200 次 open/close）。
> 只要一次被杀软/文件锁挡一下，`mark` 抛异常 ⇒ **provider 抛** ⇒ **builder 半路中断**
> ⇒ Hub 的 S-02 护栏把整页换成**占位页**（现场正好是"标签是占位页文案、列表为空"）。

**再加一条结构性的**（我在 `21_hub.md` 推出的、**〔推断〕**但链条完整）：
`widget_facade_qt.cpp:253-260` 的 `unwrap()` 会查"地址 → QPointer"表，
**命中死项就返回 nullptr**；而 `hub.cpp:526` 每次 `new QWidget` 造页容器（从不登记）
⇒ 若该地址曾被某个已销毁的门面控件占用（**地址复用**），`resolve_parent` 就会拿到 nullptr
⇒ 控件无父 ⇒ `place(nullptr, …)` **静默 return**（`widget_facade_qt.cpp:327`，无 trace）
⇒ `anything_built == false` ⇒ 占位页。**这条能解释"同一份代码 13~25/30 漂移"。**

**外部干扰**（`check_package_fixture_pages.py:237-242`，判据作者自己的定性）：
> ③ 的偶发红全是**插件页没建出来**（P17-1 取消探针页 / **P5 插件页视口为 0**），
> 而插件是**刚写进 %TEMP% 的 .py** ⇒ 怀疑**杀软扫刚写的 .py 导致 import 偶发失败**。

⇒ **三条候选成因并存**：杀软扫 .py → import 失败 → 页未注册；builder 被诊断 I/O 搅死 → 占位页；
地址复用 → 控件无父 → 占位页。**第三条是本轮新发现，且只有读代码才能看出来。**

### 2.2 ⑭「标签背后不许有深灰底板（扫到 0 个可见字段行）」

**判据本体**（`smoke.cpp:9843-9847`）：
```cpp
check(plate_rows_scanned > 0 && plate_hits == 0, "⑭ …（扫到 %1 个可见字段行，%2 处涂底）");
```
★ `plate_rows_scanned > 0` 是 B1-5（审计 0-3）**新加的自证样本**要求：
"**没有自证样本 ⇒ 候选集空就恒绿**"。
⇒ **我们看到的这条红不是"涂底"，是"候选集为空"**。

**候选集为空的四个条件**（`smoke.cpp:9809-9819`，缺一即 0）：
1. `objectName() == "field_row"` —— 只有**名字为空**时 `DropZones::attach_row` 才会命名（`drop_zone.cpp:17-19`）；
2. `isVisible()` —— 只有**当前页**上的控件算可见；
3. 同时含 `QLineEdit` 与 `QLabel`；
4. 尺寸 ≥ 8×8（布局跑过）。

★ 而夹具是 `style_hub.set_current_page(5)`（汉化包生成页，`smoke.cpp:9790`）——
若那一步没真切到（或该页不是 index 5），**所有行都不可见** ⇒ 0 个 ✓ 这就是那条红。
**这条红与"底板"无关，与"页没切对/没显示"有关** —— 与 P5 同源。

### 2.3 P16-3c「等两项菜单 2000ms 未就绪」

**判据本体**（`smoke.cpp:6579-6608`）：
```cpp
const QString page = QString::fromStdString(xrkit::plugin::current_page_id());   // ★ 当前页
const QString key  = page + "|button_on_menu";
const int n = menu_ready_actions.contains(key) ? … : menu_ready_actions.value("button_on_menu", -1);
return n == 2;      // 超时 2000ms ⇒ 记 note actions=…，随后 check 也可能红
```
**脆弱点**：`hub.cpp:829-831` 的 `render_plugin_slots()` **每注册一个 tool 就 `set_current_page(0)`**
⇒ 若宿主的 `notify_menu_ready` 在页切走之后才被调用，键就变成 `fs|button_on_menu` ⇒ 查不到 ⇒ 超时。
⇒ **判据侧仍读"当前页"，而 `hub.cpp` 那边已改成"构建点捕获 page"** —— 口径不齐。

**另一条独立成因**（`smoke.cpp:6289-6296` 的自记）：
> 夹具的 Python 源码是 C++ 字符串字面量拼接 ⇒ 在字面量之间插一行 C++ `//` 注释会**打断拼接链**
> ⇒ 生成的 `l2_demo.py` 语法错、插件加载失败，而 **C++ 照样编得过**。
⇒ 若夹具被截断，`menu_ok` 根本不会写出 ⇒ 判据空转。

## 4. 判据体系的真相

### 4.1 规模
`--smoke` 一个函数 **11989 行**、`check()` 计数在 900 上下（`SHELL-SMOKE ok checks=N`）；
`tests/` **122 个脚本**；`run_ci.py` **5640 行**（含 `--fast`/`--release` 两档与 30 余步）。

### 4.2 它做得非常好的三件事（值得保留）
1. **每块写"判红办法"**："把 X 删掉 ⇒ 立刻红"（几乎每段都有）；
2. **正反成对**：搜 `c.txt` 仍要命中（`smoke.cpp:11639`）、撤销 JSON 上限后必须能压（`:8649`）、
   worker 里"读不到"＋主线程"读得到"（`:9567`）；
3. **红之外还有第三态**：`rc=2 / NOTE / 未覆盖`（磁盘不足、360 拦、布局不适用、包不完整、无 dist）——
   **不产假红**这条纪律执行得比多数项目好。

### 4.3 它做不到的三件事（本轮三个红的判据侧成因）
1. **不区分"没抛但没挂上"与"抛了"** —— P5 那条把两者都报成"没被套上宿主视口"；
2. **把"候选集为空"写成红** —— ⑭ 因此把"页没显示"读成"底板有涂"；
3. **判据自身读"当前页"** —— P16-3c / P13-2a-2 的键会随页切换而失配。

## 6. 一句话真相

> 这个项目的**产品代码是健康的**（六页 + 引擎 + 门面都能读出清晰的设计意图与逐条修法记录）；
> 它真正的病在**"判据与被判对象同体"**：`--smoke` 既是产品入口又是判据主体，
> 于是任何"时序/生命周期/候选集"的瑕疵都会同时污染产品表现与判据结论，
> 表现为**间歇红**（同一份代码 13~25/30），而这种红**无法靠重跑收敛**，
> 只能靠"把判据的输入与观测点显式化"来收敛。
