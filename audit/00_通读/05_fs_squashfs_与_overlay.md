# `engine/fs/squashfs.h`(150) ＋ `engine/fs/overlay.h`(270)

---

## A. `squashfs.h`（150 行）

### 1. 为什么"零外部 exe"（第 3-7 行，1.x 血账）
- `sqfs2tar` **被 360 按文件哈希拦截**（复制改名也没用），且会把整包收进内存（54~99 s）；
- 改成自读元数据后是 **0.01~0.02 s**；
- 写侧同样是血账：1.x 封包调外部 `tar2sqfs.exe`，也被 360 按哈希拦过。

⇒ **这条直接解释了我们打包时反复遇到的 `vcruntime140.dll` 被 360 拦**：这台机器上
  "外部 exe/动态库被按哈希拦截"是**长期事实**，不是偶发。判据必须能区分"我们的 bug"与
  "被拦"，否则会一直产假红。

### 2. `ReadSessionScope`（第 66-83 行）：一处 74% 的性能血账
`--unpack-tree` 原先每条目都 `read_file()`，而它每条目重开镜像 + **重新 list 整棵目录树**
⇒ 真机 14861 条目把同一份元数据遍历了 14861 遍（探针实测占解包总耗时 **74%**：100.3 s / 135.3 s）。
修法：整批循环外面建一个作用域对象，作用域内对**同一镜像**复用已打开的镜像与条目索引；
离开作用域立刻失效 ⇒ 作用域外行为与今天**一字不差**。

★ 注意它的写法：**"作用域内加速，作用域外行为不变"** —— 这是"加优化不改语义"的样板，
比"全局缓存"安全得多。我们加 trace/钩子也该是这个形状（作用域式，默认零影响）。

### 3. 读取契约（第 91-95 行）
`read_file` 返回的 `data.size()` **必须等于** inode 的 size —— 不等就是解析错了，
**直接报错而不是给半截数据**。

### 4. 写侧验收判据（第 99-106 行）：**产物逐字节一致**
同一份输入，我们的产物与 1.x `sqfs_pack`（tar2sqfs 1.3.2，默认 xz）**sha256 必须相等**。
参照实现的行为（inode 编号顺序、目录项排序与分组、xz 参数、表顺序、结尾补零、块去重、
fragment 打包）已逐项取证，见 `docs/2.0.0-SquashFS-writer规格.md`。

### 5. T-07（第 124-128 行）：压缩器可选，但**默认路径一个字节都不许变**
默认仍是 `Xz`，因为黄金判据 `tests/golden_sqfs_pack.py` 必须保持绿；
写侧目前支持 `Xz`（原有）、`Gzip`（P17-169 起）；其余在 `compress_block` 里**明确报错**。

⇒ "新增能力不许动默认路径"这条，我们改判据时也要守：**默认档的行为是对拍基线**。

## B. `overlay.h`（270 行）—— fs 页的**纯模型**

### 1. 模型为什么在引擎层（第 3-6 行）
合并胜负、加载序、勾选态、下拉取值、目录条目都是**可判定的行为**；页面只该把它画出来。
放无 Qt 层 ⇒ CLI 自检能直接断言，**不用起 Qt、也不用点界面**。

⇒ 这正是我们该走的方向：**把"页是否就绪/菜单是否装好"做成模型层可断言的函数**，
而不是在 GUI 线程里等 2000ms。

### 2. 六条被照抄的 1.x 语义（第 8-17 行）
- **6.1 合并 = 后者为准**；`source` 切换成"引擎实际会读到的那一份"；**勾选态跟随原节点**
  （用户勾过的不能因为重建树而丢）；两个都是目录才**递归**；类型不同（文件↔目录）不递归。
- **6.2 加载顺序** = 按 `basename().lower()` 升序，字典序靠后的包赢。
- **6.3 `selected` 与 `checked` 是两套独立状态**：DB 栏「全选」只改前者，包内「全选」只改后者。
- **6.12 目录条目必须如实带 `is_dir`**（1.x 封包路径写死 False ⇒ DIRTYPE 分支永不触发）。
- **6.13 格式下拉存内部键**（1.x 存显示名 ⇒ `ALL_FMTS.get(fmt)` 必然取不到）。

⇒ **6.13 与 P16-0（`host_run_process` vs `run_process`）是同族**：
  "内部键 vs 显示名"混用 ⇒ 静默失效。**我们判据里的 key 也必须用内部键。**

### 3. ★★ P17-120（第 73-87 行）：`LooseInfo.truncated` —— 又一次"信号必须结构化"

修前：P17-110 把"到上限了"**写进 `error`** ⇒ 两个消费点只能**猜**：
- CLI 用**理由前缀**（`条目表已截断`）区分 ⇒ **引擎改一个中文字就静默失效**；
- GUI 把任何非空 `error` 当**硬失败** ⇒ 超深/超多目录**整份拒载**。

处置：**截断 = `truncated` 标志（不是错误）**；`error` **只**表示"没读成"。

★ 作者原话：**"典型的字符串判语义耦合"**。这与我们 P5/P13 的处境**完全同构**：
  我们把"页没建好/菜单没装好"写进 note 字符串，判据再解析字符串 ⇒ 同一个坑。
  ⇒ 正解：给 `settle` / `menu_*` / `page_ready` 定义**具名布尔状态**，判据读布尔，不读文案。

### 4. B-1（第 112-119 行）：空目录进不了包 ⇒ **必须如实报数**
`PackFileItem` 只有文件类型 ⇒ 空目录在封包后完全消失，这是**信息损失** ⇒ 计数上报。
并注明"要不要把空目录打进包是**产品口径**，本批只做如实记账"。

### 5. ★ 勾选态快照/回灌（第 183-192 行）
页面「加一个包」走 `rebuild_tree()`（整棵树丢掉重放），而勾选态**只活在树里**
⇒ 修前"源集合一变，用户勾过的全没了"。口径：**按路径快照、按路径回灌**，
`apply_checked_paths` 返回真正置上的条数（判据可对账）。

⇒ **"重建后状态丢失"也是本仓的一族 bug**（P12c-2 的"回调绑定的 label 被重建替换"同型）。

### 6. `WalkReport`（第 252-268 行）：遍历台账
原来 `collect_tree` 遇到 `ec` 就 `break`/`continue`，**扫不到的东西一个字都不报**。
现在台账跟着**同一份**遍历实现一起出来（而不是让调用方再写一遍 —— 那就是第 5 份
`recursive_directory_iterator`）。字段：`dirs/files/max_depth/errors`。

## C. 对当前红点的三条直接推论

1. **P12c-2 的"回调没改到控件"很可能就是第 B.5 条的"重建后状态丢失"**：
   页面重建 ⇒ 回调绑的是旧 label 实例 ⇒ 写进去了但不在当前控件树上。
   下一轮查 `rebuild_tree()`/页重建路径是否也会重建 label。
2. **判据不该解析文案**（B.3）：我们现有的 `note` 里大量中文原因，是**诊断**可以，
   但**判定**必须读结构字段。
3. **"作用域内加速、作用域外不变"**（A.2）是我们加 trace 的正确形状：
   现在 `XRKIT_PAGE_TRACE` 是全局开关，若改成"作用域式"（只在某个判据块内开），
   扰动面会更小。
