## 二、四个方案（按通读后的修正重排）

### 方案 A（**推荐，第一步做**）：`PageBuildResult` —— 让"造没造出来"成为数据

**现状**：`builder(QWidget*) → QWidget*`；"有没有挂上控件"只能靠事后数 `findChildren`。
`hub.cpp:660-677` 已经数了（`placed->count()`、`anything_built`），**但没把这个结论交出去** ——
于是 `smoke.cpp:7264` 只能拿到一个 `QWidget*`，只能说"你没被套上视口"。

**改法**（`hub.cpp` 内，约 20 行）：
```cpp
struct PageBuildResult {
    enum class Kind { Built, Threw, Empty } kind;
    QString detail;        // Threw ⇒ what()；Empty ⇒ "没造出任何控件"
};
// sync_pages 里把三种结局记进 result，并通过 PageServices/回调交出去；
// smoke 侧：Kind::Threw ⇒ "builder 抛了：%s"；Kind::Empty ⇒ "builder 没造出控件"；Kind::Built 才判视口
```
**收益**：P5 那条红的**报错词从"没被套上宿主视口"变成真正的三选一** ⇒ 下次红就知道该查谁。
**判红办法**：把 `Threw` 那一支故意改成 `Empty` ⇒ 新判据立刻红。
**成本**：1 个结构体 + 3 处写入 + 1 处判据改写，**半天**。

### 方案 B（**推荐，第二步做**）：页身份与候选集显式化

**(B1) 页身份传参，不读全局**
`smoke.cpp:6582` / `:7841` 用 `current_page_id()` 拼键，而 `hub.cpp:829` 每注册一个 tool 就
`set_current_page(0)`。改法：`notify_menu_ready(id, actions, page)` **已经**在 hub 侧捕获了 page
⇒ 判据侧**只用裸键** + 断言"只有一个 page 命中"：
```cpp
// 收集期：key = menu_id（裸），值记 (page, actions) 列表
// 判据期：n = 命中该 menu_id 且 actions==2 的条目数；并要求命中页 == 被测页
```
**判红办法**：把 hub 侧的 page 改成空串 ⇒ 判据立刻红（而不是"偶发").

**(B2) 候选集为空 ⇒ **NOTE**，不是红**
`smoke.cpp:9843`（⑭）、`:9503`（字体夹具）、`:10507`（MSYH）现在都是"空 ⇒ 红"。
口径应该统一成：
```
候选集为空 && 未切页/未 show  ⇒  NOTE "未覆盖（页没显示）"
候选集为空 && 页确实显示了    ⇒  红（真的没有 field_row，说明行容器没建）
```
区分只需要一条：`hub.stack()->currentWidget() == style_hub.page_at(5)` 与 `page->isVisible()`。
**收益**：⑭ 那条红不再误导成"底板有涂"。
**判红办法**：人为删掉 fontpack 页的 `attach_row` ⇒ 页显示了但 0 个 field_row ⇒ 红（新分支）。

### 方案 C（**推荐，与 A/B 并行**）：生命周期三件套做成清单 + 静态锁

已发生的 5 个先例（全部只差一行）：
1. `QTimer::singleShot` **必须给 context**（`font_picker.cpp:264` 的 0xC0000005）；
2. **静态钩子必须 RAII 撤**（`smoke.cpp:7130` 的悬垂 + 崩）；
3. **进程级回调必须析构撤**（`convert_page.cpp:322`）；
4. **`QProcess` 放弃必须 先置空→disconnect→deleteLater**（`video_page.cpp:104`）；
5. **`BlockingQueuedConnection` 不许同线程自投递**（`convert_page.cpp:92`）。

**改法**：把 `tests/check_thread_contract.py`（566 行，已有）扩成"生命周期静态锁"：
扫 `singleShot(` 是否带 context、扫静态 `set_*_hook(` 是否有配对复位、扫 `deleteLater()` 前是否 `disconnect`。
**收益**：把"每修一次错一次"变成"写的时候就被拦"。
**成本**：一个 py 脚本 ≈200 行（复用既有 check 框架）。

### 方案 D（**不建议现在做**）：每页一进程

隔离性最好（一个页崩了不带走门禁），但成本：
- `Hub` / `PageServices` / 插件注册 / 主题 / 日志 全都要跨进程；
- `--smoke` 现在是"一个进程 900 条断言"，拆进程后**跨页断言全部作废**（例如"追加插件页不许重建已有页"）。

**判断标准（什么时候值得）**：
> 当"间歇红"中**仍有 ≥2 例**无法用 A/B/C 解释时，再上 D。
现在三个红都有 A/B/C 能解释的成因 ⇒ **先做 A/B/C，不碰 D**。

## 四、中期（1~2 周）：把 `smoke.cpp` 拆开

现在：**11989 行单函数**。它的问题不是长，而是：
- 任何一次改动都要重新编译 12000 行；
- 静态钩子/静态计数在块之间共享（`flush_registered`、`menu_ready_actions`、`page_ready_seen`）；
- **一个块崩了，后面 900 条全不跑**（`B1-9` 那条教训）。

**拆法**（不改任何判据内容）：

```
smoke.h                       // SmokeResult + 声明
smoke_common.cpp              // helpers: wait_until / wait_page_ready / qss_rule_body / user_ltx_restored / write_fixture_safely
smoke_shell.cpp               // 页框架 / 主题 / 滚动 / 分栏 / 日志 / 任务壳
smoke_fs.cpp                  // fs 页全部（含 #2/#3/#4/3-1..3-4）
smoke_pages.cpp               // 其余五页
smoke_plugins.cpp             // P2b/P3/P4/P5/P6/P7a/P7c/P17-1 取消探针
smoke_contract.cpp            // P17-* 契约批（引号/设备名/JSON 深度/上限）
```
★ 关键：**每个文件导出自己的 `SmokeResult run_smoke_xxx()`**，由 `run_smoke()` 串起来；
`check` 走同一个 `SmokeResult&`。这样"一块崩"只丢那一块。
★ 这一步**不做就不做**，做了必须保持 `SHELL-SMOKE ok checks=N` 的 N **只增不减**。

## 五、不建议做的四件事（避免下一次返工）

1. **不要用"重跑 3 次取最好"来让门禁变绿** —— 这正是本项目的头号禁忌；
2. **不要为了测试把 private 方法公开**（`smoke.cpp:10537` 已经示范了正确做法：点真按钮）；
3. **不要把"候选集为空"继续写成红** —— 会让"环境问题"永久伪装成"产品问题"；
4. **不要在没有 A/B 之前动 `place(nullptr,…)` 的静默 return** —— 先让它**可观测**
   （加 trace + WARN），再决定是"补父容器"还是"记 Empty"。
