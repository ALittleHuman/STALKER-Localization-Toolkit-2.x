## 2. ★★ 占位子项的坑（第 71-80 行）

```cpp
void drop_placeholder(QTreeWidgetItem* item) {
    if (item->childCount() == 1 && item->child(0)->data(0, Qt::UserRole).toString().isEmpty())
        item->removeChild(item->child(0));
}
```

用户报「**在筛选的时候，文件夹下会多出一个空的行**」—— 真因：**只要接着要建真子项的地方
没把这个占位项摘掉**，它就留在第一个位置当空行。
⇒ 凡是"马上要往里加真子项"的路径（筛选里的一次性建树、`build_all_descendants`）都必须先摘。

★ 这与 `facade_tree.cpp:108-111` 的"**不塞占位子项**"是**两种不同策略**：
门面树选择"不塞"，fs 树选择"塞了但在加真子项前必摘"。**两者都能对，但必须一致地执行**。

## 3. ★★ 包列表树的两条锚点规则（第 82-184 行）

用户的诉求（第 83-84 行原话）：
> 「这玩意，一把 `E:\...\IWP\database` 拖进去就这样。**左边的包列表的结构也应该是一个文件树**，
>  而且**拖入文件夹的一些逻辑也要修复一下，和单个包文件那种结构的逻辑统一**。」

规则：
- **锚点 = 所有源路径的公共祖先目录**（`pkg_common_ancestor`，逐段大小写不敏感比较）；
- 两条正好相反的判据（第 135-151 行）：
  - 所有源**都直接躺在 anchor 里** ⇒ **anchor 自己不画**，文件就是根节点
    （保住"只拖一个包时，树里就一个根节点、**不画**它的祖先目录"）；
  - 否则（有源落在子目录里）⇒ **anchor 自己成为分组节点**（`src=-1`、可勾选三态、
    不显大小、无 ✕）—— 拖 `IWP\database`（57 个包分布在 config/maps/mods/…）时根＝`database/`；
- 同层排序：**目录在前、文件在后**，各自按名（**不区分大小写**）；
- 跨盘等退化情形 ⇒ 至少给它一个名字（`rel` 以 `..` 开头就退回 `fileName()`）。

## 6. 两棵树**同一个装配函数**（第 282-291、333-342 行）
```cpp
apply_pair_tree_spec(package_list_, { {"包","大小",""}, {300,90,48}, 120, true });
apply_pair_tree_spec(entry_tree_,     { {"包内条目","大小","来源"}, {340,110,220}, 160, false });
```

注释给了列宽的来由（用户圈表头打「？」那条）：
