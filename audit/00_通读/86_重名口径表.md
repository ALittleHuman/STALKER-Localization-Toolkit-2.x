## 二、重名判定必须覆盖的五类（判定用的键）

| # | 类型 | 键怎么算 | 备注 |
|---|---|---|---|
| **D1** | 完全相同的路径 | 原样字节比较 | 最基础 |
| **D2** | 大小写不同（`A.txt` / `a.txt`） | **Windows：折小写**；其它平台：原样 | Windows 落盘会覆盖，必须算重名 |
| **D3** | 文件与目录同名 | **键里带类型**（`f:` / `d:`）⇒ 不算重名，但**要单独报冲突** | 两者在盘上不能共存；extract 现状：谁先谁赢、后到的报错（可见） |
| **D4** | 尾斜杠 / 归一化后相同（`dir\` vs `dir`） | 段末尾 `\` `/` 去掉、`\`→`/`、丢掉空段与 `.` | 与 `extract` 的 `safe_out_path` **同一套归一**（R27 的落点） |
| **D5** | Unicode NFC/NFD 变体（`é` vs `e`+组合符） | **本仓路径层不做 Unicode 规范化** ⇒ 按字节比较（**会**被当成两个不同名字） | 记一条已知缺口：Windows 上也确实可能生成两种名字；若要做，必须全链路统一，不能只在 parser 做 |

## 三、证据（为什么这些口径是安全的）

1. **真机包没有重名**：`Golden Sphere/gamedata.db_base`（11xx，5376 条目）
   - 字面相同重复组：**0**
   - 大小写折叠后重复组：**0**
   ⇒ "pack 拒绝重名"不会误伤既有语料；"extract 改 first wins"对现有语料**零字节变化**。
2. **零字节文件的 offset 不是 0**（回应 batch-2 的确认要求）：
   ```
   f  config/misc/gulag_general.ltx   0  0  493497  0
   ```
   （列：type / path / size_real / size_comp / offset / crc）
   5 条零长度文件全部 `offset=493497` ⇒ **合法的零字节文件用非零 offset 指向它的位置**；
   `offset==0` 只可能是"目录/没有数据"。
   ⇒ batch-2 那条 `!is_dir && offset==0 ⇒ malformed` **可以保留**（不是误杀零字节文件）。
   ★ 但补一句防御：若将来真遇到"零长度 + offset==0"的 xdb，它会被 `parse_xdb` 判成**目录**
   （三字段全零），所以**无论如何都不会走进"文件"分支** —— 这条规则只在"自相矛盾"的输入上触发。

## 五、不做（本批明确排除）

- **Unicode 规范化（NFC/NFD）**：全链路统一才有效，parser 单点做只会制造"同一文件两种键"。
- **跨层共用一把"重名键"函数**：需要先定 D3（类型进键）在 UI 侧怎么显示，留给后续批次。
- **`--strict` 开关**：等 3a/3b/3c 落地后单独加（它只影响 db unpack 的处置，不动解析）。

## 六、3a 落地（2026-10-24）✅

- `DbEntry` 之外新增 `DbDuplicate{first, second}`；`pack_db(..., duplicates=nullptr, strict=false)`。
- **重名检测放在归一化（`/`→`\`）之前** —— 这样报出的是**用户给的原始路径**
  （先归一化再报，`dupdir/a.txt` 会变成 `dupdir\a.txt`，和用户清单对不上）。
- 键按《口径表》D1/D2/D4：`\`→`/`、去尾斜杠、丢空段与 `.`、**Windows 折小写**。
- 默认：**只记录 + 不算失败**（与官方"不查重"一致）；`strict=true` ⇒ `error` 点名两条路径 + 返回空 vector。
- CLI `--pack-db`：打印 `PACKDB warning duplicates=N` + 逐条 `PACKDB duplicate first=… second=…`；
  加 `--strict` 才拒绝（帮助行已更新）。
- 行为判据进了 smoke（`checks` 935 → **936**）：同一份"重名条目"数据上，
  **默认产物非空**（不拒官方能吃的包）＋ **strict 返回空且错误里点名路径**。
- 副作用：`check_pack_db_api.py` 的 D0 锚点原本是 `std::string* error = nullptr);` ——
  签名加了两个默认参数后锚点失效（判据因此红了，**这是判据该有的行为**）。
  已把锚点改成 `bool strict = false);` 并保留旧锚点兜底（回滚时仍能判）。
- 结果：`--fast` **PASS**（exit 0）。
