## 1. ★★ 第 7 条：勾包**不许重建右树**（第 3886-3938 行）

```cpp
dir_after == dir_item && dir_after->isExpanded() &&
topLevelItemCount() == top_before && childCount() == kids_before
```
判红办法写明："把 `on_package_item_changed` 结尾改回 `refresh_rows()` 立刻红"。

## 3. ★★ B1-9：**先判红，不许先崩**（第 4034-4076 行）

修前：只把"任务壳接上了"写成 `check(...)`，紧接着就 `unpack_all_button()->click()` /
`task()->running()` —— **没判空就解引用**。
真出接线回归时自检会**段错误** ⇒ 门禁看到的是**崩溃而不是那条红**，且**此后所有用例不再执行**。

修法：把"前提"变成**控制流**：
```cpp
const bool async_wired = task() && task()->panel() && unpack_all_button() && out_edit();
check(async_wired, "…");
if (async_wired) { …真正跑那一段… }
```
★★ 这条对**我们自己的判据**是直接可用的：
  `wait_page_ready` 之后若 `page_widget == nullptr`，后面的 `page_widget->findChildren(...)`
  在**某些路径**上是安全的（Qt 成员函数对 nullptr 会崩）—— 必须同样改成"前提变成控制流"。

## 5. ★★ ④ 拖放：从"有 `setAcceptDrops`"到"载进来了"（第 4082-4268 行）

修前事实（第 4083-4085 行原话）：
> 原来全 `src/shell` 只有 `setAcceptDrops(true)`，**一个 `dropEvent/dragEnterEvent` 都没有**
> ⇒ 拖着没反应，这就是用户说的"选择没了"。

判据链：① 有「加包」按钮（`objectName == "fs_add_package"`）→
② 引擎从真包列条目 → ③ **过滤器真装在包列表与卡片上**（`is_attached_to`）→
④ **一个 Drop 事件进来 ⇒ 包真的加载进模型**。

★ 一处**离屏环境的事实**（第 4134-4137 行）：`sendEvent(widget, &QDropEvent)` **会被 Qt 拦掉**
（返回 false、事件根本不到控件；真实 drop 走 `QWidgetWindow` 那条平台通路）
⇒ 判据**直接把事件交给过滤器**。

★ ⑤ 目录拖入的口径在 2026-10-03 **被有意改写两次**，注释把"旧期望 2"和"为什么作废"都留着：
- 目录**自己不成源**（"右边永远不显示包体，除非包体本身在包内"）；
- 目录里的包**当场加载**（"只要拖入包或者文件夹就加载上去"，实测零点几秒）。
