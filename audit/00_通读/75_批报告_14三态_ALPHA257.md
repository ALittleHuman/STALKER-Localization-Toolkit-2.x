# 批报告：⑭ 三态化 + 地址复用覆盖面（ALPHA.255 → 257）

**日期**：2026-10-23　**版本**：2.0.0 ALPHA.257
**一句话**：⑭ 从"候选集空就红"改成**产品失败 / 未覆盖 / 判据自检失败**三态 + 逐页预期行数 + 对照组；
另把"宿主容器必须登记句柄"从"记得写"变成**不可能忘**（`make_host_widget()` + 静态锁）。
**30 次（trace 关）：PASS 30 / FAIL 0 / NOT_COVERED 0**。

## 1. ⑭ 的三态（按用户口径）

| 状态 | 条件 | 处理 |
|---|---|---|
| **PASS** | 该页有预期行数且量到了行、且标签带没被涂底 | —— |
| **PRODUCT_FAIL** | 有预期行数却量到 **0**，或标签带涂了底 | `check(false, …)`，点名页与像素证据 |
| **NOT_COVERED** | 判据**主体不存在**（本 Hub 没有可判的内置页，例如判据 ④ 的抬夹具形态）；或对照组/全部页都为 0（判据/环境不成立） | 记 note + `not_covered++`，**不冒充产品红** |
| **不适用** | 页不认识（插件页）/ 该页设计上就没有字段行 | 只记**可见 note**，**不**计未覆盖（否则消费侧永远拿不到 PASS，反而逼人放宽判据） |

**预期行数来自设计**（`attach_row` 调用点 × helper 调用次数）：
`fs 1`（另一行在"封包"标签页，同一时刻不可见）/ `convert 2` / `text 2` / `xml 2` / `video 3` / `fontpack 3`。

**对照组**：内置 `fs` 页。fs 为 0 但别的内置页有行 ⇒ fs 那 0 行算**产品红**；
所有页都 0 ⇒ **判据/环境坏**（NOT_COVERED + 点名），不产假红。

实测（一次运行）：
```
⑭ 逐页：fs 期望 1 行，量到 1 行       ⑭ 逐页：xml 期望 2 行，量到 2 行
⑭ 逐页：convert 期望 2 行，量到 2 行   ⑭ 逐页：video 期望 3 行，量到 3 行
⑭ 逐页：text 期望 2 行，量到 2 行      ⑭ 逐页：fontpack 期望 3 行，量到 3 行
SHELL-SMOKE ok checks=935 failed=0 not_covered=0 mode=dark
```

## 2. 收尾行新增第三态

`SHELL-SMOKE ok checks=N failed=M **not_covered=K** mode=…`
`SmokeResult.not_covered` + `not_covered(msg)` 助手（记 note + 计数，既不算 PASS 也不算 FAIL）。
判据侧同步：`check_package_fixture_pages.py` 解析 `not_covered=K`，K>0 ⇒ 打 `!!` + 记**台账**
（脚本退 2）——**不许静默算通过**。

## 3. 地址复用：从"记得写"到"不可能忘"

- 新增 `make_host_widget()`（`plugin_ui.h` 声明 / `widget_facade_qt.cpp` 实现）= `new QWidget` + `adopt_host_widget`；
- `hub.cpp` 两处根容器（页容器、面板容器）改用它；
- 新静态锁 **`tests/check_host_widget_adopt.py`**：`hub.cpp` 里**不许**再出现 `container = new QWidget`、
  `make_host_widget()` 必须恰好 2 处、工厂本体必须真的调 `adopt_host_widget`；
  自带反例自证（裸 new 红 / 空壳工厂红 / 干净样本绿）。

## 4. 顺带修掉一条**夹具自身的竞态**（P4 `task_run` 没被接受，2/30）

现象：marker 里明明有 `task_run|ret=1|…` 与 `run:1`，但判据读到的**快照**没有 ⇒ 红。
真因：L2 夹具的 `mark()` 由 **build 线程与 worker 线程共用一个文件句柄**，无锁 ⇒
读者可能先看到 worker 的行、后看到主线程的行（Python 侧缓冲区交错）。

修法两条（都在夹具里，不动产品）：
1. `mark()` 加 `threading.Lock`，**锁内 write+flush**；
2. 判据侧把"快照包含 `run:1`"改成**完成条件**：`wait_until(read_marker().contains("run:1"), 2000)`
   成功后再刷新快照（不固定 sleep）。

⇒ 这正是 68 号文档 S-5（诊断代码改变被测对象）的又一个实例。

## 6. 边界

- `not_covered` 现在只覆盖 ⑭ 这一族；其它判据将来要用"第三态"时，直接调 `not_covered(...)` 助手即可
  （收尾行已带 `not_covered=K`，判据侧已认）。
- `make_host_widget()` 只覆盖 **hub 里"会交给插件当根"的容器**；其它"宿主自造控件"（如 `field_row`）
  没有句柄语义，不需要 adopt。
