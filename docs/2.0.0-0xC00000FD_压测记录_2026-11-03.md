## 更正：0xC0000409 是「已规避」，不是「已归因修复」（DSH 2026-11-03）

早前写的是"根因是 C++ 在 GIL 块里迭代 `py::object` 拼列表 ⇒ 0xC0000409"。**这个机制不成立**：
持有 GIL 时迭代一个合法的 `py::list` 是标准操作，不会触发 `STATUS_STACK_BUFFER_OVERRUN`
（0xC0000409 是 `__fastfail`，通常来自 `/GS` 栈 cookie 被破坏、`abort()`、
CRT invalid parameter handler、或 pybind11 internals 存在两份）。

⇒ 准确表述：

```
0xC0000409：已规避（C++ 不再迭代 py::object 拼列表，改 Python 侧拼接），**未归因**。
不可作为"0xC00000FD 与它无关"的证据 —— 两起 fail-fast 可能同源（栈破坏是共同上游）。
下次任何 fail-fast（0409/00FD/0005）都先 !analyze -v 看 exception code + 栈，不先归因。
```
