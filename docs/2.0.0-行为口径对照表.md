## 2.0 最容易漏掉的 10 条（按风险排序）

1. **合并语义照文档写就错**：`merge(replace=True)` 已是 last-wins；且"散装最后覆盖"**根本没实现**。
2. **"没有滚动条就不许滚"是三层闸门**：`bar_shown` 四看 + 控件级 `guard_wheel` + `wheel_claim`(serial)。Qt 里别依赖默认 wheel 处理。
3. **SplitPane 的"用户收起"状态机**：Qt `QSplitter` 默认会按 `minimumSizeHint` 把它推回来，必须显式覆盖。
4. **`fit="viewport"` vs `fit="content"` 的绑定规则** + "没内容不许能滚"必须用矮窗口夹具才测得出。
5. **`TaskRunner` 收尾恢复前置状态 + `idle_status` 兜底**（Qt 里信号顺序要显式排队）。
6. **编码链顺序与两个程序化判定**（多变字节＝UTF-8 / 单字节家族用 `bytes(range(256))` 判）。
7. **ffmpeg 只认两处 + 惰性探测（失败也置位）+ 非阻塞三按钮窗 + 自动安装只能挂按钮**。
8. **字库定标三条硬参数**：`range(size,size+14)`、`墨迹高 ≤ cell−4` 且 `墨迹宽 ≤ 推进宽`（不留余量）、`need = max_y`。
9. **标签条钉住 + 页内视口**：Notebook 绝不能被包进滚动视口。
10. **布局 pack 顺序决定生死**：竖条(右) → 横条(底) → 被滚控件(expand)；操作栏必须先 pack 且 `side="bottom"`。

### 14.4 补充（2026-09-26）：user.ltx 写回**丢注释** —— 1.x 同样丢，**不是不一致**

HanaAgent 审计（2026-09-25）提了一条【低】：2.x `theme.cpp` 写回 `user.ltx` 会把注释丢掉。
**先去 1.x 取证再定**（不许猜），结论如下：

- 1.x `toolkit_platform.py`：`load_user_config()` → `_parse_ltx(f.read())`，**只产出
  section→dict 两层结构** —— 注释在**解析期就已经丢了**；
  `save_user_values()` 拿到 dict 后调 `_render_ltx(data)` **整文件重渲染** ——
  注释、空行与原格式都不保留。
- 也就是说 1.x 那句"**保留其它段**"只在**段**这一层成立；注释从来不在它的承诺范围内。
- ⇒ 2.x 的行为与 1.x **一致**：本条**结案、不改**（硬要"更聪明地保留注释"反而会与参照不同，
  违背"1.x 是行为代理"的口径）。
- 触发场景两者相同：保存主题 / 上次用过的字体 / 手动指定的 ffmpeg 路径。
