# CoP 追更预研（2026-11-03）：用**已知真值**量 diff 的准确率

**结论先说**：现有 `--xml-compare-dirs` 在 **`--mode text`** 下，对"开头插 3 条 + 改 1 条 + 删 1 条"的
已知真值 **5/5 全中、0 假变更**；两次跑 sha256 一致。⇒ **不需要序列对齐**。
但 **默认 mode=stats 会漏掉纯文本改动** ⇒ 将来的 `--track` 必须显式用 `--mode text`。

## 1. 样本怎么来的（合成，但真值已知）

CoP 4.26 IX-Ray 的 `gamedata\\configs\\text\\eng\\st_pf_dynamic_stashes.xml`（40 条 `<string id=…>`）：

- `old/`：原样复制；
- `new/`：**开头插 3 条** + **改 1 条文本** + **删 1 条**（真值 = added 3 / changed 1 / removed 1）。

## 2. 实测

| 命令 | 结果 |
|---|---|
| `--xml-compare-dirs old new`（默认 stats） | `only_b=3 only_a=1 text_diff=0` ⇒ **文本改动漏报** |
| `--xml-compare-dirs old new --mode text` | `only_b=3 only_a=1 text_diff=1` ⇒ **5/5 全中** |
| 纯文本改动（只改 1 条，无增删）`--mode text` | `kind=diff text_diff=1` ✅ |
| 同输入跑两遍（`--mode text`） | sha256 相同（`07B0D9ADEE71259B…`）✅ 确定性 |

**ID 平移担忧不成立**：CoP 的 XML 自带稳定 `id` 属性（`ids_a=40 ids_b=42`，净 +2），
或 `--ori-tree` 会保留原 id ⇒ 开头插入不会把全文件重编号。**"假变更率" = 0/5 = 0%**。

## 3. 对"AI 追更"的直接结论

1. **不需要序列对齐**（假变更率 0%）；
2. `--track` 的 schema 可以直接用：路径 + id + status + 原文；
3. **必须固定 `--mode text`**（否则纯文本改动会被当 `same`，这是本预言到的最大坑）；
4. 已知真值样本可复现（临时目录 `xrkit_cop_*`），命令：
   `--ori-tree` 只在该样本上做对比时才需要；直接对两个 XML 目录 `--xml-compare-dirs` 即可。
