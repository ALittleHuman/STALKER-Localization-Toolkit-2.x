# 2.0.0 跨插件服务契约（设计稿，2026-11-03）

> 用户 2026-11-03：「就是需要跨插件能力，联网插件提供的是基础的所需依赖和对接其他插件的接口，
> 这样多个插件都要联网只需要带上这个插件就行了。」
> 本文钉死**最小契约**与**范围边界**；实现按本文的 5 条规则 + 5 条判据走。

## 1. 为什么要它

现在插件之间没有任何通道：每个要联网的插件都得自己实现一遍 http_get。
"带一个联网插件就够"这句话，缺的不是插件，是**服务契约**：

```
api.services.register("net.http_get", fn)          # 提供者
api.services.call("net.http_get", url, timeout=5)  # 消费者
api.services.available()                           # 调试/doctor 列出已注册
```

## 2. 五条必须写死的规则

| # | 规则 | 理由 |
|---|---|---|
| 1 | 名字**必须带命名空间**（含 `.`，如 `net.http_get`） | 防两个插件抢同一个 `http_get` |
| 2 | 重复注册 ⇒ **报错**，不许静默覆盖 | 静默覆盖 = 谁都不知道自己在调谁 |
| 3 | 调用**按名字实时查找**，不缓存 callable | 提供者的 py 对象生命周期变了（加载失败回滚/退出清表）⇒ 消费者立刻得到"服务不可用"，不悬垂 |
| 4 | 服务调用在**调用者线程同步执行**，handler 必须线程安全 | 不写跨线程调度；"同进程、无隔离、无超时"必须写进契约 |
| 5 | 调用未注册的服务 ⇒ **抛明确异常**（文本含服务名），不返回 None | 零静默 |

## 3. 明确不做（否则滚成包管理器）

```
允许：无状态、请求-响应、粗版本（provides 里一个 int，如 net.http_get/1）
不做：自动安装/卸载、传递依赖的自动修复、版本求解器、加载顺序编排
★ 2026-11-09 更新：**模组前置**（另一件事，见 `2.0.0-插件清单与前置口径.md`）已在加载期做
  "id + 版本范围"检查：缺前置/版本不满足/循环依赖 ⇒ 该插件自动禁用（不调 register），
  启动后由「插件管理器」统一说明。服务（本文件）仍按名字实时查，两者互不替代。
```

循环依赖在这个范围里**不可能发生** —— 服务调用是运行时按名字查，不是加载期依赖。
这是"150 行够用"的关键论据。

## 4. 诚实的代价（写进文档，不承诺隔离）

- 同进程 ⇒ 提供者死循环会卡住消费者；这不是 bug，是设计性质；
- 没有超时、没有沙箱、没有权限；
- 提供者可以返回任意 Python 对象（契约只约定"调用者自己知道要什么"）。

## 5. 联网插件：用 WinHTTP，不要自带 _ssl.pyd

| 路径 | 依赖 | 评价 |
|---|---|---|
| **A（推荐）** 纯 Python + `ctypes` 调 `winhttp.dll` | 0 依赖、0 体积 | 系统组件自带 TLS/代理 |
| B 插件自带 `_ssl.pyd` + libssl/libcrypto | ~7.4 MB/插件 | 脆：ABI 必须精确匹配 `python314`；`ssl.py` 在 stdlib zip 里；DLL 搜索顺序要自己处理 |

⇒ 联网插件 = 一个**零依赖纯 Python 插件**，通过 `api.services` 暴露 `net.http_get`；
其他插件只写 `requires: ["net.http_get"]`，不重复实现 HTTP。

参考实现（不随包强绑，谁用谁抄）：`plugins/_sdk/http_winhttp.py`。

## 6. 与"宿主联网"的边界（最容易混）

```
宿主：用 WinHTTP 做**手动检查更新**（系统 DLL，不随包文件）；
      不把 WinHTTP 能力暴露给插件。
插件：可以自行联网，但须**自备依赖**（自带 _ssl.pyd + OpenSSL，或 ctypes 调 winhttp.dll）；
      宿主不提供代理/证书/错误处理，也不保证插件联网可用。
```

这条必须与包内"无联网面"判据一起读：那条判据禁的是**随包文件**
（`_ssl.pyd`/libssl/libcrypto/sqlite3/Qt6Network/tls），不是禁止宿主用系统 WinHTTP。

## 7. 判据（实现时一起加，全部静态/离线）

1. 注册重名 ⇒ 红（或 `--py-plugins` 报冲突）；
2. `call` 未注册服务 ⇒ 异常文本含服务名（不是 None、不是裸 KeyError）；
3. 提供者被禁用后 `call` ⇒ **同一个异常**（证明没缓存 callable）；
4. `--py-plugins` 输出每个插件的 `provides:` / `requires:`（并与 imports 可见合成一列）；
5. `requires` 缺失 ⇒ 启动日志一条可见警告（"插件 X 需要 net.http_get，当前没有提供者"），不静默。

## 8. 生命周期口径（2026-11-03 定，HA/DSH 一致）

**当前支持**：

- 插件**加载失败** ⇒ 按 owner 回滚（`registry.rollback_plugin` 同点 `unregister_services(owner)`），
  判据见 `tests/check_plugin_services.py` 的 `05_partial` / `06_check_partial`；
- **进程退出** ⇒ `shutdown_python()` 在 `Py_FinalizeEx` 之前清表。

**尚未实现**：

- 插件**运行时禁用/热卸载** —— 2.0 目前没有插件管理器入口；
  ⇒ **宿主不提供运行时禁用**；将来若加，注销点必须与"加载失败"同一处。

所以契约里不再写"提供者被禁用后立刻不可用"这种悬空表述：**能证明的只有上面两条**。
