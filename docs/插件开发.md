# 插件开发

> 插件 API 目前是**实验性**的：版本可能变，行为以 `api.ui`/`api.engine`/`api.host` 的实际能力为准。
> `PLUGIN_API` 是 Python 插件 API 的**契约版本**（当前 2；API 1 仍兼容），不是二进制 ABI；插件只支持 Python 文件/目录。
> 仓库自带的 `plugins/*_page.py` 是**非产品夹具**（API 用法样例，不承诺生产可用），可以抄写法，不要当依赖。

## 1. 目录与加载

```text
plugins/
  my_plugin.py            ← 形态一：单个 .py
  multi/                  ← 形态二：多文件插件
    __init__.py           ←   或 plugin.py（两个都有时优先 plugin.py）
    helper.py             ←   入口里可以 from . import helper
```

- 加载器只扫 `plugins/` **顶层**（不递归）：
  - 顶层 `*.py` = 单文件插件，稳定键 / 禁用键 = **文件名**；
  - 顶层**子目录** = 多文件插件，入口是 `<dir>/plugin.py` 或 `<dir>/__init__.py`；
    稳定键 / 禁用键 = **目录名**（与 `PLUGIN_INFO["name"]` 无关）；
  - 没有入口文件的子目录会被忽略（可放数据/资源）。
- **模块名 = 入口名**（文件名去掉 `.py`，或目录名），宿主把 `plugins/` 根追加进 `sys.path`。
  非合法标识符会被归一化（`00_provider` → `_00_provider`；`.`/`-` 等替换成 `_`），
  所以跨插件 import 时以"归一化后的入口名"为准。
- **插件内部多文件**：目录插件里直接 `from . import helper` 即可（宿主按包加载，`__path__` 指向该目录）。
- **跨插件 import（受限）**：
  - 必须在 `PLUGIN_INFO` **赋值之后**写（守卫从模块里读声明）；
  - 目标插件必须写进 `PLUGIN_INFO["depends"]`（键是目标插件的 **id**，值写 `depends` 里的版本范围）；
    import 时用目标插件的 **入口名**：`import aa_base`，声明用 `{"gate.base": ">=1.0"}`；
  - 未声明、目标被禁用、版本不满足 ⇒ `ModuleNotFoundError`（带可读理由），插件加载失败；
  - **运行时（按钮回调/worker）禁止跨插件 import**——那时没有"当前插件"上下文；跨插件调用请用
    `api.services.call`。

  ```python
  PLUGIN_INFO = {
      "id": "demo.consumer",
      "version": "1.0",
      "depends": {"demo.base": ">=1.0"},   # 声明用目标插件的 id
  }
  import aa_base                            # import 用目标插件的入口名（aa_base.py）
  ```
- 禁用记录在 `plugins/plugins.disabled`（插件管理器可查看）；被禁用的插件**不会加载**，会打印原因。

## 2. 最小插件

```python
# plugins/hello.py
PLUGIN_API = 2
PLUGIN_INFO = {
    "name": "Hello",
    "version": "1.0",
    "description": "最小示例",
}

SECTION = "tools"          # 菜单/工具分组（可选）

def register(api):
    api.log("Hello：已注册")

    def build():
        ui = api.ui
        ui.label(None, "你好，这是插件页")
        ui.button(None, "点我", lambda: api.log("clicked"))

    api.register_tool("hello", build, 100, "", "示例", "Hello")
```

- `register(api)` 在**主线程**调用；不要在这里做重活（会拖慢启动）。
- `register_tool(name, build, order=0, replaces="", subtitle="", title="")`：
  - `name` 全局唯一；`order` 决定页签顺序（内置页占 0–4）；
  - `replaces` 必须**显式**写目标 id 才会替换（被替换页只隐藏、可一键还原）；留空＝新增页；
  - `subtitle` 是页内副标题（小字说明），`title` 是页签标题；两者都为空时用 `PLUGIN_INFO["name"]`；
  - `build()` 也只在主线程调用，返回 `None` 即可（宿主负责套外壳/滚动）。
- 可选 `headless(api, args)`：给 `xrkit_cli --py-plugin-call` 用，**不能碰任何控件**。

## 3. 三条 API 面

| 面 | 用途 | 线程 |
|---|---|---|
| `api.ui` | 控件、对话框、任务壳、树/列表、复制/打开 | **绝大多数只能在主线程** |
| `api.engine` | 解包/封包、文本、字库、XML、视频、补丁、清单 | worker 也可调用（引擎自己保证） |
| `api.host` | 偏好读写、进程执行、路径/目录 | 见下 |

### 3.1 `api.ui` 的常见方法

- 造控件：`label(parent, text)`、`button(parent, text, on_click, width=None, style=None, enabled=True)`、
  `row(parent)`、`checkbox(parent, text, checked, on_change)`、`entry(parent, text, width, password=False)`、
  `text(parent, text, height, width, wrap)`、`combo(parent, values, on_change=None)`、
  `list(parent, rows, height)`、`tree(parent)`、`tabs(parent)`、`drop_box(parent, on_file, placeholder, width)`
- 改值/取值：`set_text`、`get_text`、`set_enabled`、`set_checked`、`checkbox_state`、`combo_value`、
  `combo_set_items`、`set_progress`、`progress`、`log_view_append`、`log`、`text_view`、`log_view`、
  `entry_on_change`
- 树：`tree_set_columns`、`tree_set_root`、`tree_on_expand`、`tree_set_children`、`tree_on_check`、
  `tree_set_checked`、`tree_checked`、`tree_set_filter`、`tree_filter_hits`、`tree_on_click`、
  `tree_on_activate`、`tree_on_action`、`tree_select`、`tree_selected_key`、`tree_selected_keys`、
  `tree_set_expanded`、`tree_expanded_keys`
- 列表：`list_set_row_count`、`list_set_row_text`、`list_selected_rows`、`list_set_multi`
- 布局：`pack(parent, child, side, expand, fill, padding, spacing)`、`split`、`split_add_pane`
- 菜单：`button_on_menu`（按钮左键动作菜单）、`context_menu`（右键菜单）
- 对话框：`ask_directory`、`ask_open_file`、`ask_save_file`、`ask_yes_no`、`pick_font`；`copy_text`、`open_path`
- 任务壳：`task_panel(parent, with_cancel)`、`task_run(panel, title, worker)`、`task_status(panel)`、
  `task_cancel(panel)`、`task_cancel_requested(panel)`、`task_on_message(panel, callback)`、`on_ui_thread()`

（以上是仓库内插件实际用到的名字；完整名字以 `xrkit_cli --ui-facade` 的 `UIFACADE Ui=…` 为准。）

**方法名/参数的事实来源**：
- `api.supports("ui.post")` / `api.supports("api.v2")`：启动时查询能力；缺能力返回 `False`，不要靠 `hasattr`。
- 运行 `xrkit_cli --ui-facade`：打印 `xrkit` 模块**实际暴露**的 `Api/Ui/Engine/Host` 名字与控件门面可用性
  （CLI 里 `available=0` 是正常的——没有 GUI 进程装门面；GUI 进程里为 1）；
- 参数名（核心 16 条）冻结在 `tests/check_ui_contract_params.py` 的 `CONTRACT_FROZEN`，门禁逐条对账；
- 方法名的字符串来自宿主实现（`py_host.cpp` 里的 `PyUi` 绑定）；仓库不提供单独的契约产物文件。

### 3.2 线程契约（最容易踩）

- worker 线程里**只允许** `ui.task_cancel_requested(panel)`、`ui.on_ui_thread()` 与 `ui.post(fn, *args)`；
  其余 `api.ui.*` 会被**拒绝并记 Warn**（控件不会变、返回值多半是 None）。
- `ui.post(fn, *args)`：任意线程调用，回调在宿主 UI 线程执行；`fn` 抛异常只记宿主日志，不穿越 Qt。
  页面销毁后宿主不保证回调不再触发，回调里先 `ui.alive(控件)` 自查。
- 正确姿势：主线程取控件值 → 打包成纯数据 → `task_run` 的 `worker(progress, message)` 里只做引擎调用 →
  结果用 `message(text)` 回主线程 → `task_on_message` 回调里再碰控件。
- `api.engine.*` 可以在 worker 里调；`api.host.pref_get/pref_set` 是文件读写，建议在主线程使用（并发写没有保证）。

### 3.2.1 生命周期（可选但推荐）

```python
def shutdown(api):
    ...  # 停线程、停 server、停止自己的定时器

def register(api):
    api.on_unload(lambda: ...)
```

- 宿主在 H4 reload、插件更新/禁用（若走进程内重载）和进程退出前调用 `shutdown(api)`，再跑 `api.on_unload` 回调；两者都在主线程、GIL 内执行。
- 回调里**不要碰控件**：此时页面可能已销毁；只做线程/进程/文件/模块清理。
- 宿主会清 import 期加载的插件模块；运行期 `exec`/动态 import 的 vendor 模块用 `api.register_module("xRayXmlParser")` 登记，卸载时宿主按 owner 清理。
- Python 线程不能强杀：`shutdown` 是协作式的，插件必须自己让 worker 退出。
- 不要在插件里做无限阻塞；没有超时保护，宿主只能等。

### 3.3 `api.host`

`pref_get(section, key, default)` / `pref_set(section, key, value)`（写工具自己的 `xrkit_user.ltx`）；
`run_process(options)`：`program`/`args`/`working_dir`/`on_stdout`/`on_stderr`/`should_stop`/`cancel_wait_ms`，
返回 `started/exit_code/stdout_lines/stderr_lines/stderr_tail/error`；`app_dir()` 等。

- `data_dir()` / `cache_dir()`：每个插件自己的持久目录/可清理缓存（`%LOCALAPPDATA%\xrkit\plugins\<id>`，插件更新不删除）。
- `start_process({"program","args","working_dir","log_path"})`：长驻/后台进程，**不建管道**，stdout/stderr 重定向到 `log_path`（空=NUL）；返回 `started/pid/error`。宿主用 kill-on-close Job 托管，进程随宿主退出一起收掉。
- `stop_process(pid)` / `process_alive(pid)`：停止并最多等 5 秒 / 查询存活。
- `http_get(url, timeout_sec=20, max_bytes=1<<20)` / `http_post(url, body, content_type="application/json", ...)`：返回 `ok/status/body/error/bytes/truncated`；联网总开关与宿主更新共用。
- `http_download(url, path, timeout_sec=300, max_bytes=8<<30)`：下载到文件，返回同上外加 `path`/`url`；失败不留半文件。**GB 级模型/运行库走这条**，不要用 `http_get` 攒进内存。
  `url` 可以是**字符串或列表**：只给一个地址时直连、不做任何探测；给多个时先各取 1 字节测首包延迟，快的先下、失败按序回退（`url` 返回实际用的那个）。**哈希校验由插件自己做**（宿主不知道期望值）。

## 4. `when` 条件

`register_tool(..., when={...})` 或命令注册里的 `when`：

- **falsy**（`None`/`{}`/`False`）⇒ 恒真；
- **dict** ⇒ 逐键比较上下文（`ContextValue` 是**字符串**，宿主喂进来的也是字符串）：
  - 字符串值**按原样比较**：`when={"loaded": "1"}`；
  - **非字符串值（数字/布尔）永远不会命中**——不要写 `when={"loaded": 1}`；
  - `None` 表示"该键不存在"也算命中；
- **可调用对象** ⇒ 以 `dict` 形式收到上下文，返回真值即命中；抛异常按不命中；
- 其它真值（含裸字符串）**恒真**——不要把裸字符串当条件。

## 5. 拖放

`ui.drop_box(parent, on_file, placeholder, width)` 会安装真实拖放过滤器：
拖入本机文件时回调 `on_file(user, path)`（当前只取**第一个**路径，UTF-8）。
页面级的"整行可拖"由 `api.ui` 的容器/页面宿主提供；需要多文件时自己用 `ask_open_file` 多选。

## 6. 网络

- 发行包保留 Python 的 SSL（`_ssl.pyd` / `libssl` / `libcrypto`），插件可以直接用
  `urllib.request` / `http.client`；也可以使用 `plugins/_sdk/http_winhttp.py`
  （ctypes + 系统 WinHTTP，走系统代理与系统证书）。不需要额外依赖。
- 插件联网**不受**「工具 → 联网功能」开关的强制约束（该开关只约束宿主自身的检查更新与下载）。
  需要尊重用户设置时，自行读取：

```python
enabled = api.host.pref_get("network", "enabled", "1") != "0"
```

- 联网调用要放在任务 worker 里（`ui.task_run` 的 `worker`），不要阻塞 UI 线程；
  自行设置超时与响应大小上限，失败用 `message()` 报出来。
- 动态下载的内容建议放固定缓存目录（例如 `plugins/.cache/<插件id>/`），便于用户清理与安全软件放行。
- 边界：插件与宿主同进程、同权限，能访问任意地址与本地文件；宿主不做域名白名单，也不审计请求。

## 7. 数据库（SQLite）

发行包随带 Python 标准库 `sqlite3`，可直接使用，不需要额外依赖：

```python
import os, sqlite3

db = os.path.join(api.host.app_dir(), "plugins", ".cache", "my_plugin.db")
os.makedirs(os.path.dirname(db), exist_ok=True)
con = sqlite3.connect(db)
con.execute("create table if not exists kv(k text primary key, v text)")
con.execute("insert or replace into kv values(?, ?)", ("k", "v"))
con.commit()
con.close()
```

- 大查询/写盘放任务 worker 里，不要阻塞 UI 线程；
- 数据库文件放插件自己的目录（如 `plugins/.cache/<插件id>/`），便于清理；
- 不要打开不可信的 `.db` 文件（SQLite 文件不是可信输入）；
- 并发写请自行串行化（同一连接不要跨线程用）。

## 8. 调试与排错

| 手段 | 用法 |
|---|---|
| `xrkit_cli --py-plugins plugins` | 加载并打印 `files/loaded/registrations/errors`、逐条 `warn`/`disabled`、坏插件的 `residue`（应为 0） |
| `xrkit_cli --ui-facade` | 打印宿主实际暴露的 `api.ui` 名字（方法清单的权威来源）与门面可用性 |
| 日志 | 界面日志与 `logs\log_*.txt` 同源；`api.log()` 写一行 |
| 插件管理器 | `xrkit_plugin_manager.exe` 查看已加载/禁用/更新状态 |
| 拆分定位 | 先只留一个插件；`register` 里抛出异常会被记为注册错误，不会带病注册 |

**限制**：

- 插件与宿主**同进程**：`import` 期的副作用、崩溃、死循环都会影响宿主；
- `PLUGIN_INFO.requires` 缺前置时插件会被**自动禁用**（管理器可见），不会报"加载失败"；
- 插件更新是"整目录备份 + 替换"，失败回滚；原本禁用的插件更新后仍禁用。

## 9. 无界面入口（给脚本/门禁）

```python
def headless(api, args):
    # args 是 JSON 解析出的 dict；不得触碰 api.ui
    return {"ok": True, "value": args.get("path", "")}
```

```bat
xrkit_cli --py-plugin-call plugins {"path":"E:\\x"}
```

返回值会被序列化打印；异常按失败返回。适合做"同一实现两种入口"的校验
（界面按钮与 headless 走同一段逻辑）。
