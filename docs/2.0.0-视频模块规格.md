## 1. 编码器选择（1.x `CODEC_MAP` / `_pick_video_encoder`，172–228 行）

- `CODEC_MAP = {mpeg4→libxvid, xvid→libxvid, msmpeg4v3→libxvid, theora→libtheora}`；
  参考编码不在表里 ⇒ 首选 `libtheora`。
- **可用编码器惰性扫描一次**（`ffmpeg -encoders`，timeout=10s，解析 ` V`/` A` 行的第 2 列）：
  1.x 明写**不能放构造函数**——Hub 启动会一次性构造全部 6 个 App，冷盘/杀软下用户看到的是
  "Hub 启动就卡住"。**失败不许静默**（原先是 `except: pass` ⇒ 集合空、静默回退 mpeg4）。
- 首选不可用 ⇒ 按 `[libtheora, libxvid, mpeg4]` 顺序回退；**一个都没探到** ⇒ 回退 `mpeg4`
  **并告警**（内置编码器总可用，但输出编码与参考不一致，必须让用户知道）。

## 2. 命令行构造（1.x `convert()`，244–329 行）

参考参数（缺省值就是 1.x 的缺省）：`ref_vcodec=""`、`ref_w/h/fps=0`、`ref_vbitrate=0`；
音频 `ref_ar=48000`、`ref_ac=2`、`ref_abitrate=160000`（且只在**参考值 > 0** 时覆盖）。

```
[ffmpeg, -y, -i, <输入>]
视频：
  若选中的编码器 ∈ {libxvid, mpeg4}：
      -c:v <vcodec> -b:v <ref_vbitrate 或 2500000> -pix_fmt yuv420p
  否则（libtheora 家族）：
      有 ref_vbitrate ⇒ -c:v libtheora -b:v <ref_vbitrate> -pix_fmt yuv420p
      没有          ⇒ -c:v libtheora -q:v 7 -pix_fmt yuv420p -g 30
缩放/帧率（`-vf`，逗号连接，**先 scale 后 fps**）：
  need_scale = ref_w>0 且 ref_h>0；need_fps = ref_fps>0
  源与参考**同宽高** ⇒ 取消 scale；源与参考 fps 差 < 0.01 ⇒ 取消 fps（避免无谓重编码）
音频：
  ffprobe **解析失败**（src_info=None）⇒ 保留音频选项 + **告警**（旧版会当"无音轨"直接 -an）
  源**确认有音轨** ⇒ -c:a libvorbis -b:a <ref_abitrate> -ar <ref_ar> -ac <ref_ac>
  源**确认无音轨** ⇒ -an（只有这一种情况才禁音轨）
收尾：-f ogg <输出>
```

- **完整命令行写"详细日志"**（只落盘，不刷 GUI）——排障最需要。
- `src_info` 来自 `ffprobe`（`parse_video_info`），拿它判"有没有音轨"与"要不要缩放/改帧率"。

## 3. 进度与取消（340 行起）

- 读 ffmpeg **stderr**，用 `time=(\d+):(\d+):(\d+)\.(\d+)` 抓当前时间，配合源时长算百分比。
- `cancel()`：置 `_cancelled` → **terminate 子进程**；`convert()` 开头若已取消直接返回"已取消"；
  **`convert()` 不清零 `_cancelled`**（清零只由 `reset_cancel()` 做）。

## 4. 判据（实现时要立的锁）

1. **argv 差分**：一组输入（参考编码 × 有无参考码率 × 源同尺寸/异尺寸 × 同帧率/异帧率 ×
   有音轨/无音轨/ffprobe 失败）→ 我们的 argv **逐项等于 1.x 的 argv**（参照用 **AST 摘出 1.x
   方法 + 桩 `subprocess.Popen`/`ffprobe` 后 exec**，期望值现算自源码，不手写）。
2. **编码器选择表**：首选可用 / 首选不可用走回退 / 全不可用 ⇒ mpeg4 + 告警（三条各一例）。
3. **失败与取消**：ffmpeg 启动失败 ⇒ 返回失败 + 理由；转换中取消 ⇒ 进程被 terminate 且返回"已取消"。
4. **不留半成品**：失败时输出文件不留下（与"拒绝式检查判据落在副作用上"同一条纪律）。
