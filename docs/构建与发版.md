# 构建与发版

## 安装与回退

安装：把构建产物目录整体放到目标机器；运行 `xrkit_app.exe`/`xrkit_cli.exe`，不写注册表、不装服务。

回退：保留上一版目录，直接换回旧目录即可；更新失败由 `xrkit_updater.exe` 回滚事务。

注意：解包/封包的默认落点是**来源所在目录**（引擎 `resolve_output_root`）；不改落点直接开始，产物会落进来源包所在目录。工具不会自动安装或修改游戏文件，但不会替用户改默认落点。

## 1. 前提

- Windows 10/11 x64；
- Visual Studio 2022 Build Tools（C++ 工作负载）；
- CMake ≥ 3.21、Ninja；
- Qt 6.8.3 MSVC 2022 x64；
- Python 3.14（构建期需要；发行包自带 embeddable Python）。

路径可用环境变量覆盖：

```text
XRKIT_VS       VS Build Tools 根
XRKIT_QT       Qt 根
XRKIT_PYTHON   构建期 Python
```

## 2. 构建

```bat
scripts\build.ps1                          :: msvc-release：CLI + 引擎
scripts\build.ps1 -Preset msvc-shell       :: GUI + xrkit_smoke
```

产物：

```text
build\msvc-release\tools\cli\xrkit_cli.exe
build\msvc-shell\src\shell\xrkit_app.exe
build\msvc-shell\src\shell\xrkit_smoke.exe
```

## 3. smoke 已从本体拆出

RC2 起：

- `xrkit_app.exe` **不再包含** `smoke.cpp` / `--smoke`；
- `xrkit_smoke.exe` 是独立离屏自检，带自己的版本资源与 manifest；
- 它只用于构建、门禁和包内临时自检，**不随发布包发放**；
- `package.ps1` 打包时临时拷入 `xrkit_smoke.exe`，自检后删除；
- 自检结论行：

```text
SHELL-SMOKE ok checks=N failed=0 not_covered=0
```

## 4. 打包

正式入口是 CLI 驱动：

```bat
xrkit_cli --build-package version.json 2.0.0 BETA <通道序号>
xrkit_cli --build-package version.json 2.0.0 BETA <通道序号> --prebuilt
```

- `--prebuilt` 只算 sha/打包/收尾，不重新编译；
- `scripts\package.ps1` 由 `--build-package` 调用；手工调用必须给齐参数：

```bat
scripts\package.ps1 -BuildIndex <通道序号> -VersionString "x.y.z.<build>" -ExeSha256 <sha256>
```

- 产物是目录，不压 zip；落点：

```text
dist\<主版本>\<标记>\<序号>\
```

- `platforms\` 同时带 `qwindows.dll` 与 `qoffscreen.dll`；`qoffscreen.dll` 随包常驻，不是自检后删除；
- 只出目录，不压 zip；
- 包内自检结论行是 `SHELL-SMOKE ok checks=N failed=0`。

- 包内 `version.txt` 同时写 `index`（通道序号）和 `build`（全局构建号）；
- 包内 `xrkit_smoke.exe` 应为空；smoke 只在自检期间存在；
- 打包会跑包内 smoke、Python 宿主、插件链、IX-Ray selftest；
- 旧序号目录**不自动删除**；发布过的旧包不要动。

## 5. 发版

```bat
scripts\release.ps1 -Index <通道序号> -Version 2.0.0 -Mark BETA
```

脚本做四步：

1. `--write-version` 递增全局 build_counter，写 `version.h` / `.rc` / `version.json.current`；
2. 编译 `msvc-shell` 与 `msvc-release`；
3. `--build-package --prebuilt`；
4. 校验 `version.txt`、包内 CLI `--version`、包内 app VERSIONINFO、sha256。

产物：

```text
dist\2.0.0\BETA\<通道序号>
```

**脚本只构建/打包/校验，不发布。**

## 6. 版本模型 C

- 唯一先后依据：`version.json` 的 `build_counter`，每次构建 +1；
- 稳定版版本串：`x.y.z`；
- 测试版版本串：`x.y.z.<build>`；
- 通道（ALPHA/BETA/RC）只作标签，不进版本串；
- dist 落点：`dist\x.y.z\<标记>\<通道序号>`;
- 测试版比较只比 build；正式版 > 同版本测试版。

示例：

```text
BETA.260 + build 520 ⇒ 2.0.0.520
RC.2    + build 514 ⇒ 2.0.0.514
```

## 7. GitHub / npm 更新

- GitHub：BETA/RC 必须创建为 **Prerelease**；正式版才用 Release；
- 一个 Release 只放一个 zip；资产名用 `<build>.zip`，tag 用版本串；
- npm workflow：`.github/workflows/publish-update-npm.yml`；
- 模型 C 的四段版本不是合法 npm semver：workflow 会转成 `x.y.z-<build>`，资产路径仍是 `full/x.y.z.<build>.zip`；
- 客户端同时尝试精确 npm 版本和 `x.y.z-<build>` 后备 URL；
- 当前 BETA.260 只本地打包，**没有上传 GitHub/npm**；RC2 `2.0.0.514` 是已有 Prerelease。

## 8. 门禁

```bat
third_party\python-embed\python.exe tests\run_ci.py --fast
```

- fast：公开 CI，外部前提缺件记告警；
- release：任何 SKIP 即 FAIL；
- 常用单项：`check_release_criterion.py`、`check_version_consistency.py`、`check_fontpack_ref.py`、`check_host_update_poll.py`；
- 手工构建必须设置 `XRKIT_PYTHON`，否则可能量不到 `/showIncludes` 前缀，改头文件不重编。

## 9. 常见问题

| 现象 | 处理 |
|---|---|
| `vcvars 环境导出失败` | 检查 `XRKIT_VS` 下 `VC\Auxiliary\Build\vcvars64.bat` |
| `LNK1104` 打不开 exe | 先关掉正在运行的 `xrkit_app`/`xrkit_plugin_manager`/`xrkit_cli` |
| 包内自检失败 | 看 `logs`，常见是缺 `qoffscreen.dll` 或 Python 运行库 |
| smoke 直接退 `0xC0000409` | 构建目录缺打包期资源；用 `--build-package` 的包内自检 |
| 包内 CLI build 与 version.txt 不符 | 确认 `version.txt` 有 `build=`，且 `--write-version` 已写回 |
