# 构建与发版

## 1. 环境

| 依赖 | 版本/位置 | 说明 |
|---|---|---|
| Windows | 10/11 x64 | |
| Visual Studio | 2022 Build Tools（MSVC 14.44） | `cl.exe` 不在 PATH，脚本会注入 vcvars 环境 |
| CMake + Ninja | VS 自带（`Common7\IDE\CommonExtensions\Microsoft\CMake\…`） | 脚本自动加进 PATH |
| Qt | 6.8.3 msvc2022_64 | 只 GUI 档需要 |
| Python | 3.14 embeddable（`third_party\python-embed`） | 运行插件/自检用；**不需要系统 Python** |
| 1.x 仓库（可选） | `..\STALKER_Toolkit` | golden 语料与少数生成器判据需要它 |

可覆盖的环境变量：`XRKIT_VS`、`XRKIT_QT`、`XRKIT_PYTHON`、`XRKIT_TOOLKIT_1X`。
（`XRKIT_SHOWINCLUDES_PREFIX` 是 CMake 变量，由 `build.ps1` 量出后自动传入，不需要手动设。）

## 2. 两档构建

```bat
scripts\build.ps1                          :: 默认 msvc-release：CLI + engine/core（**不含 Qt**）
scripts\build.ps1 -Preset msvc-shell       :: GUI（xrkit_app.exe）
scripts\build.ps1 -Reconfigure             :: 重新导出 vcvars 环境
```

产物：

```text
build\msvc-release\tools\cli\xrkit_cli.exe
build\msvc-shell\src\shell\xrkit_app.exe
```

> **构建前提**：必须通过 `XRKIT_PYTHON` 指定可用的 Python（embeddable python 或 `py -3`）。
> 未指定时脚本退回 `python`，可能量不出 `/showIncludes` 前缀，导致头文件依赖缺失（改 `.h` 不重编）。

## 3. 打包

```bat
:: 正式入口：CLI 驱动（算 sha256 / 版本串 → 调 package.ps1 → 包内自检）
xrkit_cli --build-package version.json 2.0.0 BETA 253
xrkit_cli --build-package version.json 2.0.0 BETA 253 --prebuilt   :: 已编译好、只打包

:: 计划模式（不落盘）
scripts\package.ps1 -PlanOnly

:: 手工调用 package.ps1 时必须给齐（否则脚本会拒绝：打包链必须由 --build-package 驱动）
scripts\package.ps1 -BuildIndex 253 -VersionString "2.0.0 BETA.253" -ExeSha256 <sha256>
```

- 分类规则唯一一份（`Get-PackageDest`），`-PlanOnly` 与真打包共用；
- Qt 运行时用 `windeployqt` 铺；`platforms\` **同时**带 `qwindows.dll` 与 `qoffscreen.dll`（**qoffscreen.dll 随包常驻**）；
- 产物形态：脚本**只出目录、不压 zip**；发布更新资产时另行把该目录压成单个 `.zip`（更新器只认 `.zip`）；落点 `dist\<主版本>\<标记>\<序号>\`（只留序号）；
- **Python 运行期随包**：保留 `_ssl.pyd`/`libssl`/`libcrypto` 与 `sqlite3.dll`/`_sqlite3.pyd`，
  插件可用标准库 HTTPS 与 `sqlite3`；仍剥掉 Qt 的 `Qt6Network.dll`/`tls\`（宿主更新走 WinHTTP 系统组件）；
- 包内写 `README.txt` 与 `version.txt`（版本 + 源提交 + 构建时间）；**不发放 `xrkit_user.ltx`**；
- 打完后**从包目录真跑一次** `xrkit_app.exe --smoke`（结论行 `SHELL-SMOKE ok checks=N failed=0`，且退出码 0），再查包内 exe 的
  VERSIONINFO 与 sha256、`--python-host` 的 `gil=released`、IX-Ray `--selftest`。

## 4. 安装与回退

- 解压后直接运行；删除目录即回退，不写注册表。
- 解包默认落点是**来源包所在目录**（引擎 `efs::resolve_output_root`：第一个源所在目录；无源用当前目录）；不自动安装或修改游戏文件。

## 5. 构建与打包（BETA/RC 预发布）

```bat
scripts\release.ps1 -Index 253 -Version 2.0.0 -Mark BETA
```

四步（脚本会逐步校验）：

1. `xrkit_cli --write-version 2.0.0 BETA 253`（改 `version.h` 与 `.rc`，不动 `version.json.current`）；
2. `build.ps1` 两档（此时没有进程占用 `xrkit_cli.exe`）；
3. `xrkit_cli --build-package version.json 2.0.0 BETA 253 --prebuilt`（只算 sha + 打包 + 收尾）；
4. 校验包内 `version.txt` / `xrkit_cli --version` / 包内 app 的 VERSIONINFO 三者一致。

产物：`dist\2.0.0\BETA\253\`（旧序号目录保留；重建同序号＝覆盖该序号自身）。

发布资产：把该目录压成**单个** `.zip`（`xrkit_app.exe` 在根层或包内单层目录都可以，更新器会递归定位）。

BETA/RC 包上传到 GitHub 时必须勾选 **Set as a pre-release**（Prerelease），**不要**作为正式 Release；只有正式版才用 Release。`scripts\release.ps1` 只做本地构建/打包/校验，不负责上传，也不会替你选择发布状态。

更新器只认 `.zip`，且一个 Release 或 Prerelease 只应有一个 zip。


## 6. 更新分发（npm / unpkg）

GitHub Release 仍是“源”；更新包另发一份到 npm，客户端优先走 unpkg，失败才回退 ghfast/gh-proxy/GitHub。

工作流：`.github/workflows/publish-update-npm.yml`  
npm 包：`@alittlehuman/stalker-toolkit-update`  
客户端 URL：`https://unpkg.com/@alittlehuman/stalker-toolkit-update@<version>/full/<version>.zip`

### 6.1 首次引导（只需一次）

npm 的 Trusted Publishing 要求包已经存在，并且账号开启 2FA。

```bat
:: 在一个临时 npm 包目录里，先发一个最小版本
npm publish --access public

:: 配置 GitHub Actions 为可信发布者（文件名必须与 workflow 一致）
npm trust github @alittlehuman/stalker-toolkit-update ^
  --file publish-update-npm.yml ^
  --repo ALittleHuman/STALKER-Localization-Toolkit-2.x ^
  --allow-publish
```

之后 npm 的 GitHub Actions 发布不再需要 token/OTP。

### 6.2 每次发布

1. 先有 GitHub Release 资产（例如 `252.zip`）；
2. GitHub → Actions → **Publish npm update package** → Run workflow：
   - `version`：`2.0.0-beta.252`
   - `release_tag`：`2.0.0-beta.252`
   - `asset_name`：`252.zip`
   - `dist_tag`：`beta`
3. workflow 会下载资产、生成 `manifest.json`、发布 npm 包；
4. 客户端更新检查拿到版本后，先试 unpkg 的 zip；失败回退 ghfast/gh-proxy/GitHub。

约束：

- workflow 依赖 **GitHub Release 资产**；没有资产就无法发 npm；
- npm 包包含完整 zip，36MB 包在 npm 上约 36MB tarball；
- 本机实测 unpkg 36MB 约 4.6s（7.9MB/s），npmmirror tarball 约 2.9MB/s，npm 官方 tarball 约 140KB/s；
- 公共 CDN 速度随时段/地区波动，客户端必须保留回退链，不能只认 unpkg。

## 7. 门禁（提交前至少跑前两道）

```bat
:: 1) 三层门禁
third_party\python-embed\python.exe tests\run_ci.py            :: local 全量
third_party\python-embed\python.exe tests\run_ci.py --fast     :: 公开 CI
third_party\python-embed\python.exe tests\run_ci.py --release  :: 正式版发版门禁（任何 SKIP 即 FAIL；BETA/RC 预发布用 --fast）
:: 2) GUI 自检
set QT_QPA_PLATFORM=offscreen && build\msvc-shell\src\shell\xrkit_app.exe --smoke
:: 3) 单项检查器（示例）
third_party\python-embed\python.exe tests\check_audit_p0_guards.py
third_party\python-embed\python.exe tests\check_host_update_poll.py
third_party\python-embed\python.exe tools\gen_winres.py --check
```

规则（很重要）：

- **仓库自带的门禁文件缺件 = FAIL**（不许"删掉门禁文件变绿"）；
- **外部前提缺件（MSVC/真机样本/1.x 仓库）= SKIP + 记入未覆盖清单**；`--release` 下任何 SKIP 即 FAIL；
- 每个 checker 约定退出码 `0/1/2`（PASS/FAIL/SKIP）与固定收尾行。

## 8. 排障

| 现象 | 处理 |
|---|---|
| `configure` 卡在 "Detecting CXX compiler ABI info" | 确认构建进程有权限执行 `cl.exe`（被杀软/权限拦住时会卡住） |
| 改了 `.h` 不重编 | 设 `XRKIT_PYTHON` 后 `-Reconfigure`；看 `.ninja_deps` 是否含头文件 |
| `vcvars 环境导出失败` | 检查 `XRKIT_VS` 路径下 `VC\Auxiliary\Build\vcvars64.bat` |
| 包内自检 `failed=1` | 先看 `logs`；常见是缺 `qoffscreen.dll` 或漏了 Python 运行库 |
| 构建目录里 `xrkit_app.exe --smoke` 直接退 `0xC0000409`、无输出 | 构建目录缺打包期资源（`python\`、`platforms\` 布局）——**这不是代码问题**；请用 `--build-package`（内部会在 `build\package_stage` 里跑一次包内自检）或直接跑包内 exe |
| `check_ui_contract_params.py` 失败 | `api.ui` 的参数名/顺序改了：改回，或同步更新 `CONTRACT_FROZEN` |
