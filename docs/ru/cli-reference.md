# Справочник CLI (`xrkit_cli.exe`)

Здесь описаны основные команды. **Полная таблица параметров — в самой программе:**

```bat
xrkit_cli --help
xrkit_cli --help <команда>
xrkit_cli --actions
```

`--actions` выводит структурированную таблицу действий (JSON), `--help` — полный текст.

## 0. Общие соглашения

- Коды возврата: `0` — успех; `1` — ошибка (с причиной); `3` — действие не выполнено (неверные аргументы, защита записи или требуется подтверждение; читайте строку с причиной).
- Пути с пробелами или не-ASCII символами заключайте в кавычки; по возможности используйте абсолютные пути.
- Названия кодировок — стандартные (`windows-1251`); если не уверены, используйте `auto`.
- Список `--only` содержит по одному пути внутри пакета на строку; разделитель `/`, регистр важен; пустой список отклоняется.
- Режимы GUI «Статистика строк/ID» и «Сравнение текста по ID» соответствуют `--mode stats` и `--mode text`.

## 1. Отслеживание изменений и снимки

```bat
xrkit_cli --snapshot <корень> <out.json>
xrkit_cli --diff-snapshot <старый.json> <новый.json>
xrkit_cli --track <baseline_dir> <current_dir> <out_dir> [--baseline old.json] [--rehash]
```

- `--snapshot`: файловый manifest (`rel/kind/size/mtime/sha256` + порядок строк JSGME), без временных меток; два запуска дают одинаковые байты.
- `--diff-snapshot`: сравнивает только manifest и печатает added/removed/modified/jsgme_changed; даже при изменениях возвращает 0.
- `--track`: файловая предварительная фильтрация + сравнение текста XML по записям; пишет `report.json` и `changed/*.tsv`; `.ltx/.script/.txt` сравниваются только на уровне файлов.

## 2. Сравнение XML

```bat
xrkit_cli --xml-compare-dirs <каталогA> <каталогB> [--mode stats|text] [--enc-a X] [--enc-b Y]
```

По умолчанию `stats` сравнивает только наборы ID и число файлов; для поиска изменений текста нужен `--mode text`. Обрабатываются только `.xml`.

## 3. Извлечение текста

```bat
xrkit_cli --extract-text <исходный_каталог> <каталог_вывода> [--prefix p] [--id-prefix p] [--lang rus] [--clean]
```

`<исходный_каталог>` может быть самим `scripts`/`gameplay`, либо **корнем игры, корнем мода или корнем addons**:

- в режиме корня рекурсивно находятся все поддеревья `scripts`/`gameplay`;
- изменённые файлы сохраняют **путь относительно исходного корня** (например, `addon/gamedata/scripts/...`);
- таблицы текста попадают в читаемый движком `.../gamedata/configs/text/<lang>/`; `--lang` по умолчанию `rus`;
- префикс ID каждого поддерева содержит хэш относительного пути, поэтому ID не пересекаются между таблицами;
- конфигурационный XML, корень которого не `string_table`, считается «без текста»: не обрабатывается как таблица и не копируется;
- поддеревья без переводимого текста учитываются только как `notext`, пустые файлы не создаются;
- каталог вывода не может совпадать с исходным, содержать его или находиться внутри него.

`--clean` сначала очищает каталог вывода.

Поля итоговой строки:

```text
TEXT ok kind=scripts files=4 strings=18 chars=202 notext=1 skipped=1 replskip=0 writefail=0 ...
```

- `notext`: число файлов без переводимого текста;
- `skipped`: число пропущенных файлов;
- `replskip`: извлечено, но не заменено (должно быть 0);
- `writefail`: ошибок записи (должно быть 0).

Строки скриптов с `--` могут быть пропущены логикой удаления комментариев; см. `已知问题与边界.md`.

## 4. Пакет локализации

«Размер» векторного шрифта IX-Ray — это не изменение TTF, а размер атласа во время работы:

- генератор вычисляет `FontAtlasSize` по числу символов в пакете и максимальному размеру из `fonts.ltx`;
- минимум 4096, затем степень двойки до 8192, только увеличение;
- патч размера также записывает `engine_external.ltx` в патч.

`--merge-glyphs` копирует в целевой шрифт только недостающие глифы и `hmtx`; **вертикальные метрики hhea / OS/2 цели не изменяются** (от ascent/descender зависит высота текстовой строки в движке). При подсчёте символов исключается область C1 (U+0080–U+009F), поэтому continuation-байты UTF-8 не считаются реальными символами.

### `--font-pack`

```bat
xrkit_cli --font-pack ^
  --ref <эталонный_пакет|builtin> ^
  --text-root <корень_перевода|корень_пакета> ^
  --out <каталог> ^
  [--font <TTF>] [--font-weight 700] [--game SoC|ClS|CoP] [--lang rus] [--langs rus] ^
  [--on-missing fail|warn] [--require-full-cyrillic] [--merge-glyphs <исходный_TTF>] ^
  [--patch-offsets 3,-1] [--jsgme --jsgme-name <имя>]
```

- `--ref builtin`: встроенный bitmap-шаблон (SoC/ClS/CoP);
- `--ref <каталог>`: сканирует `fonts.ltx` и выбирает writer по доказательствам (векторные шрифты ⇒ vector, bitmap-текстуры ⇒ bitmap); при конфликте или отсутствии данных требуется `--writer bitmap|vector`;
- `--text-root` может быть корнем пакета, корнем `gamedata`, `gamedata/configs/text/<lang>` или каталогом текстов;
- без `--font` инструмент ищет подходящий китайский шрифт; для вариативного шрифта `--font-weight` задаёт ось `wght` (100–900, по умолчанию 700);
- `--patch-offsets` создаёт отдельные патчи размера, совместимые с `--jsgme`;
- JSGME всегда раскладывает в `MODS\<имя>\`; `--jsgme-category` оставлен только для совместимости и игнорируется с предупреждением;
- bitmap-атлас не больше 8192; для крупного набора 50px атлас принудительно расширяется до 8192×4096, без многстраничности и автоуменьшения;
- участвуют все секции шрифтов; базовые HUD/STAT пропускаются; особые секции проверяются вручную;
- векторный IX-Ray записывает `FontAtlasSize=8192` в `gamedata/configs/engine_external.ltx`.

### `--font-size-patch`

```bat
xrkit_cli --font-size-patch <эталонный_пакет> <offset> <каталог_вывода>
```

Меняет только явные `size = N` в IX-Ray `fonts.ltx` (наследуемые секции следуют за родителем; TTF не перерисовывается). Это отдельный механизм от bitmap `--patch-offsets`.

### `--extract-pack`

```bat
xrkit_cli --extract-pack <исходный_корень> <корень_вывода> [--no-language-pack] [--no-rewritten]
```

Порядок извлечения: корневой `scripts` + `configs/scripts` + `gameplay`; пустой результат возвращает 1. Исходный корень должен содержать `configs`/`config`.

### `--langpack-scan`

```bat
xrkit_cli --langpack-scan <пакет_локализации|каталог>
```

Определяет слоты `gamedata/configs/text/<lang>` и ресурсы шрифтов/текстур; не распаковывает и не изменяет файлы.

## 5. Просмотр ресурсов

```bat
xrkit_cli --dump <файл_пакета> [формат_DB]
```

Выводит записи шести форматов DB/SquashFS; только чтение. Формат определяется автоматически, если не указан.

## 6. Версия и упаковка

| Команда | Назначение |
|---|---|
| `--version` | Печать версии (включая `build=`) |
| `--write-version <версия> <метка> <номер>` | Увеличить `build_counter`, записать `version.h/.rc/version.json.current` |
| `--build-package <version.json> <версия> <метка> <номер> [--prebuilt]` | SHA, упаковка, запись истории; `--prebuilt` только упаковывает |
| `--exe-version <exe>` | Прочитать VERSIONINFO |
| `--sha256 <файл>` | Печать SHA256 |

Модель C: версия тестовой сборки — `x.y.z.<build>`; метка/номер задают только каталог канала:

```text
BETA.270 + build 530 ⇒ 2.0.0.530, dist\2.0.0\BETA\270
```

## 7. Самопроверка и диагностика хоста

```bat
xrkit_cli --version
xrkit_cli --python-host
xrkit_cli --py-plugins <каталог>
xrkit_cli --ui-facade
xrkit_cli --py-plugin-call <каталог> [JSON]
```

Диагностика обновления (обычно из GUI):

```bat
xrkit_app --host-update-check
xrkit_app --host-update-apply
```

`--host-update-apply` скачивает и запускает `xrkit_updater.exe`; при успехе текущий процесс завершается.

`--smoke` не является командой CLI/GUI; офскрин-самопроверка выполняется отдельным `xrkit_smoke.exe`. В релизный пакет smoke не входит.
