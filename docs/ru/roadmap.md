# Планы (вне 2.0.0)

Здесь записаны только **подтверждённые планы, не входящие в 2.0.0**; это не обещание текущего поведения.  
В 2.0.0 сначала закрываются текущая генерация шрифтов и цепочка обновления; ниже — только проектные наброски.

## 1. Модульная генерация шрифтов

### Сейчас

За одна генерация выбирается **один шрифт**, и все секции `fonts.ltx` используют его:

- обычные секции размера;
- пользовательские секции в `ui\fonts\`;
- особые секции шрифтов.

Пропускаются только базовые HUD/STAT. Если в секции не хватает глифа, предупреждение выдаётся на весь пакет; заменить шрифт одной секции нельзя.

### План

Сделать «секцию» минимальной единицей конфигурации; на уровне секции **разрешено** менять только:

```text
имя секции / исходная секция fonts.ltx
  ├─ файл шрифта (TTF/TTC/OTF, может отличаться; для TTC можно указать face)
  ├─ wght / насыщенность (вариативный шрифт)
  └─ набор символов: по умолчанию / кириллица / цифры / латиница / свой
```

**Суффикс не является настройкой секции.** Суффикс — это глобальный `font_prefix` в `localization.ltx`, выбирается один раз на пакет; настройка секции не может его менять и не может записывать суффикс в имя texture в `fonts.ltx`.

**Размер, формат и пропуск также не настраиваются на уровне секции**: они остаются глобальными/из эталонного пакета.

По умолчанию остаётся «один глобальный шрифт + стандартный набор символов»; секции без отдельной настройки наследуют глобальные параметры, чтобы результат совпадал с 2.0.0.

### Два обязательных блока интерфейса

1. **Выбор символов**
   - для каждой секции выбирается один набор: **по умолчанию / кириллица / цифры / латиница / свой**;
   - «по умолчанию» = текущий набор 2.0.0;
   - «свой» — диапазоны Unicode или посимвольный список;
   - генерируются только реально выбранные символы; отсутствие глифа сообщается только для этой секции, а не для всего пакета.

2. **Предпросмотр**
   - предпросмотр по секциям, а не только глобального шрифта;
   - можно переключать **шрифт, насыщенность и набор символов** секции;
   - показываются итоговая ссылка `fonts.ltx`, имя texture и размер `.dds` при глобальном размере;
   - предпросмотр и реальная генерация используют один и тот же растеризатор FreeType.

### Ограничения проектирования

- имя секции `fonts.ltx` — **единственный ключ**, имя texture не может быть ключом конфигурации;
- пользовательские/особые секции должны быть настраиваемыми, без предварительного отбора по 256 слотам или CJK;
- при отдельном шрифте для секции журнал генерации должен вестись по секциям (без молчаливого отката);
- очистка старых шрифтов в каталоге вывода должна учитывать фактический набор этой генерации и не удалять чужие секции;
- суффикс/формат/размер остаются глобальными; настройка секции не обходит эти три параметра;
- поддержку отдельных файлов шрифтов в векторном IX-Ray сначала проверить на образцах; в 2.0.0 её нет;
- текущий `--font-weight` превращается в «глобальное значение по умолчанию + переопределение секции».

### Черновик приёмки

- без переопределений секций результат побайтно совпадает с 2.0.0;
- после замены шрифта/набора в одной небазовой секции меняются только её texture/INI;
- на уровне секции меняются только шрифт (включая TTC face)/wght/набор; суффикс и глобальные размер/формат не затрагиваются;
- отсутствие глифа влияет только на предупреждение этой секции;
- изображение предпросмотра и итоговая генерация совпадают по пикселям для соответствующей секции;
- настройки секций сохраняются/загружаются, у CLI есть эквивалентный JSON.

## 2. OGSR / универсальные бинарные патчи движка

### Контекст

В локальном архиве патчей накоплены образцы для OGSR, CryRay/OpenXRay fork, семейства CoC и др.

В архиве уже есть: хэши оригинала/патча, изменения RVA/байтов, установка и откат, проверка на реальной машине, заметки по поиску. Это **источник образцов и критериев** для планов, а не runtime-зависимость 2.0.0.

### План

Сделать помощник, работающий **по семейству/отпечатку версии движка**, а не «универсальный патчер»:

1. определить семейство и версию `xrEngine.exe` / `xrCore.dll` / `xrGame*.dll`;
2. сопоставить известные шаблоны патчей по хэшу/отпечатку инструкций;
3. показать, какие файлы, RVA и значения до/после будут изменены;
4. обязательно сохранить оригинал и сгенерировать скрипт отката;
5. после применения проверить результат (точный файл, хэш, запуск/переносы строк);
6. при несовпадении — явный отказ, без догадок и переноса RVA между версиями.

### Область

- приоритет: **OGSR / IX-Ray / Advanced X-Ray / Open X-Ray**;
- CoC — низкий приоритет;
- глубоко изменённые/редкие ветки — только отдельные патчи, без универсальных обещаний;
- не создавать полную библиотеку образцов и универсальный патчер; только патчи по шаблонам/отпечаткам.

### Граница с 2.0.0

- в 2.0.0 **не добавляется** UI/CLI бинарных патчей;
- в 2.0.0 остаются локальный архив патчей и критерий «ширина знаков — проблема шрифта»;
- помощнику нужны стабильное определение семейства и воспроизводимые образцы, затем отдельный проект.

## 3. Порядок работ

| Проект | 2.0.0 | Далее |
|---|---|---|
| Модульная генерация шрифтов | Нет | Сначала настройки секций + выбор символов + предпросмотр |
| Предпросмотр/выбор символов по секциям | Нет | Вместе с модульностью |
| OGSR/универсальные бинарные патчи | Нет | Сначала архив образцов/определение семейства, затем применение |

Эта страница не меняет критерии приёмки 2.0.0; для 2.0.0 действуют `docs/ru/build-and-release.md` и текущие проверки.
