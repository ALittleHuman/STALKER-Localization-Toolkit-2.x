# 路线图（非 2.0.0 内容）

本页只记录**已明确要做、但不进入 2.0.0** 的规划；不是当前行为承诺。  
2.0.0 先收口现有字库生成与更新链路，以下两项只做设计沉淀。

## 1. 模块化字库生成

### 现状

当前一次生成只选**一个字体**，所有 `ui_font_*` 段共用它：

- `ui_font_arial_21`
- `ui_font_graffiti19_russian`
- `ui_font_electron_18`
- `ui\fonts\` 下的自定义段
- 以及普通 11..25 段

只有 `hud*` / `stat_*` 基础字体跳过。某个段缺字时只能对整包告警，无法为单个段换字体。

### 规划

把「段」作为字库生成的最小配置单位，每个段可以独立指定：

```text
段名 / fonts.ltx 里的原段
  ├─ 字体文件（TTF/TTC/OTF，可不同）
  ├─ face index（TTC 内第几个 face）
  ├─ wght（可变字体）
  ├─ 字号 / 字号偏移
  ├─ 后缀（font_prefix）
  ├─ 字符集 / 选字范围
  ├─ 格式（A8 / 8888 / DXT5，按参照包能力）
  └─ 是否跳过
```

默认仍是「一份全局字体」；没有单独配置的段继承全局设置，保证现有产物与 2.0.0 行为一致。

### 必须加的两块界面

1. **选字**
   - 每个段可选字符集：全部、ASCII、西里尔、CJK 常用、自定义范围/清单；
   - 只生成该段实际要用的字，不再因为别的段缺字而对整包告警；
   - 显示每段「需要 / 可渲染 / 缺字」三个数，缺字只对该段报。

2. **预览**
   - 按段预览，而不是只预览全局字体；
   - 预览要能切字号、wght、格式、字符集；
   - 显示该段最终 `fonts.ltx` 引用、纹理名、`.dds` 尺寸；
   - 预览与真正出包共用同一套 FreeType 栅格口径。

### 设计约束

- `fonts.ltx` 段名是**唯一键**，不能用纹理名当配置键；
- 自定义段/electron 段必须可配置，不能按 256 槽或 CJK 预筛；
- 一个段一个字体时，生成台账必须逐段记账（没有静默回退）；
- 输出目录的旧字库清理要按「本次实际生成集合」做差集，不能误删别的段；
- IX-Ray 矢量路径先只做「逐段字体文件 / size」，TTF 重烘另立项；
- 现有 `--font-weight` 升级为「全局默认 + 段级覆盖」。

### 验收草案

- 不配置段级覆盖时，产物与 2.0.0 逐字节一致；
- 给 `ui_font_graffiti19_russian` 单独换字体后，只有该段纹理/INI 变化；
- 某段缺字只影响该段告警，不再对整包报「字体缺字」；
- 预览图与生成图的对应段逐像素一致；
- 段级配置可保存/加载，CLI 有等价 JSON。

## 2. OGSR / 通用引擎二进制补丁

### 背景

`E:\Software\Games\STALKER\PATCHES` 已积累多份引擎补丁档案：

- NLC-UTF8多字节长度（OGSR 分支）
- Liquidation-CJK自动换行（OGSR x64，源码级）
- IWP-彩色文本不换行（CryRay/OpenXRay fork）
- VESSEL-中文不显示与标点宽度（CoC 系，一次性）

档案里已有：原件/补丁版哈希、RVA/字节改动、安装还原、真机验收、定位笔记。  
这些是路线图的**样本与判据来源**，不是 2.0.0 的运行时依赖。

### 规划

做一个**按引擎家族/版本指纹工作**的补丁助手，而不是「万能补丁器」：

1. 识别目标 `xrEngine.exe` / `xrCore.dll` / `xrGame*.dll` 的家族与版本；
2. 按哈希/指令指纹匹配已知补丁模式；
3. 预览将改哪些文件、哪些 RVA、字节前后值；
4. 强制备份原件，生成还原脚本；
5. 应用后做落地校验（目标路径上的确切文件、哈希、可启动/文本换行验收）；
6. 失败/不匹配必须明确拒绝，不猜、不跨版本搬 RVA。

### 范围

- 优先：**OGSR / IX-Ray / Advanced X-Ray / Open X-Ray**；
- CoC 系低优先；
- 深度魔改或冷门分支：只做专门补丁，不承诺通用；
- 不建全量样本库、不做普适补丁工具；只做按规律/指纹的模式补丁。

### 与 2.0.0 的边界

- 2.0.0 **不加入**二进制补丁 UI/CLI；
- 2.0.0 只保留 `PATCHES` 档案与字库侧「标点宽度是字库问题」的判据；
- 补丁助手需要先有稳定的家族识别和可复现样本，再单独立项。
