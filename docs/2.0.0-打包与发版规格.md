# 2.0.0 打包与发版规格（M3）

> 用户 2026-09-26 交付链："先补 → 我自己审计+测试 → Hana 审计 → 我实测 → **打包给别人测**"。
> 本文是**发版口径**与**打包判据**；包由 `scripts/package.ps1` 产出。

## 1. 包内 / 包外（一句话：只放"跑起来必需"的，别的都不放）

**包内**：
- `xrkit_app.exe`（`build/msvc-shell` 的 Qt6 外壳）；
- **Qt 运行时**：由官方 **`windeployqt`** 铺（`platforms\`、`styles\` 等）——**不手抄 DLL 名单**，避免漏平台插件；
  `tls\` 等联网后端**已退役**，包里不该出现（判据 `check_package_ffmpeg.py` 会红）；
- `plugins\`：**存在但为空**（NLC 解密插件闭源、不随包发布；用户要用自己放进去）；
  ★ 开发版也**不带夹具**（2026-10-27 起；夹具只留在仓库，判据 `check_package_plugin_list.py`）；
- ★ **只自带 `ffmpeg.exe`**（用户 2026-10-05 口径「ffmpeg 等依赖应当自带」；现为**自建 minimal 7.1.5**：
  `--disable-everything` + 显式 enable，不带 GPL，**不出 ffprobe/ffplay**）。
  来源顺序：`XRKIT_FFMPEG_DIR` → `third_party\ffmpeg\` → `deps\ffmpeg\` → 同机 1.x 工具目录；
  找不到就 **`throw`**（不静默跳过 —— 静默跳过＝用户拿到一个视频页不能用的包，而没人知道为什么）。
  版本守卫照 ⑧8.6：**ffmpeg 8.x 拒收**（8.x 的 theora 编码器对 STALKER OGM 有 bug）。
  ★ **不再自带 `ffprobe.exe`**：探测走 `ffmpeg -i` 降级；用户可自备 `bin\ffprobe.exe`
  （判据 `check_package_ffmpeg.py` 断"包内无 ffprobe"）。落点必须是**包根**/`bin\`：
  视频页只认程序目录与 `xrkit_user.ltx` 两处（不搜 PATH）；
- ★ **不带 `download_ffmpeg.py`**（自动安装按钮已退役；判据同 `check_package_ffmpeg.py`）；
- `third_party\ffmpeg\LICENSE.txt`、`BUILD.txt`（版本 + configure 行）——合规件必须随包；
- `README.txt`（安装/回退/插件/自带什么/不含什么）、`version.txt`（版本 + 源提交 + 构建时间）。

**包外（明确不放）**：
- **NLC 解密插件**与任何闭源插件；
- **实验性引擎补丁**（补丁工作线单独走 `PATCHES\` 归档，不进 2.x 发行包）；
- 语料/测试数据/构建中间物、测试夹具（`tests/python_plugins*`、`plugins\_fixtures`）；
- 自检夹具（`xrkit_fake_ffmpeg.exe` 只是构建产物，`package.ps1` 不拷它）。

## 2. 打包判据（不是"看文件齐不齐"，是"从包目录跑得起来"）

`scripts/package.ps1` 的流程（**现状**；2026-09-29 定下产物形态之后没再变过）：

1. **舞台** `build\package_stage`：`xrkit_app.exe` ＋ `windeployqt` 铺出来的 Qt 运行时 ＋
   `ffmpeg.exe` ＋ `plugins\`（空）＋ `README.txt` / `version.txt`；
2. **`platforms\` 同时带 `qwindows.dll` 与 `qoffscreen.dll`，且随包常驻**（用户 2026-10-07 裁决：
   用 109 KB 换"判据＝从产物里真跑一次"）。`version.txt` 里那行
   `platform_plugins=qwindows,qoffscreen` 是**机器可读的声明**，门禁 `pkg-platform` 按它断言。
   ★ 修前那种"验之前才补一份、验完再撤掉"的做法**已作废**：撤掉之后包内 `--smoke` 会直接崩
   `0xC0000409`（ALPHA.57~59 踩过）；
3. **包内自检**：`QT_QPA_PLATFORM=offscreen` 起包里的 `xrkit_app.exe --smoke`，要求结论行
   `SHELL-SMOKE ok checks=N failed=0`；随后按口径断 `PLUGIN-PAGES`（可见页＝**五个内置页**）与
   `plugins\` 顶层为空（**不再有** `_fixtures\` 枚数这一项）；
4. **落位**：`Move-Item` 到 `dist\<主版本>\<标记>\<序号>\` —— **只出目录、不压 zip**；
   历史按序号共存、不删（重建同一序号就覆盖它自己）。

- 实测数字**不写死在这儿**：以门禁收尾 `RESULT:`/`checks=` 与包内自检那行为准（每次发版前重跑）。
- 产物形态与命名的口径来源：用户 2026-09-28/29 ——「构建出来不要使用压缩包的形式，因为我是单人
  开发，压缩包方便分发但不方便测试」「构建成功的不要加时间戳」「历史不删」。
- 踩到的两个坑（脚本注释里也写着）：① `windeployqt` **不铺 offscreen 平台插件**；
  ② 原生程序往 **stderr** 打 Qt 警告时，`$ErrorActionPreference='Stop'` 会把它当终止错误 ⇒
  自检调用临时用 `Continue`，把输出收进日志再挑结论行。

## 3. 安装与回退（写进 README.txt，也写在这里）

- **安装**：整个目录解压到任意位置，双击 `xrkit_app.exe`。
- **回退**：删除该目录即可。本工具**不会自动安装或修改游戏文件**；唯一会**自动**写盘的用户设置是
  **工具自己的 `xrkit_user.ltx`**（主题 / 上次字体 / 手动指定的 ffmpeg），删掉它即恢复默认。
  ★ 游戏的 `user.ltx` **不会被写入**：初次启动只会在「旧文件里有我们写过的键」时**读一次做迁移**
  （`check_user_ltx_identity.py` 断"旧文件逐字节不变"）。
- **⚠ 默认落点（必须写进 README.txt，别写成无条件承诺）**：解包/封包/字库的产物写到
  **用户选择的目录**；但**默认落点是"来源所在目录"**（引擎 `efs::resolve_output_root`：
  来源包在哪个目录，产物就落在哪个目录）—— 直接点开始、没改落点的话，产物会落进
  **来源包所在的游戏/模组目录**。2026-10-05 真发生过"一次默认落点解包把 3.9 万个文件盖在
  模组目录上"的事故。★ 口径（用户 2026-10-04 拍板）：**不改默认落点**、**不弹模态确认框**，
  但**覆盖必须可见**（逐条原因 ＋ 计数）。⇒ 说明书**不许**写成"工具完全不碰"那类绝对句
  （判据 `tests/check_readme_claims.py` 会红），必须按上面这句照实说。
- **失败可见**：插件加载失败**不阻塞启动**，问题会显示在启动后的日志栏里（`plugins\` 目录不存在也不算错）。

## 4. 发版前必做（顺序固定）

1. **`python tests/run_ci.py --release`** —— 抽样档会漏整树缺陷（这一条是 2026-09-27 真机整树跑
   `sqzy_patch` 抓到跨块偏移缺陷后立的规矩）；
2. **`powershell -File scripts/package.ps1`** —— 产出一个**能直接双击跑的目录**：
   `dist\<主版本>\<标记>\<序号>\`（历史按序号共存、不删、不压 zip），
   且包内自检必须过（`SHELL-SMOKE ok checks=N failed=0`）；
3. 把**产物目录里各个文件的 sha256**（或整目录指纹）与**源提交**记进交接区材料（给 HanaAgent 审计与用户实测用）；
4. 交付链剩下的三步（**Hana 审计 → 用户实测 → 外部测试**）没走完之前，**不对外发布**。
