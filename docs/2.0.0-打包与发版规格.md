# 打包与发版规格（当前版）

适用：`2.0.0 BETA.244` 之后。脚本入口与目录结构以仓库当前实现为准。

## 1. 构建层级

```text
build\msvc-release\   CLI / 引擎（不含 Qt）
build\msvc-shell\     GUI
dist\2.0.0\<MARK>\<n>  发布包
```

两套构建并存，用来真实检查 core/engine 不依赖 Qt。

## 2. 入口脚本

```bat
scripts\build.ps1
scripts\package.ps1
scripts\release.ps1 -Index <n> -Version 2.0.0 -Mark BETA
```

`release.ps1` 负责写版本、重编、打包、校验；不要手工改 `version.h` 后跳过脚本。

版本唯一来源：

```text
version.json
version.h
assets\xrkit_winres.rc
```

三者由构建脚本同步；`gen_winres.py --check` 校验 FileVersion/ProductVersion。

## 3. 包内容

正式包是目录形态，至少包含：

```text
xrkit_app.exe
xrkit_cli.exe
xrkit_updater.exe
Qt6 DLL / platforms
python\
tools\
third_party\
LICENSE.txt
```

包内 `plugins\` 顶层默认为空；插件页不是默认产品功能。

## 4. 包内自检

打包脚本从包目录运行：

```bat
set QT_QPA_PLATFORM=offscreen
xrkit_app.exe --smoke
```

要求：

```text
SHELL-SMOKE ok checks=N failed=0
退出码 0
```

失败即拒绝出包。字体选择器交互段当前未覆盖，包内 smoke 会显示 note，不是一个“全绿”的替代。

## 5. 版本与通道

- 正式版：无 `BETA.n`，对应正式 Release；
- 测试版：`BETA.n`，对应 prerelease；
- 包目录名与 CLI 自报版本必须一致；
- 正式版只接受正式 Release，测试版不会推给正式版。

## 6. 更新发布顺序

```text
1. 生成 app.zip
2. 上传 GitHub Release（正式或 prerelease）
3. 验证资产 URL 200 + sha256
4. 客户端用 Release API 发现
```

禁止先发更新清单/先改版本再传资产。当前已无 `app_update.json` 第二清单依赖。

## 7. 发布前检查

```text
本机 SHELL-SMOKE failed=0
包内 SHELL-SMOKE failed=0
golden_text_extract PASS
check_audit_p0_guards PASS
dist 包存在且 CLI 自报版本匹配
```

任何一项未过，不得标记为可发布。

## 8. 历史产物

旧构建保留在 `dist` 仅作追溯，不代表当前行为。清理旧包前先确认最新正式包资产仍可下载。
