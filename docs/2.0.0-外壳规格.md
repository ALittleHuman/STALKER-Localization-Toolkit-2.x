# 2.0.0 外壳规格（M2，第一版：分片与判据）

> **判据来源**：`docs/2.0.0-行为口径对照表.md` 的 **15 组**逐条重验（那是 1.x 代码的实测口径，
> 不是文档漂移版）；性能不低于 PySide6 试点（拖动 12~15 ms/步）。**六页形态原样保留**
> （文件系统 / 编码转换 / 文本提取 / XML 校对 / 视频转换 / 汉化包生成，用户 C1 拍板）。
> 本模块是 1.x 花钱最多的地方（用户原话：滚动条一族"大约有五一到四一的钱"），所以
> **每一片都要先有能在真程序里量的判据**，再写代码。

## 0. 目录与边界

```
src/shell/
  main.cpp            入口（--smoke 自检模式：离屏跑，ASCII 收尾行）
  hub.{h,cpp}         Hub 主窗口（六页切换 + 日志栏 + 菜单）
  theme.{h,cpp}       令牌 → QPalette/QSS 映射（**表在 core，Qt 侧不抄一份**）
  scroll_viewport · split_pane · task_shell · log_box · virtual_list
  pages/              page_base（页框架）· page_factory（下标 → 页）；六个页面各占一片
```

- **数据层不碰 Qt**（1.x 的约束）：颜色/字体/`px()`/`user.ltx` 在 `core/theme.{h,cpp}`，
  令牌表由 `tools/gen_theme_tables.py` 从 1.x `toolkit_theme.py` **按 AST** 生成
  （`--check` 已进门禁 [13]）——因为 `import toolkit_theme` 会拖进 `tkinter`，
  1.x 自己的 Qt 试点也是按 AST 读这份真值。
- 外壳只依赖 `xrkit_core` / `xrkit_engine`；`core`/`engine` 仍**不许 include Qt**（J5 锁）。

## 1. M2-0 主题数据层 —— **已完成**

`core/theme.{h,cpp}` + `--themecheck`（门禁 [5] 的真检查，83 项）：

- 18 个颜色角色 × 暗/亮两套（`#RRGGBB` 校验、两套角色集必须齐）、6 个字体角色、`_BG_ROLES`；
- `px()`：96 DPI 基准值 × 缩放（1.0/1.5/2.0 → 24/36/48），**按 96 DPI 定的像素都必须过它**，
  否则 150% 屏上正文行高变大而写死的行高不变 → 文字被裁；
- 模式切换只改一个值（外壳那边要"**原地更新**"，1.x 明文写着：重新绑定会让切主题静默失效）；
- `user.ltx`：`[section]` + `key = value`，**读→改一项→整体写回、保留其它段**，
  无法识别的行（注释/垃圾）跳过而不丢整个文件；写盘按文本模式语义（每个 `\n` → `\r\n`）；
  路径 = **exe 所在目录**（1.x `app_dir()/user.ltx`）。

## 3. M2-6a 页框架 —— **已完成**

六页不是"各写各的一套壳"，而是**同一份框架 + 各自的 body**。框架把 ⑤ 的三条口径
和规则 2（操作栏先放且贴底）收在一处，页面实现文件里**连视口都不许造**：

- `PageBase` 负责：标题 → 视口(`fit=content`, `minsize_y=page_min_h()`) → 贴底操作栏；
  自检量的就是这个层次关系（body 必须在视口里、操作栏必须在视口外）。
- `page_min_h()` 是**函数**（`core::px(430)`）。自检改三次缩放（1.0/1.5/2.0）看它是否
  跟着变（430/645/860）—— 常量会三组全返回 430，当场露馅。
- 静态锁两条：`pages/` 里不许自己造视口（只能 `PageBase` 造）；`px(430)` 只许出现在
  `page_base.cpp`。两条锁都过 `active_code()`（滤掉整行注释），并且**锁自己有自证样本**
  —— 太松会被一句注释绕过，太紧会把注释当违规（注释里正是这几条口径的出处）。
- "压到 `page_min_h()` 时操作栏还在"必须在**裸 Toplevel** 上量：Hub 式布局
  （页列表 + 页栈 + 竖分栏）永远压不矮，挂上去量等于没量（M2-2 踩过同一个坑）。

## 4. M2-6b1 文件系统页·引擎侧 —— **已完成**

"导出到磁盘"这一件事**整条**放在引擎里（`fs::extract_tree`），页面只传参和显示。
理由是 6.7：归档条目名是不可信输入，而落盘就是**任意文件写** —— 判据必须和"写文件"
待在同一个函数里，中间不给人留缝。逐条照 1.x `stalker_fs.py` 的代码（不是文档）：

- 6.7 五条拒因按 1.x 的**顺序**实现（空 → 绝对/UNC → 盘符 → `..` → 复核兜底），
  并且**连拒因文字一起断言**：改顺序、删一条都会红。注意 `a//b`、`a/./b` 在 1.x 里
  是**合法**的（拆段时丢空段与 `.`），拒的只有真正的 `..` —— 照代码才知道这件事。
- 6.10 是 1.x 的真缺陷：`if not files:` 同时覆盖 `None` 与 `[]`，于是"什么都没勾"
  会退化成**整镜像导出**、还被记成成功。2.0 把"全部 / 列出的清单"做成两个显式状态，
  空清单直接拒绝并说明理由（合成夹具专门证这一条）。
- 6.8 空文件**写出 0 字节文件**（1.x 旧代码 `rc == 0 and r.stdout` 把空文件当"解不出来"）。
  `nlc-sq-levels` 的真机树里正好有 0 字节条目，基线里记着它。
- 6.9 原子写：同目录 `.part` → **读回逐字节复核** → 同盘 rename；任一环失败先 unlink，
  绝不留"看起来存在"的坏文件。对拍时额外扫一遍 `*.part` 残留。
- 6.14 失败原因随返回值走（`ExtractTreeResult::error` / `failures`），没有模块级全局 ——
  1.x 的 `sqfs_last_error` 会被并发任务互相覆盖。

判据落点：自检 42 项（路径判据纯逻辑，不需要夹具）+ 门禁 [8] 的真机整树对拍
（7 镜像 × 6 项，与 1.x 的 `sqfs_extract` 一次导出结果逐项比）+ 合成夹具 4 组
（空文件 / 空清单 / 只选目录 / 选了不存在的条目）。

## 5. M2-6b2 文件系统页·界面与状态 —— **已完成**

界面形态那几条也全部落在**无 Qt 的模型**（`engine::fs` 的 `overlay`）上，页面
（`pages/fs_page`）只负责画和转发。理由是 M2 的通用教训：**能建模成数据的判断，
不要放进控件回调里** —— 放进去就只能靠点界面验，而点界面不在门禁里。

- 6.1/6.2 `MergeTree`：加载序按 `basename().lower()` 稳定升序；合并**后者为准**，
  同名项的 `source_index` 随之切到"引擎实际会读到的那一份"；**勾选态跟随原节点**
  （用户勾过的不能因为重建树而丢）；两边都是目录才递归，类型变化（文件↔目录）
  整个换掉且算一次替换。原先（1.x 早期）是 first-wins，`sqzy_patch` 里的同名文件
  永远输给 `sq_base` —— 那是错的。
- 6.3 `FsSelection` 与树里的 `checked` 是**两个对象**，页面上就是**两个不同的按钮**
  （「全选包」改前者、「包内全选」改后者）。自检交叉断言：点了这个，另一个不许动。
- 6.13 下拉的 `data()` 是内部键、显示名只用于展示；判据是**显示名解析不出格式**
  （1.x 存显示名 ⇒ `ALL_FMTS.get(fmt)` 必然取不到 ⇒ SquashFS 被静默按 xdb 打包）。
- 6.11 页面里 `extract_tree(` **恰好一处**（门禁静态锁），选中集与批量因此不可能分叉；
  自检再证两条调用"同样失败、同样的话"。
- 6.12 `collect_tree` 让目录条目**如实**带 `is_dir`，并做端到端回读：带目录的条目
  交给 `pack_db` 再解回来，目录条目数必须一致 —— 这就是"引擎的 `DIRTYPE` 分支
  真的可达"的判据（1.x 在 App 侧把 `is_dir` 写死 False，那条分支永不触发）。
- 6.4 页里**没有** `drop_zone` 控件，拖放直接挂在包列表上（`acceptDrops`）。

**6.5 如实标注为待夹具**："lzo 压缩的镜像取大小失败时列表仍可用、`size_real` 全 0、
错误可见"需要一份 lzo 镜像；手头语料里没有，而 2.0 的 writer 只出 xz。
按判据纪律，这条**不写成"已完成"**：等有 lzo 参照镜像再补（届时作为门禁 [8] 的一组夹具）。

## 6. M2-6c 编码转换页 —— **已完成**（c1 判据面 + c2 界面/写出）

⑨ 的判据面（c1）与"把结果画出来"（c2）分开落地，中间用一条**结构约束**连接：
定案步骤标签只能由引擎给。

- 9.7 的原话是"1.x 的日志标签是 convert_app **复算**的（只查有没有声明、不校验字节证实）
  ⇒ 与判定可不一致"。2.0 的修法不是"再算准一点"，而是**取消页面复算这件事**：
  引擎发一个步号，`sniff_result_label` 出一行 `多字节(utf-8)`，页面只搬运。
  静态锁按**构造形态**拦（活代码里不许出现 `多字节(` / `指定(` / `声明(` / `统计(`）——
  页面可以解释链条，但不许把结论拼出来。
- 写出路径照 1.x `convert_file` 的代码：入口剥 BOM 但**剥掉不等于忘掉**；
  解码/编码都用 `errors="replace"`；`.xml` 走 `_fix_xml_decl`（只替换**已存在**的
  encoding 属性、只处理第一条声明）；`_needs_rewrite` 的窗口是 `raw[:400]`；
  源==目标时走**对齐分支**（不是简单地不写）。
- `errors="replace"` 的语义是**逐字节等于 Python** 的，不是"看着像"：
  新对拍 114 例（UTF-8 截断/越界/代理区/过长编码、单字节全排、GB 家族两字节/四字节/
  截断/空洞、编码方向的 `?`）折进了门禁 [12]。实测出来的三条规则写在
  `encoding.cpp` 的注释里（尤其"末尾截断吃已经吃过的那些字节"与
  "gbk/gb2312 只有两字节路径且各用各的表"）。
- 顺手做的一次小重构：原子写从 `fs/extract_tree.cpp` 提到 `core::write_file_atomic`
  —— 解包与转换共用同一条纪律；安全关键的东西写两份，一定会有一份先腐坏。
- 页面能力：源路径/输出目录（既有控件上收拖放）、编码下拉（**只列对拍过的编码**）、
  逐文件表（定案步骤 + 是否已跳过）、任务壳管进度、**暂停状态机归 App**（⑬13.6）。

## 10. 最容易漏的几条（照对照表 §2.0 的"10 条"抄下来，写代码前先看）

> **2.7 成本口径的如实说明**：自动门禁里量到的"拖动一步（含重绘）"是 **离屏（offscreen）下的
> 下界**（实测 0.01~0.02 ms/步），**不能**拿它声称"比 PySide6 试点（12~15 ms/步）快 1000 倍" ——
> 离屏没有真实合成器与窗口重绘。真实窗口下的成本必须在有显示器的机器上量，作为**人工验收项**
> 记在这里：**待测**。门禁只保证"离屏下每步 < 30 ms"这条宽松上界（防回归数量级）。
1. **"没有滚动条就不许滚"是三层闸门**：`bar_shown` 四看 + 控件级 `guard_wheel` + `wheel_claim`(serial)。
   Qt 里**别依赖默认 wheel 处理**（`QAbstractScrollArea` 的默认行为会绕过我们的条子）。
2. **布局顺序决定生死**：竖条(右) → 横条(底) → 被滚控件(expand)；操作栏先放且贴底。
3. **`fit` 规则**：body 装弹性内容（自带条子的树）→ `viewport`；静态内容 → `content`。
4. 拖动分隔条：**松手才重排**，但拖动中预览块要**填充背景**（不是一条线）。
5. 明细列表虚拟化：`+2` 行 overscan，无硬编码上限。
6. 主题：`T` 原地更新；`user.ltx` 不许整文件重写（AST 锁：主题模块里不得出现整写）。
7. 日志栏**不归**主窗口滚动条管；一次只有一个滚动条能动。

### ★ 2026-10-06：`SplitPane` 的分栏判据**改写**（审计 3-8；二选一里选的那条及理由）

**事实**：全仓 grep `SplitPane` 只有三处 —— `split_pane.{h,cpp}` 自己、`src/shell/hub.h`
一个**没人用的前向声明**、以及 `src/shell/smoke.cpp`（自检夹具）。**产品路径零实例化**：
FS 页的分栏用的是 `QSplitter`（`fs_page.cpp` 的 `new QSplitter(Qt::Horizontal)`）。

**原来的毛病**：本表上面那行原来把"拖动中预览框有填色 / 松手一次重排 / 边界不被 clamp"
写成验收判据，而那些行为**只存在于产品不用的 `SplitPane` 里**（自检在跑它、
`smoke.cpp` 甚至拿它当几何夹具）—— 也就是"**判据测的是死代码**"：用户拖产品里那条
分隔条，验收表里那三句话一条都不适用。

**二选一，选的是"改写规格判据"，理由**：
1. **用户的真实诉求是观感**（原话：「松手一次重排。但是拖拽的时候预览框不能只是一条线，
   而是要把那部分相应的背景也进行填充」）—— 而产品那条 `QSplitter` 的 sash **已经是
   主题刷出来的填充色带**（`src/shell/theme.cpp` 的 `QSplitter::handle { background: … }`），

2. 让 FS 页改用 `SplitPane` 要把它接进 `PageBase` 的整组装配（工具行/卡片/最小高都在
