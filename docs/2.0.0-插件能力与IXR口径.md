## 一、插件定位（已拍板）

| 问题 | 裁决 |
|---|---|
| C++ 插件 ABI | **不恢复**（决策 1 继续有效：`stk_api` / `LoadLibrary` 插件路径已退净） |
| 上 PySide6（任意 Qt 控件） | **不上**（+200 MB、LGPL、门面不再是唯一入口，现有判据要重写） |
| 恢复 Tkinter（1.x 原样） | **不做**（Tk 控件嵌不进 Qt 页面，两张皮） |
| **走哪条** | **纯补门面**：只加插件门面方法，不碰 ABI、不换 UI 栈 |

**"天花板"的实证**：1.1.0 的第三方插件 `plugins\ai_translate.py`（162.9 KB，AI 离线翻译：模型下载/断点续传/子进程 llama-server/术语表/XML·ltx·script 翻译）**只用标准库 + 16 个 `api.ui` 方法**。

⇒ 2.0 现有 189 个绑定**已覆盖并超出**这 16 个 ⇒ **"1.x 能做的插件，2.x 都做得出来"**。

## 二、门面补强顺序（已定）

| 阶段 | 补什么 | 为什么 |
|---|---|---|
| **P2（最急）** | `set_visible` / `destroy` / `timer` | 修前门面**连 hide 都没有**：做不了条件显隐、动态删控件、UI 线程定时刷新 |
| **P3** | `image` / `dialog` / `set_style` | 图形预览（IXR 必需）、自建对话框、视觉分组 |
| **P4（可选）** | `on_event`（click/key）/ `canvas` | 交互与自绘；到这一步才谈得上"画自己的控件" |

三条硬边界（**改不了**，除非换 UI 栈）：
1. 不能造**新控件类型**（只能把已有的拼成复合控件）；
2. 不能**自绘**（没有 QPainter，除非 P4 canvas）；
3. 不能**子类化/改行为**（没有事件模型）。

**复杂度分层**：L1 布局（已有）／L2 数据（tree/list/log/progress，已有）／L3 交互与表现（P2 起补）——L3 补齐后，插件页才能"行为上"追平内置页。

## 三、IX-Ray（必须施工）

**旧交接里"IX-Ray 规划中、禁止施工"是旧会话 AI 自写、非用户口径** —— 2026-10-26 用户明确更正：**必须施工**。

路线（用户原话）：

1. 先把本工具做稳定；
2. 稳定后把 IX-Ray 生成**做成插件**（插件层独立迭代、判据可覆盖）；
3. 插件稳定后**合并**进产品。
   ★ 理由："这样很多地方都能测试一遍"——生成器会顺带压到文本/字库/XML/打包各条链。

**现状（2026-10-26 实测）**：

| 规划（328 行） | `E:\Software\Tools\Transition\HanaAgent\01_新增\STALKER工具集\IXR\plans\12_规划_语言包识别与分部位字体.md` | §十一 是 2026-10-25 的实现核对；`14_IX-Ray生成工具审计` 的行号/结论**已过时** |

| 2.x 侧 | — | **未接**：`fontpack_page` 单字体、写死 `eng/rus/chs`、无扫描/识别/逐槽位 |

**目标形态**（"指定"模式，默认档）：用户给一个**能当模组打的整包**（例：`MODS\~NotoSansSC`、`~HPSimplifiedHans-*`），工具：

1. **识别**四档（SoC/ClS/CoP/IX-Ray）—— 有 `fonts/<lang>/*.ttf` + `fonts.ltx` 的 `name` ⇒ IX-Ray；只有 dds ⇒ 位图三档；
2. **分区（逐槽位）选字体** —— 分区字体＝**汉化包生成的高级功能**（10 档字号槽位勾选），不是独立插件面板；
3. 生成时**以参照包为基底**：替换字体与文本，**其余文件逐字节保留**；
4. 输出仍是"能当模组打的整包"。

**技术选型**：TTF 合并用 **fonttools**（纯 Python，随插件/外部助手带；C++ 自写 glyf 合并会丢 CFF/变体/TTC，且要自己写 15 张表）。
2.x 侧**主体 C++**（扫描/识别/计划/ltx 改写），fonttools 只做"合并"这一步的外部工具。
