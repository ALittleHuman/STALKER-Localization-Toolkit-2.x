# 限制与注意事项

本页只列当前版本的用户可见限制与规避办法。

## 1. 路径与编码

- CLI 与 GUI（含构建器/插件管理器/更新器）都已声明 `activeCodePage=UTF-8` + `longPathAware`；
- 中文/西里尔路径的读取、打包、列举已实测通过；
- 超过 260 字符仍受 Windows `EnableLongPaths` 系统开关限制；超限会点名路径，不静默跳过。

## 2. 封包（LZHUF）

- 极难压缩的数据可能触发编码失败（“头长度为 0”）；
- 封包后会自动回读自检：解析不了或条目数不符直接报错；
- 仍建议对重要包跑 `xrkit_cli --dump <包>` 复核。

## 3. 文本提取

- GUI 在「文本工具」页选「提取文本」；CLI 是 `--extract-text`，共用引擎实现；CLI 的源可以是 scripts/gameplay 本身，也可以是游戏根/addons 根（自动找子树、保留相对树；文本表落 `gamedata/configs/text/<lang>/`，跨表 ID 不重名）；
- 含 `--` 的脚本文本可能被注释剥离逻辑跳过，计入 `notext`，不报错；
- 脚本全局替换不区分注释里的同名字面量，注释也可能被改写。

## 4. 插件

- API 实验性；`PLUGIN_API=2`（1 兼容），不是二进制 ABI；
- 支持顶层 `.py` 与 `<name>/plugin.py` / `__init__.py`；目录插件按包加载；
- 跨插件 import 必须声明 `PLUGIN_INFO.depends`，运行时回调里禁止，用 `api.services.call`；
- 守卫不是沙箱：同进程仍可读文件、`ctypes` 加载 DLL；
- 插件可联网、用 sqlite3；「工具 → 联网功能」不强制约束插件；
- 同进程：崩溃/import 副作用会影响宿主；UI 主线程 30 秒无心跳会写 `logs/ui_watchdog.log` 并退出进程（fail-fast，不热恢复）；长活放 `task_run` worker；
- 官方发行包 `plugins\` 顶层为空；第三方插件的兼容性由插件作者保证。

## 5. 视频转换

- ffmpeg 只认两处：`xrkit_user.ltx` 的 `[ffmpeg] path/probe`，或程序目录/`bin`；不搜 PATH；
- 只接受 7.x；8.x 的 theora 对 STALKER OGM 有 bug；
- 发行包不带 ffprobe；缺时自动用 `ffmpeg -i` 降级；
- 输出 == 源/参考直接拒绝；输出已存在问一次。

## 6. 规划中的边界

模块化字库（逐段字体/选字/预览）和 OGSR 等引擎二进制补丁**不属于 2.0.0**；设计草案见 `路线图.md`。2.0.0 的现有单字体生成与告警仍是当前行为。

## 7. 编码转换

- 单文件 + 原地 + 勾备份时备份路径会退化，建议填输出目录或手动备份；
- 输出目录 == 源目录按原地覆盖处理且不备份；
- 自动判定不确定会弹确认框；答否跳过。

## 8. 汉化包生成

- 扫描与生成两步：游戏版本由参照包判定（`config`⇒SoC；`configs`+8888⇒ClS；+A8⇒CoP；只有 TTF⇒IXR）；
- 位图-from-ref 保留全部段；纹理名非标准时按段名编号生成纹理名并改写引用；
- 所有字体段都参与生成，包括自定义段；只有基础 HUD/STAT 字体跳过；
- `--suffix` 是 `localization.ltx` 的 `font_prefix`，不写进 `fonts.ltx`；
- 可变字体按 `wght` 轴实例化；页面有字重下拉与预览。静态字体忽略字重；`--font-weight` 支持 100–900。IX-Ray 矢量路径不按 wght 重烘，选项会禁用。
- 单张图集最多 8192；50px/大字集硬扩到 8192×4096，超过就失败，不做多页/自动降字号；
- IX-Ray 矢量包写 `engine_external.ltx` 的 `FontAtlasSize=8192`；
- NBSP 不再被误报为可裁剪空白；
- 缺字默认只警告，严格失败用 `--on-missing fail`；
- 输出目录不要直接指游戏根；成功会覆盖 `gamedata` 下同名文件；
- 重新生成同目录会清理上次生成、这次没再生成的字库（`stale_removed=`）；
- 位图 `字号+N` 与 IX-Ray `--font-size-patch` 是两套机制。

## 9. 更新与下载

- 正式版只查正式 Release；BETA/RC 必须发 Prerelease；
- 一个 Release 多 zip 时按版本 build 选资产并配对 digest；
- 更新包下载统一走 `DownloadManager`：`.part.N` + `.segments`，支持取消/续传；
- 下载中可点「取消下载」；取消后保留分片；关闭窗口也会取消；
- 下载完成询问重启；选否下次启动安装；
- npm 是可选通道：模型 C 版本会转成 `x.y.z-<build>` 发布；BETA.269 已上传 npm，BETA.270 暂未发布，客户端回退 GitHub；
- 「工具 → 启用检测更新」/「工具 → 联网功能」/`--no-auto-update` 可关闭相关行为。

## 10. smoke 与门禁

- `xrkit_smoke.exe` 独立存在，发布包不带；
- `--smoke` 不是本体/CLI 动作；
- smoke 会读写真实 `xrkit_user.ltx`（有备份/还原），跑前备份；
- 部分门禁需要仓库外 1.x 源码；缺件记 SKIP，release 档算 FAIL；
- 手工构建必须设置 `XRKIT_PYTHON`。

## 11. 反馈

附 `logs\log_*.txt`、操作步骤、输入样本类型、输出目录；封包/解包异常附 `xrkit_cli --dump` 结果。
