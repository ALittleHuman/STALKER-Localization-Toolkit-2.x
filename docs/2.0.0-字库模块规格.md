## 2. 只有两处"技术难点"

### 2.1 栅格一致 —— **已验证可行（2026-09-24）**

探针 `tests/golden_font_raster.py`（门禁第 [17] 步）：`msyh.ttf` 的 58 个样本字符 × 字号
11/13/15/17，我们的 FreeType 栅格与 Pillow `getmask(mode="L")` **逐字节一致**。

- FreeType 调用：`FT_Set_Pixel_Sizes(face, 0, size)` + `FT_Load_Glyph(FT_LOAD_DEFAULT)`
  + `FT_Render_Glyph(FT_RENDER_MODE_NORMAL)`（= Pillow 的默认路径）；
- `mask.getbbox()` **会裁掉首尾全零的行/列**；
- 边界实测：'你' 的 FreeType 位图末行全零，Pillow 的 `getbbox()` 因此少一行 ——
  这是 bbox 语义，不是像素差异（逐字节比位图本身就一致）。

### 2.1.1 mask 画布口径 —— ★ **旧结论是错的，以本节为准**（2026-09-24 二次实测）

第一版探针只在**槽位字号** 11/13/15/17 上验过，得出"宽 = advance 像素、
高 = `max(墨迹行数, bitmap_top)`、墨迹贴 `(bitmap_left, 0)`"—— 那个结论在**定标字号**
（11→16、13→17、15→18、16→21、17→22、18→24、20→26、25→31）上**不成立**：
实测产物里 '&' 少一列、'j' 偏 2 列、'_' 偏 2 行，**整张 3428 字的图集有 15.9 万像素对不上**。
（槽位字号上碰巧成立，是因为那批样本的 `font.getbbox` 恰好等于 advance 宽、y0 恰好等于
`ascent − bitmap_top`。）

Pillow 的 `getmask` 画布是 `font.getbbox` 给出的**布局盒**，逐字实测（61 字符 × 8 个定标字号
全部成立）：

```
设 w = 位图宽, rows = 位图行数, left = bitmap_left, top = bitmap_top, asc = ascent 像素
    adv = advance 像素（= advance_26_6 >> 6；实测 4 字体 × 5 字号下 advance 恒为整像素）

bbox = ( min(0, left),                              # x0：墨迹可以探到笔位左边
         asc − max(0, top),                         # y0：**夹在 ascent 线上**（top<0 时不再上探）
         max(adv, left + w),                        # x1：布局宽与墨迹右沿取大
         max(asc, asc − top + rows) )               # y1：行带底与墨迹下沿取大

画布 = (x1 − x0) × (y1 − y0)，墨迹贴 (left − x0, (asc − top) − y0)
mb   = 画布的非零紧致 bbox（首尾全零行列都裁）
```

三条要点：

- `top = bbox[1] // S + vshift`（§1 第 7 步）里的 **y0 必须夹在 ascent 线上**：`_`（下划线）
  的 `bitmap_top = −2`，不夹的话整个字会**低 2px**（实测：我们是第 39 行、原版/1.x 是第 37 行）。
- `left0 = mb[0] // S` 仍然是**紧致 bbox** 的首列（不是 `bbox[0]`）：'j' 的 `bbox[0] = −2`
  而 `mb[0] = 0`（画布左移了 2 列把负左沿装进去）。
- Pillow 的 `getbbox` 的 y1（`bbox[3]`）与墨迹无关（`“` 的 y1 是行带底、不是墨迹底），
  1.x 只用到 x0/y0 → 我们只复刻盒的**左上角与尺寸**，但尺寸必须对，否则画布裁墨。

### 2.2 Pillow 的 LANCZOS（x2 档 16/17/18）—— **已复刻，逐字节一致**

只在 `S=2` 时触发（`glyph.resize((gw,gh), Image.LANCZOS)`）。实现见
`include/xrkit/engine/font/resample.h` + `src/engine/font/resample.cpp`，
**逐句照抄** `Pillow-12.3.0/src/libImaging/Resample.c` 的 8bpc 单通道路径：

- `precompute_coeffs`：`scale = (in1−in0)/outSize`、`filterscale = max(scale,1)`、
  `support = 3*filterscale`（LANCZOS）、`ksize = ceil(support)*2+1`；
  `center = in0 + (xx+0.5)*scale`、`xmin = (int)(center−support+0.5)`（**向零截断**，不是 floor）、
  `xmax = min((int)(center+support+0.5), inSize)`；系数按
  `lanczos((x+xmin−center+0.5)/filterscale)` 算完再除以和；
- `normalize_coeffs_8bpc`：定点 `PRECISION_BITS = 32−8−2 = 22`，
  正数 `(int)(0.5 + v*2^22)`、负数 `(int)(−0.5 + v*2^22)`；
- 累加：`ss = 1<<21` 起头逐项加 `像素*系数`（`int32`），最后 `clip8(ss >> 22)` 夹到 0..255
  （等价于 Pillow 那张 −640..639 的查表）；
- 两趟顺序 **先横后竖**；横向那趟只处理源图 `[ybox_first, ybox_last)` 行，竖向的 bounds
  相应左移 `ybox_first`；`box` 恒为 `(0, 0, 源宽, 源高)`。

**孤立对拍**（门禁 [20]，`tests/golden_font_resample.py`）：86 个用例（整数倍降采样、
非整数缩放、放大、退化尺寸、全零/全满/渐变/条纹/随机噪声）与 `PIL.Image.resize(LANCZOS)`
**逐字节一致**。另有两处 x2 专有的除 S：`top = bbox[1]//S + vshift`（漏掉 `/S` 会整体低
7–13px，长字被"上移补偿"救回、短字就错位 —— 这类 bug 只有逐字节对拍才抓得住）。

另外两处 Python/C++ 语义坑（都已按 Python 口径实现）：
- `//` 是**向下取整**、C++ `/` 是向零截断：`bbox[1]//S`、`(asc+desc)//S` 在负数上会差 1
  ⇒ 统一走 `floor_div`；
- Pillow 的 `round()` 是**四舍六入五成双** ⇒ 用 `std::nearbyint`（默认舍入模式同口径）。

### 4.1 几何层对拍方式（门禁 [18]，`tests/golden_font_metrics.py`）

C++ 侧 `xrkit_cli --font-metrics <out.bin>` 把全部查询按固定扫描顺序导出（5.3 MB），
Python 侧**用 1.x 的 `font_pack` 逐条重算**当裁判：

- `is_block_char`（EAW∈{W,F} ∪ FORCED_FULLWIDTH）**全码位空间** 1 114 112 条；
- `punct_class` / `rect_w_for` 各 10 档 × 全 BMP = 655 360 条；
- `st_fallback` 全 BMP 65 536 条；`cell_height_for` 1..64；
- **框宽裁决全流程** 20 000 例 —— 用例的**输入由 C++ 侧生成、连输入一起写进 dump**，
  Python 只做"按 1.x 的函数重算"，⇒ 两端没有第二份需要同步的用例表。

导入 1.x 的 `font_pack` 要**按文件路径**装载（`importlib`）：`font_pack/` 是没有
`__init__.py` 的目录、里面才叫 `font_pack.py`，`import font_pack` 会先命中同名命名空间包。

### 4.2 渲染产物对拍方式（门禁 [19]，`tests/golden_font_render.py`）

`xrkit_cli --font-render <字体> <字号> <x2> <8888|A8> <字符集文件> <输出前缀>` 写
`<前缀>.dds` + `<前缀>.ini`；字符集文件 = **每行一个十六进制码位**（顺序即槽位顺序），
两端拿同一个文件 ⇒ 没有"文本里有没有尾换行"这种含糊口径。基准由 1.x 的
`render_font` + `write_dds` 现场生成（ini 由 Python 文本模式落盘 ⇒ CRLF），逐字节比。

用例：小字符集（387 字：`REQUIRED_CHARS` + 定标样本 + 四类标点 + 表值 0/1px 的边界码位 +
私用区 `.notdef`）× 字号 11/13/15（S=1）与 16/17/18（x2）× 格式 8888/A8，外加**原版成品
字符集 3428 字**（压大画布路径 1024→2048；S=1 的 11 与 x2 的 16 各一例）。**14/14 逐字节一致**。

### 4.3 与**原版工具**成品的交叉检查（第三方证据，2026-09-24 实测）

拿原版 `汉化包生成工具2024` 的 `ui_font_{11,13,15}_chs.{dds,ini}` 当参照（同一批 3428 个码位
当输入，`msyh.ttf`、A8）：

- **几何（ini）**：行数、`height=`、每行 `x1,y1` **完全一致**；3430 行里有 35/42/63 行不同，
  全部落在两类：
  1. **标点收窄**（`。，、；：！？（）“”…—·°《》–` 等 17 类）：1.x 有意收窄（`punct_box_px`），
     原版给**整块宽**（17/18/19）。这是 1.x 的**有意改进**（用户报过"标点两侧空档"），
     2.x 按判据复刻 1.x，**记为有意分歧**；
  2. **控制字符与私用区**（`U+0000..U+001F`、`U+007F`、`U+E07F/E0DD/E1A7/E13B/E7AE` 等）：
     原版给 0 或整块宽，1.x 按字体 advance 现算。同样按 1.x 复刻。
  另有零星普通字（`U+2022 •`、`U+00B0 °`、`U+03B2 β`、`U+0440 р` 等）宽差 1px —— 原版的
  宽度裁决与 1.x 不是同一套，属同一类台账。
- **DDS 头**：原版 `flags = 0x00081007`（含 `DDSD_LINEARSIZE`），1.x `0x00001007`。
  两者都是合法 DDS 头；**按判据取 1.x**，记台账。
- **DDS 像素**：相差 28%/25%/37%（3426/3428 个槽位都动），且不是位移差 —— 同一字号下
  原版的笔形就不同（例：`中` 的横是 `-@-`/`#####` 而 Pillow 是 `**`/`@@@@@`），
  整体还高 1px。⇒ **原版成品的像素不是本工具的复刻对象**（它自带字体与渲染栈不同）；
  要复刻它得先取到原版工具的字体与栅格器。判据仍是"与 1.x 逐字节一致"（已达成）。

### 4.4 出包端到端（门禁 [22]，`tests/golden_font_package.py`）

`xrkit_cli --build-font-pack <SoC|ClS|CoP> <语言> <xml目录> <字体> <输出目录> [--suffix s] [--offset n] [--no-full-cyrillic]`
→ 整棵 `gamedata/`：10 个字号（**S=1 与 x2 都在内**）× `.dds`/`.ini`、
`config(s)/text/<lang>/*.xml`（无 BOM UTF-8 + 第一条声明的 encoding 改 utf-8）、
`config(s)/fonts.ltx`、`config(s)/localization.ltx`（`_#LANG#`→后缀、`#LANG#`→语言）。

三套游戏版本各跑一遍（顺带验 `GAMES` 的目录名 `config`/`configs` 与 DDS 格式 `8888`/`A8`）：
语料 7 个 XML（真语料 + 声明 utf-8/gb2312/windows-1251 + 无声明 1251 + 无声明 UTF-8 + 带 BOM），
**每个版本 29 个文件逐字节一致**。另加**字体守卫**用例：拿没有中日韩字形的字体
（`tahoma.ttf`）出包，两边都必须拒绝、且都**不留半成品 `gamedata`**（1.x 的守卫跑在建目录之前）。

> 逐字节一致的两个细节（都踩过）：
> · `.ini`/`.ltx` 用 Python **文本模式**写（`\n` → `\r\n`，**每一个** `\n` 都翻）；
>   而 XML 用 `newline=""`（**不**翻译）—— 两者不一样，写反了产物长度就不对。
> · 生成的 C++ 字面量里，**源码折行不等于数据换行**：换行必须写成 `\n` 转义。
>   第一版把模板换行当成折行 ⇒ `fonts.ltx` 丢 77 个换行（1569 B → 1415 B）；
>   反过来第一版又给每个折行补了 `\n` ⇒ 字符集凭空多出 U+000A。两个错都被门禁当场抓住。

## 5. 风险与报账口径（R2）

- 若栅格或 LANCZOS 最终仍有像素差：**先按几何判据（11 组）全部达标**，再把差异
  （位置 × 判据 × 实测值 × 成因）逐条列出交用户裁决；**绝不在判据上偷偷放宽**。
- `S=1` 档先出结果（无重采样），能把"栅格一致性"单独验证干净；x2 档单独排期。
- 与 1.x 的**有意分歧**目前两条（§4.3 的标点收窄、DDS 头 flags）—— 都记在本文档，
  不当"实现 bug"处理；若用户要改成对齐原版，改的是 1.x 的口径而不是我们的实现。
