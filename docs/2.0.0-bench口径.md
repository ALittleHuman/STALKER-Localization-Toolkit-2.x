# 2.0.0 `--bench` 口径（2026-09-27 定）

> 目的：**防数量级回归**，不是性能承诺。离屏/合成环境量到的数字只是**下界**（本项目既有纪律），
> 所以门禁只守一条**很宽松的上界**，真实成本仍以人工验收为准。

## 量什么（三条真实 I/O 路径，各打印一行机器可读的 `BENCH`）

| 指标 | 做法 | 单位 |
|---|---|---|
| `dump_ms` | 对**真机镜像**跑 `xrkit_cli --dump`（元数据直读，不解压数据块） | 毫秒 + 条目数 |
| `extract_mbps` | 从同一镜像抽 **16 个普通文件**（走 `--extract`），按字节数/耗时 | MB/s |
| `text_decode_ms` | 对真语料里的文本文件跑 `--decode-text` | 毫秒 |

## 判据（门禁第 28 步，宽松到"只抓数量级"）

- `dump_ms < 60000`（真机 2 GB 级镜像的元数据列举；实测在秒级，留两个数量级余量）；
- `extract_mbps > 1`（真机镜像抽取；实测数十 MB/s 级）；
- `text_decode_ms < 20000`；
- 样本缺失 ⇒ 退 2（进"本次未覆盖"），**不许混进通过**。

## 为什么不在 C++ 里做

三条路径都已有稳定的 CLI 动作；在**测试侧**计时（`time.perf_counter`）不需要给引擎加
"为性能而性能"的 API，也不会把测量逻辑混进产品代码。数字与命令都打印出来，便于人工复核。
