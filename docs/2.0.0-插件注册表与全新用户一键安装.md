# 插件注册表：让「全新用户」在插件管理里就能看到并一键安装线上插件

> 来源：`qy0214/stalker-localization-toolkit-ai-translate-2x`（AI 离线翻译插件作者）提出的
> 联调需求：插件发布后，**只有平台的客户**也应该能在插件管理里看到并装上它。
> 本分支是可直接合并的最小实现。

## 现状与问题

插件管理器（`tools/plugin_manager/main.cpp`）：

- 主表格 `items_` **只来自本地扫描**（`xrkit_cli --py-plugins-scan <plugins_dir>`）；
- 「安装所选更新」按钮取**表格当前行的 id**，再去线上注册表里找同名条目，
  下载 `package` → 校验 `sha256` → 解压 → 按 `entry` 定位目录 →
  整目录替换 `plugins/<target>/`。

于是这条链路只能给**已经装在本地**的插件做更新：
线上注册表（`plugins.json`）里有的、但本地没装的插件，在表格里没有行 ⇒ 选不中 ⇒ 装不上。

## 本分支的改动

| 文件 | 改动 |
|---|---|
| `include/xrkit/core/plugin_registry.h` | **新增**。注册表条目结构 + `registry_missing()`（注册表 ∖ 本地）+ `registry_pick()`。刻意**不依赖 Qt**：core 层不许依赖 Qt（见顶层 `CMakeLists.txt` 的全局口径），而且这段纯逻辑值得独立可编译的回归测试。 |
| `tools/plugin_manager/main.cpp` | 新增 `sync_registry_rows(verbose)`：拉线上注册表，把**本地还没装的条目**补成表格行（状态列「可安装（线上注册表）」）。接入三条路径：**启动时自动同步**（`QTimer::singleShot(300ms)`）、**点「刷新」同步**、**点「检查插件更新」同步**（并弹窗列出注册表条目）。安装逻辑一行未改。 |
| `tools/plugin_manager/main.cpp` | 注册表地址提为 `kDefaultRegistryUrl`，并支持环境变量 `XRKIT_PLUGIN_REGISTRY_URL` 覆盖（默认仍是原地址；便于自建镜像与联调）。 |
| `tools/plugin_manager/main.cpp` | 新增自检入口 `--registry-rows <url>`：无头跑一遍**真实的表格补行路径**并把表格内容打到 stdout（CI / 人工核对用）。 |
| `tests/plugin_registry_test.cpp` | **新增**。纯 C++ 回归测试（不依赖 Qt，可单独编译）。 |

行为变化（对用户）：

1. 打开插件管理器（或点「刷新」）→ 表格里除了本地插件，多出线上注册表里尚未安装的条目；
2. 选中其中一行 → 「安装所选更新」按原逻辑下载 / 校验 / 解压 / 整目录替换；
3. 本地没有该插件时，`update_prepare` 会建空备份再替换
   （`src/core/update_transaction.cpp` 已有该分支），所以**全新安装**同样走事务，失败可回滚。

## 构建与验证

```powershell
scripts\build.ps1 -Preset msvc-shell
# 产物：build\msvc-shell\src\shell\xrkit_plugin_manager.exe
```

跑新增的纯逻辑测试（不需要 Qt）：

```bat
cl /nologo /std:c++20 /EHsc /W4 /permissive- /utf-8 /I include ^
   tests\plugin_registry_test.cpp /Fe:build\plugin_registry_test.exe
build\plugin_registry_test.exe
```

无头自检（走真实表格路径）：

```bat
xrkit_plugin_manager.exe --registry-rows <plugins.json 的地址> <插件目录>
```

输出形如：

```text
REGISTRY-ROW ai_translate|ai_translate|AI 离线翻译（Hy-MT2 / 自选模型）|2.0.1|可安装（线上注册表）
PLUGIN-MANAGER ok action=registry-rows added=1 rows=1
```

## 依赖

线上注册表地址仍是原本硬编码的那个：

```text
https://raw.githubusercontent.com/ALittleHuman/STALKER-Localization-Toolkit-2.x-Network-Plugin/main/plugins.json
```

该仓库需要**公开**（客户端是匿名拉取的）。条目格式（平台实际读取的字段）：

```json
{
  "plugins": [
    {
      "id": "ai_translate",
      "version": "2.0.1",
      "package": "https://github.com/qy0214/stalker-localization-toolkit-ai-translate-2x/releases/download/v2.0.1/ai_translate_plugin_v2.0.1_install.zip",
      "sha256": "555aef58610a091d4b2031fa3ad83e06b81a8ebec7b2f26f25e283d47da7754b",
      "entry": "plugin.py",
      "target": "ai_translate",
      "name": "AI 离线翻译（Hy-MT2 / 自选模型）",
      "repo": "https://github.com/qy0214/stalker-localization-toolkit-ai-translate-2x",
      "note": "本地离线 AI 翻译 X-Ray 文本：Hy-MT2 两档内置模型 + 自选 GGUF，CPU/CUDA/Vulkan 自动识别，多路并发，术语库随包。"
    }
  ]
}
```

字段语义：`package` 不以 `http` 开头时会被拼到注册表仓库的 `main/` 后面（即把安装包放进
注册表仓库用相对路径）；`entry` 是**文件名**（不是路径），解压后在目录树里递归按文件名找，
找到后它所在的整个目录被替换到 `plugins/<target>/`；`target` 缺省取 `id`。
