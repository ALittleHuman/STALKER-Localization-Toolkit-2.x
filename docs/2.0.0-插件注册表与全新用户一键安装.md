# 插件注册表：让全新用户也能一键安装线上插件

> 来源：`qy0214/stalker-localization-toolkit-ai-translate-2x`（AI 离线翻译插件作者）的联调需求。

## 改动了什么

| 文件 | 改动 |
|---|---|
| `include/xrkit/core/plugin_registry.h` | **新增**。注册表条目结构（`id` / `version` / `package` / `sha256` / `entry` / `target`）+ 两个纯函数：`registry_missing()`（注册表 ∖ 本地已装）、`registry_pick()`（按选中 id 取条目）。不依赖 Qt —— core 层不许依赖 Qt。 |
| `tools/plugin_manager/main.cpp` | 新增 `sync_registry_rows()`：拉线上注册表，把**本地还没装的条目**补进表格，状态列标「可安装（线上注册表）」。接入三条路径：**启动时自动同步**、点「刷新」、点「检查插件更新」（并弹窗列出注册表条目）。注册表地址提为 `kDefaultRegistryUrl`，并支持环境变量 `XRKIT_PLUGIN_REGISTRY_URL` 覆盖（默认仍是原地址）。新增 `--registry-rows <url>` 无头自检口。**安装逻辑一行未改**。 |
| `tests/plugin_registry_test.cpp` | **新增**。纯 C++ 回归测试（不依赖 Qt，可单独编译）。 |
| `docs/2.0.0-插件注册表与全新用户一键安装.md` | **新增**。本文件。 |

## 作用是什么

**改动前**：插件管理器的表格只扫本地 `plugins/` 目录，「安装所选更新」也只认表格里已经存在的行。于是线上注册表（`plugins.json`）里有的、本地没装的插件，**界面里既看不到也装不上** —— 这条链路只能给已装插件做更新。插件作者的发布包说得再好，客户在平台里也找不到入口。

**改动后**：

- 打开插件管理器（启动即同步）或点「刷新」，线上注册表里尚未安装的插件会以「可安装（线上注册表）」出现在表格中；
- 选中该行 → 点「安装所选更新」→ 走原有逻辑完成下载 → sha256 校验 → 解压 → 按 `entry` 定位目录 → 整目录替换 `plugins/<target>/`；
- 未安装过也能装：`update_prepare` 对不存在的目标目录会建空备份再替换（`src/core/update_transaction.cpp` 已有该分支），**全新安装同样走事务，失败可回滚**。

**结果**：客户只装平台，也能在插件管理界面里找到并一键安装线上插件；插件作者把发布包登记进注册表就能触达用户，无需预装、无需手工解压。

**顺带**：

- 注册表地址可用环境变量覆盖 → 便于自建镜像或联调，不必改代码；
- `--registry-rows <url>` 可在无界面环境下跑一遍真实的表格补行路径并打印表格内容，便于 CI 核对。
