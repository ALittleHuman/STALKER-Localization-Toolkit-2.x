## 一、基础设施与语义

### 1.1 三个档位（`main()` 7296-7297）

| 档 | 含义 | SKIP 的后果 | 未覆盖清单的后果 |
|---|---|---|---|
| `--fast` | 公开 CI：跳过外部前提步骤 | 记 SKIP + `UNCOVERED` | **不判红**（结论行如实说"本次未覆盖"） |
| 默认（local） | 能跑的都跑 | 记 SKIP + `UNCOVERED` | 不判红 |
| `--release` | 发版口径 | `prereq()` 直接 `fail()`（**零容忍**） | `UNCOVERED` 非空 ⇒ 收尾整体 FAIL（7378-7380） |

### 1.2 五类"状态产生器"（都在顶部 149-200）

| 函数 | 写什么 | 性质 | release 档 |
|---|---|---|---|
| `fail(msg)` | `FAILURES += 1` | 真失败 | FAIL |
| `ok(msg)` | 只打印 | 通过 | — |
| `prereq(what, why, release)` | `UNCOVERED`（或 release 时 `fail`） | **外部前提缺件**（参照工具/真机样本/包不存在） | **FAIL** |
| `ledger(what, why)` | `LEDGERS` | **已知且被冻结的能力缺口**（如 chardet GB2312 探针未移植） | **不阻断**，但必须可见 |
| `package_fact(what, why, release)` | release: `prereq`；其它: `ledger` | 包内端到端事实 | **不许退化为台账**（P17-2） |

★★ 关键判据（P17-2，185-199）：**`LEDGERS` 不进 `UNCOVERED`** ⇒ 若"包内端到端事实"走 `ledger()`，
`--release` 可以在**这三条一次都没真跑**的情况下打 PASS —— 那是假绿。所以 release 档必须走 `prereq`。

### 1.3 子进程统一入口 `run(cmd, env, timeout=600)`（112-146）

| 行为 | 细节 |
|---|---|
| CWD | **恒为仓库根** `ROOT`（137）—— 脚本里若有依赖 CWD 的相对路径，等价于依赖"从仓库根跑" |
| 编码 | 子进程强制 `PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8` |
| TEMP | **每步独占**一个 `%TEMP%\rctmp_<pid>_<ms>`（122-128）—— 隔离 `--smoke` 的 `%TEMP%\xrkit_smoke_*` 互撞 |
| 残留进程 | 每次起子进程前 `taskkill /F /T /IM xrkit_app.exe`（130-133） |
| 超时 | 返回码 **124** + `[超时 Ns]`（144-146）—— 调用方必须把它当失败判（不是 SKIP） |
| 输出 | stdout+stderr 合并、UTF-8 解码（replace） |

★ 顶部还**自己**重编码 stdout（62-66）：修前只给子进程设 UTF-8，脚本自己打印 `✓/✗` 可能
`UnicodeEncodeError` ⇒ 退 1 且**没有 RESULT 行**（"红但不说哪一步"）。

### 1.4 汇总层（7328-7411）

```
for name, fn in STEPS:            ← 顺序即依赖（见 ② 的分组）
    if --only 且不匹配: continue   ← 不执行；收尾按"未执行"记账
    before = FAILURES
    fn(release)
    if 该步首次判红 且 name ∈ FLAKY_RETRY: 复跑一次；绿 ⇒ 撤销首次计数并登记"飘"
收尾:
    missing = STEPS - ran ⇒ UNCOVERED（"--only 过滤掉"与"一个都没匹配上"分开说）
    release 且 UNCOVERED ⇒ FAILURES += 1
    版本快照恢复 + 断言（_restore_and_assert_version_json，**在打印 RESULT 之前**）
    flaky_seen ⇒ ledger（可见、不阻断）
    FAILURES ? "RESULT: FAIL（N 处失败）" : "RESULT: PASS"
```

**★ 三类"未覆盖"来源（都进 `UNCOVERED`）**
1. `prereq()` —— 外部前提缺件；
2. `--only` 过滤掉的步骤（7305-7311 的修复：修前直接 `continue`，`--release --only winres` 能一键变绿）；
3. `package_fact()` 在 release 档的前提缺失。

**★ 一个"允许复跑"的白名单**（7326）：`FLAKY_RETRY = {golden-sqfs-pack-real, pkg-platform, release-criterion}`
—— 只这三个，只复跑一次，且**必须留痕**（`≈ … 首次红、复跑绿 ⇒ 登记为"飘"`）。
★ 复跑绿不算"干净"：收尾会把它记进 `LEDGERS`（P17-135：原来 `flaky_seen` 只 append 没人读）。

### 1.5 已知的"版本三件套"耦合（P17-130/133，7302 / 7332-7336 / 7382-7394）
- 开场 `_snapshot_version_json()`；
- **每个步骤前后**算一次 `version.json` 的 sha（`_vw_mark`）⇒ 收尾能点名"哪个步骤改过它"；
- 收尾 `_restore_and_assert_version_json()`：逐字节恢复三件 + 断言；
- ★ 实测结论：被点名的永远是 `shell-smoke`（它跑打包脚本，脚本写 version.json），
  而 `--only shell-smoke` 单跑不复现 ⇒ **写入依赖前面步骤留下的状态**；收敛条件是"那段在门禁状态下不写"。

### 2.1 顺序上的真依赖（读登记表里的注释得到）

| 依赖 | 依据 |
|---|---|
| `build` 必须第 1 | 后面绝大多数步骤读 `build/msvc-release/tools/cli/xrkit_cli.exe` |
| `shell-smoke`（110）必须在 `winres`（114）之前 | 那一步才把 `xrkit_app.exe` 编出来；`winres` 要读它的真实资源字节 |
| `pkg-platform`（115）→ `package-pages`（116）→ `release-criterion`（117） | 都要读 `dist/` 里的产物；前者失败会让后面按"前提缺失"记账 |
| `version-identity`（118）**最后** | 它同时读 tree / version.h / .rc / **包内 exe**，必须等包已定稿 |
