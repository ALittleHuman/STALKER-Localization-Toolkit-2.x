## 二、三条会改变设计的结论

1. **OGM 参考没有流级码率** ⇒ `ref_vbitrate = 0` ⇒ 走 `-q:v 7`（`transcode.cpp`），`-b:v` 不出现。
2. **容器级 `Duration: ..., bitrate: N kb/s` 必须忽略**：本批 4 组里容器级普遍比流级大 30–60 kb/s；
   拿它填视频流码率会凭空造出 `-b:v`，与 `-q:v 7` 是**结构性**差异，不是数值差。
3. **现有 4 份旧样本（`tests/golden/video_probe/`）全是 25/1**，名字叫 `ntsc` 的那份实测也是 25/1 ——
   “分数帧率/VFR”在旧样本里一格都没有；本批新录的两组（24000/1001、30000/1001）才真的覆盖。

## 三、对一份外部结论的更正

外部复核（DSH）给的表里写 `ffprobe_videoonly_avi.json` 的视频流 bit_rate = 447440。
实测：**447440 是 `format.bit_rate`，该样本视频流没有 `bit_rate`**；四份旧样本的**视频流全部没有** bit_rate。
⇒ “`-b:v` ±1000 只在参考恰好是单流 AVI 时相关”这句话的样本依据不成立；
  正确说法是：**在现有全部样本里，参考侧视频流码率都不存在**，`-b:v` 只可能来自用户自备的、带流级码率的文件。

## 四、L2 白名单（按实测收敛）

| 字段 | 容差 |
|---|---|
| codec / width / height / channels / sample_rate | 完全一致 |
| fps | `abs(a-b) <= 0.01`（实测最大差 0.00393） |
| 流级 bit_rate | `abs(a-b) <= 1000`（实测最大差 751）；**缺失 ≠ 0**，按 missing 单独判 |
| duration | `<= 0.02`（ffprobe 1.000000 vs 文本 00:00:01.00） |
| has_video / has_audio / parsed | 完全一致 |
| size_mb | 两边都不从文本取（`file_size()`），不参与 L2 对比 |
