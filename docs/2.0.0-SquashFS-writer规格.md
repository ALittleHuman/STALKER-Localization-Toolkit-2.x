## 1. 参照工具的行为（实测确认）

- 压缩器默认 **xz**（`compressor_get_default` 首选 xz），块大小 **131072**（`block_log=17`）
- 产物**确定性**：同一 tar 连打两次字节完全相同；`mkfs_time` 默认 0；`-d mtime=` / `-k` 可钉住
- 1.x 的 `sqfs_pack` 只喂**普通文件**（`apps/fs_app.py` 的 `files_data` 里 `is_dir=False`），
  目录由 tar2sqfs 按路径**隐式建**（mode 0755 / mtime 0 / uid gid 0）
- 结尾**补零到 4096 的整数倍**（`padd_sqfs`，`bytes_used` 不含补零）

## 2. 逐项规则（v1 里的 10 条疑问，现在都有答案）

| # | 项 | 确认的规则 | 证据 |
|---|---|---|---|
| 1 | 超块 96 字节字段 | 见 §3；缺表一律 `0xFFFFFFFFFFFFFFFF` | 实测 + `write_super.c` |
| 2 | inode 编号顺序 | **先递归子目录，再按名字序给本层子节点编号，根最后** | `fstree/post_process.c:16-57` |
| 3 | inode 记录类型 | 目录：条目数 ≥ 256 或目录表 > 0xFFFC ⇒ `DIR_X`，否则 `DIR`；文件：`sparse>0` 或 `nlink>1` ⇒ `LREG`，否则 `REG` | `dir_writer.c:383-391`、`inode.c:204-227` |
| 4 | 目录项排序与分组 | 子节点按**名字字节序**（`strcmp`）插入；落盘按 inode 编号序（子先于父）；每组 ≤256 条 / 同 inode 元数据块 / 编号差 ±32767 / 不跨 8 KiB | `fstree/mknode.c:14-31`、`dir_writer.c:219-248` |
| 5 | 块切分与碎尾 | 128 KiB 一块；**碎尾进 fragment**（≤ block_size 的碎片攒成一块，攒满即写、收尾再写） | `block_processor/frontend.c:176-215` |

### 2.1 超块 `flags` 的算法（v1 写错过一次）

初始 `NO_FRAGMENTS(0x10) | NO_XATTRS(0x200) | NO_DUPLICATES(0x40)`；
有碎片时**清 NO_FRAGMENTS、置 ALWAYS_FRAGMENTS(0x20)，再置 UNCOMPRESSED_FRAGMENTS(0x08)**，
随后**只要有任何一块 fragment 被压缩过就清掉 UNCOMPRESSED_FRAGMENTS**（`frag_table.c:129-155`）。
实测常态 ⇒ `0x260`。v1 的文档把它记成"0x200 无 xattr + 0x40 重复 + 0x20 always fragments"
——位名对、但漏了"0x08 是被清掉的"这条**方向性**规则，v2 更正。

### 2.2 块去重（影响盘上布局，必须复刻）

- **数据块**：文件结束（含"恰好整块"的文件）时，拿**本文件全部已写块的（长度, 校验和）序列**
  与**更早的任何起点**逐段比对（校验和用 xxh32 预筛 + 盘上逐字节复核）；命中则
  `blocks_start` 指回旧位置，并把刚写的重复块**截断**掉（`block_writer.c:56-120`）。
- **fragment**：按（xxh32, 长度）预筛 + 逐字节复核，命中则新碎片不写，inode 指回旧碎片
  （`block_processor/backend.c:151-176`）。
- 全零块/全零碎尾 ⇒ **稀疏**：不写盘、`block_sizes[i]=0`、inode 升 `LREG` 并累加 `sparse`
  （`block_processor.c:19-23`、`backend.c:88-97`、`backend.c:138-146`）。

## 3. 踩过的坑（都是"逐字节对拍"抓出来的，别改回去）

1. **数据区必须从偏移 96 开始**：参照实现是先写超块再写数据块；我们若直接从 0 写数据，
   整条数据区前移 96 字节、所有 `blocks_start` 全错，但镜像仍能被 reader 读出来 ——
   只有逐字节对拍能发现（我们的做法：开文件后先占住 96 字节）。
2. **`sqfs_dir_index_t` 的磁盘字段顺序是 `index, start_block, size`**（不是
   `start_block` 在前）。源码里给内存结构体赋值时写的是 `ent.start_block = idx->block`，
   容易被读成"磁盘也是这个顺序"，实测会被抓。
3. **xz 必须走 `lzma_stream_buffer_encode`**：它与"流式 API"的产物**差 4 字节**
   （块头是否写压缩/未压缩长度字段）。两种都是合法 xz，只有逐字节对拍分得出来。
   注意我们 vendored 的是 xz **5.6.4**，而参照包内是 **5.2.5**：实测**载荷完全一致**、
   只差那个块头字段，所以用 5.6.4 + `stream_buffer_encode` 即可复刻（已由 5 组夹具证明）。
4. **压缩"压不小就原样存"**：`written >= 输入长度`、或输出缓冲放不下（`LZMA_BUF_ERROR`）
   都算"不值得压"，置 bit24 原样存 —— 这两条在参照里是同一个返回值 0，别拆成两种处理。
5. **元数据块是 8 KiB 一分块**（不是 128 KiB），块头 2 字节（bit15 = 未压缩），
   前进用 `2 + 压缩后长度`。

## 4. 判据与常态化验证

`tests/golden_sqfs_pack.py`（门禁第 [10] 步）：

```
python tests/golden_sqfs_pack.py --write   # 用 1.x 的 sqfs_pack 生成基线（sha256 入库）
python tests/golden_sqfs_pack.py           # 对拍：跑 2.x 的 xrkit_cli --pack-sqfs
```

夹具与它各自覆盖的规则：

| 夹具 | 覆盖 |
|---|---|
| `basic` | 碎尾 fragment / 正好一块 / 多块+尾 / 空文件 / 隐式目录 / 西里尔与非 ASCII 名 |
| `dedup` | 整段数据块去重 + 同名碎片去重（实测省掉 2 个数据块 + 2 个碎片） |
| `many` | 600 个碎片小文件：inode 表与目录表都跨 8 KiB 元数据块 + 目录 ≥256 条（`DIR_X` + inodex 索引） |
| `sparse` | 全零数据块（稀疏）+ 全零碎尾（参照实现里最刁的一条路径） |
| `dirs` | 显式目录条目（含空目录；1.x 的 fs 页只喂文件，这里走 `--pack-dirs` 单独验证） |

三层判据：① 产物 sha256 == 基线 sha256；② 产物能被**我们自己的 reader** 读回
（路径/类型/大小与夹具一致）；③ 产物能被 **rdsquashfs**（第三方）读回（路径 + 类型一致）。

### 4.1 反证记录（这条锁"会红"的证据，J4 口径）

不是"设计上应该会红"，而是**这一轮真的红过**、且每条对应一个真缺陷：

| 注入（= 把规则写错/拿掉） | 谁变红 | 现象 |
|---|---|---|
| 不先占住超块那 96 字节 | `basic` 红 | 数据区前移 96 字节，`blocks_start` 全错（reader 照样能读出来） |
| `UNCOMPRESSED_FRAGMENTS` 置/清方向写反 | `basic` 红 | 超块第 24 字节 `0x268` vs 基线 `0x260` |
| `sqfs_dir_index_t` 按 `start_block, index` 写 | `many` 红 | inode 表偏移 19261 起字段互换 |
| 关掉块去重（或碎片去重） | `dedup` 红 | 布局与基线不同（这一轮实测省了 2 个数据块 + 2 个碎片） |

## 5. 还没做的（如实记账）

- **其它压缩器**（gzip / lz4 / zstd）：1.x 的封包只产出 xz，没有"逐字节一致"的参照基线，
  按"不写没法验证的代码"的口径**暂不实现**（`compress_block` 显式报错，不静默降级）。
  什么时候要，就先用 `tar2sqfs -c <name>` 造基线、再补。
- **大端 `sqsh` 写**：读已支持（A1），写只有小端（参照工具也只写小端）。
- **符号链接 / 硬链接 / 设备节点**：1.x 的封包链路不产生这些条目，未实现。
