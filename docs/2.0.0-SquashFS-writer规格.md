# 2.0.0 SquashFS writer 规格（M1-5，第一版）

> **验收判据（用户拍板，不许降级）**：**产物逐字节一致**。
> 落地方式：同一份输入 → 我们的 writer 与 `tar2sqfs`（1.x 的封包工具）产出的镜像
> **sha256 必须相等**。
>
> 可行性已实测（2026-09-24）：`tar2sqfs` 产物是**确定性**的 ——
> 同一 tar 连打两次字节完全相同；superblock 的 `mkfs_time` **默认写 0**（不是当前时间）；
> `-d mtime=<值>` / `-k` 可显式钉住时间戳。所以"逐字节一致"是良定义、可验证的判据。

## 1. 参照工具的行为（实测）

- 工具：`deps/squashfs-tools-ng-1.3.2-mingw64/bin/tar2sqfs.exe`，版本 1.3.2
- 压缩器**默认 xz**（`--help` 里 `xz (default)`；1.x 的 `sqfs_pack` 不传 `-c`）
- 块大小 **131072**（128 KiB），`block_log=17`
- 产物确定性：
  | 选项 | 两次运行 | `mkfs_time` |
  |---|---|---|
  | 默认 | 字节相同 | **0** |
  | `-d mtime=1700000000` | 字节相同 | 1700000000 |
  | `-k -d mtime=…` | 字节相同 | 1700000000 |

## 2. 参照镜像的实测解剖（小样本：1 目录 + 2 文件，4096 B）

```
magic=hsqs  inodes=4  mkfs_time=1700000000  block_size=131072(log=17)
frags=1  comp=4(xz)  flags=0x260  no_ids=1  version=4.0
root_inode=0x60  bytes_used=625
inode_table=408  dir_table=522  frag_table=603  id_table=617
export_table=0xFFFFFFFFFFFFFFFF（缺失）  xattr_id_table=0xFFFFFFFFFFFFFFFF（缺失）
```

- `flags=0x260` = `0x200`(no xattrs) + `0x40`(duplicates) + `0x20`(always fragments)
- **区段顺序**：超块(0..96) → 数据块区(96..408) → inode 表(408) → 目录表(522) →
  fragment 表(603) → id 表(617) → 结束(625)
- 缺失的表用 `0xFFFFFFFFFFFFFFFF` 占位（不是 0）
- 数据区里每块都是独立的 xz 流（`fd 37 7a 58 5a` 魔数可见）
- 元数据块（inode 表/目录表/fragment 表/id 表）按 8 KiB 解压上限分块，块头 2 字节
  （bit15 = 未压缩）

## 3. 我们的 writer 必须复刻的清单（逐项都要有判据）

| # | 项 | 判据 |
|---|---|---|
| 1 | 超块 96 字节字段值与顺序 | 与参照**逐字节**相同 |
| 2 | inode 编号分配顺序 | 参照镜像里 inode_number 的分配次序（需继续解剖确认） |
| 3 | inode 记录类型选择（REG vs LREG、DIR vs DIR_X） | 与参照相同（参照用了哪些要看实际镜像） |
| 4 | 目录表分块与条目排序 | 目录项顺序（参照在 `dir` 目录下先 `b.bin` 后 … —— **排序规则待确认**） |
| 5 | 128 KiB 块切分 + 尾部 fragment 打包 | 与参照相同（含 `always_fragments` 语义） |
| 6 | xz 压缩参数（级别/字典/校验） | 与参照相同（默认级别待确认，可能要查 xz 参数记录块 `flags & 0x400`） |
| 7 | fragment 表条目 | 与参照逐字节相同 |
| 8 | id 表（`no_ids=1`，单条 uid/gid） | 与参照逐字节相同 |
| 9 | `bytes_used` 与结尾无多余填充 | 文件总长与参照相同 |
| 10 | 不写 export 表 / xattr 表 | 对应字段为 `0xFFFF…` |

## 4. 验证脚本计划（`tests/golden_sqfs_pack.py`）

- 输入：合成目录（含目录/空文件/西里尔名/多块大文件/超 128 KiB 的文件）
- 基线：`tar2sqfs -q <out>`（**由 1.x 的 `sqfs_pack` 逻辑生成**，可加 `-d mtime=` 钉时间）
- 对拍：我们 writer 的产物 **sha256 必须相等**；不等就打印首个不同字节与上下文，
  并逐字段比对超块（定位是布局差异还是压缩差异）
- 附带：产物必须能被**我们自己的 reader** 与 **rdsquashfs** 读回逐条一致（双保险）
