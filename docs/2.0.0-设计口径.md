## 1. 总纲

### 1.1 目标（已定）
用 **C++20 + Qt6 Widgets** 完全重写 STALKER 汉化工具集：**行为对齐 1.x、速度与精度提升、兼容性不倒退**。
六页功能面原样保留（文件系统 / 编码转换 / 文本提取 / XML 校对 / 视频转换 / 汉化包生成）。

### 1.2 非目标（本轮不做）
- 不加新功能页、不改六页的交互形态（1.x 口径就是验收基线）。
- **引擎补丁件（`engine_utf8_patch`）本轮不重写**（用户 2026-09-24："补丁是需要重写的，那个稍后再说"）。
- 不做插件生态推广（题材冷门，插件只服务我们自己与少数人）。

### 1.3 继承的已定口径（2026-09-18，不复述理由）
| 项 | 内容 |
|---|---|
| 三阶段 | ①引擎库 `xr_fs` / `xr_font` / `xr_text`（**core 不许 include Qt**）+ CLI（`--selftest/--bench/--themecheck/--dump`）+ **黄金语料逐字节差分**；②Qt6 外壳 + 六页；③插件 SDK（**C ABI**）/ 打包 / 行为对齐 |
| 命名 | 命名空间 `xrkit::`；文件名 `snake_case`；类型 `CamelCase` |
| 重写理由 | "不破不立"：X-Ray 本身是 C++，解包封包更顺更准；闭源插件源码在手；插件生态非约束 |

### 1.4 本轮新增决策（2026-09-24）
见 `2.0.0-待拍板清单.md` 的「决策记录」表。其中对架构影响最大的三条：
- **B2 全部支持** ⇒ 插件 ABI 必须能承载 `panel`/`tool`，**16 方法 UI 工厂进 C ABI**。
- **B3** ⇒ NLC 解密件移植成 C++ **内部模块**（继续不随发行包发布）；补丁件推迟。
- **C3 实现方式可以改变，生成产物要保持原样** ⇒ 内部实现自由，**产物与 1.x 逐字节对齐**当判据。

## 2. 分层架构

```
STALKER_Toolkit_2.x/
├─ CMakeLists.txt / CMakePresets.json      # MSVC 14.44 + Ninja + Qt 6.8.3
├─ include/xrkit/                          # 公共头（core/engine 的对外面）
├─ src/
│  ├─ core/      xrkit::core               # ★ 不许 include 任何 Qt 头
│  │     path / log / text(编码链) / ini(user.ltx) / thread / bytes / result
│  ├─ engine/    xrkit::fs  xrkit::font  xrkit::text  xrkit::xml  xrkit::video
│  │     （同样不许 include Qt；可被 CLI 直接黑盒驱动）
│  ├─ shell/     Qt6 Widgets 外壳
│  │     hub / 六个页面 / components(滚动·分栏·树·日志·任务壳) / theme
│  └─ plugin/    C ABI 宿主：注册表 / 加载器 / 16 方法 UI 工厂 / 内置件
├─ include/xrkit/plugin/abi.h               # ★ 历史遗留契约头（C ABI 已退役；新插件走 .py）
├─ tools/       xrkit_cli（--selftest / --bench / --themecheck / --dump）
├─ tests/       黄金语料差分 + 行为判据探针 + 注入验证器
├─ third_party/ 源码 vendored（含 sha256 记录，离线可复现）
└─ docs/
```

**依赖方向（硬约束）**：`shell → engine → core`；`plugin` 只依赖 `core` 与纯 C 头。
**机器强制**：`core/` 与 `engine/` 的编译单元若出现 `#include <Q…>` 或链接到 Qt 库 → 门禁直接红（AST 扫描 + 链接依赖检查双保险）。

## 3. 引擎设计（含 1.x 已确认缺陷的修法）

### 3.1 `xrkit::fs`（SquashFS + DB 六格式）
| 项 | 设计 |
|---|---|
| SquashFS 读 | **自实现**元数据读取（超块 96B → inode 表 → 目录表），游标式跨块读取（**不许对 ref 做 `ref+16` 算术**） |
| 字节序 | 小端 `hsqs` + **大端 `sqsh` 都支持**（1.x 只认小端，大端退化成"大小全 0"） |
| 压缩 | gzip / xz / lz4（块格式）/ zstd / **lzo / 旧 lzma 补齐**（1.x 的 lzo 缺口就此关掉） |
| 访问方式 | **mmap + 按 `offset/size_comp` 预读**（1.x 把整包读进 `bytes`，8.3 GB 镜像直接爆内存） |
| SquashFS 写 | **自实现 writer**（不再依赖外部 `tar2sqfs.exe`；360 会按文件哈希拦外部 exe） |
| 默认压缩 | **xz 块**（与 1.x 产物同族），UI 另给 gzip / lz4 / zstd |
| 目录条目 | 目录必须写 **DIRTYPE**（1.x 虽修了引擎分支，但fs 页恒传 `is_dir=False` ⇒ 分支永不触发） |
| 解包路径安全 | 选中集与整镜像**两条路都过同一套六条校验**（1.x 整镜像分支推给外部工具、未验证） |
| 错误上报 | **随返回值/异常对象传递**（1.x 用模块级全局 `sqfs_last_error`，并发互相覆盖） |
| DB 六格式 | `xdb/2947ru/2947ww/2945/2215/11xx` 的 LZHUF + scrambler 逐值照抄；`auto_detect` **唯一自洽才返回**，歧义返回"未识别"让用户手选 |
| 运行时依赖 | **零外部 exe**（这是本模块的红线） |

### 3.2 `xrkit::text`（编码链 + 文本提取）
- 编码链**顺序不可改**：BOM → 多字节检查（`max(raw)≥0x80` 且严格 UTF-8）→ 手动指定 → XML 声明（**须被字节证实**）→ 统计 → `windows-1251`。
- 两个程序化判定：多字节＝UTF-8；单字节家族用 `bytes(range(256))` 容错解码长度判，**不许维护编码名单**（1.x 曾漏 `cp865` 导致整篇乱码）。
- `gb18030` 必须排在 `windows-1251` 之前。
- **判定函数返回"胜出步号 + 理由"**，日志直接用返回值（1.x 是 `convert_app` 复算，与判定可不一致）。
- 文本提取：正则用 **PCRE2**（兼容 Python `re` 的 lookbehind）；候选遍历**必须排序**，保证 ID 生成可复现。

### 3.3 `xrkit::font`（产物保持原样）
- 渲染：FreeType；重采样：自实现（**实现方式可变**）。
- **产物判据＝与 1.x 产物逐字节一致**（用户 C3 口径）：
  - 几何参数全部照抄：`SIZES` / `CELL_HEIGHTS` / `BLOCK_WIDTHS` / `CELL_HEIGHT_RATIO=1.40` / `PUNCT_PAD_PX`；
  - 墨迹定标 `range(size, size+14)`，判据 `墨迹高 ≤ cell−4` 且 `墨迹宽 ≤ min(推进宽, cell)`；
  - 宽度口径顺序：`rect_w_for` → `min(rw,cell)` → 抬框 → 标点内缩 → 封顶 cell → 墨迹压进框；
  - DDS：legacy `DDS_PIXELFORMAT`、无 DX10 头、无 mipmap、`8888`（SoC/ClS）/`A8`（CoP）；
  - 画布高 `need = max(1, max_y)`（写 `max_y-1` 会静默丢一整行）；
  - ini 行格式、简繁回退（键仍是原码位）、缺字形的**拒绝 vs 告警**两套语义分开。
- **不做的事**：不为"字节一致"去复刻 Pillow 的内部实现；用 FreeType + 自写重采样逼近，差异逐条报账（见 §6 R2）。

### 3.4 `xrkit::xml` / `xrkit::video`
- XML 校对：两种内置模式声明式（列/筛选/比较/行/明细）；明细**虚拟化**（视口 + 2 行 overscan）；`detail` 列**不许调 `detail_builder`**。
- 视频：只认 `user.ltx [ffmpeg]` + 程序目录两处；**惰性探测、失败也置位**；三按钮**非阻塞**小窗；自动安装**只能挂按钮**。

## 4. 插件 ABI（B2：全部支持）

### 4.1 形态（已定：纯 C ABI + 版本化结构体）
```c
/* ★ 历史口径（已作废）：include/xrkit/plugin/abi.h —— C ABI 已退役，新插件是 .py 模块 */
#define STK_ABI_VERSION 1u

typedef struct stk_widget stk_widget;   /* 不透明：宿主的 Qt 控件，插件只拿指针 */

typedef struct stk_host_api {
    uint32_t abi_version;               /* 宿主先校验 == STK_ABI_VERSION */
    uint32_t struct_size;               /* = sizeof(stk_host_api)，为向后兼容留口 */
    void*    host;                      /* 不透明，回传给下面所有回调 */
    /* ① 注册面：与 1.x 的 10 个注册点一一对应（含 panel/tool） */
    void (*register_decryptor)(void*, const char* name, int (*check)(const char*), int (*decrypt)(const char*, stk_buf*));
    void (*register_format)(void*, const char* name, const stk_format_handler*);
    void (*register_command)(void*, const char* action_id, const char* label, void (*handler)(void*), const char* when_json);
    void (*register_menu_item)(void*, const char* label, const char* location, const char* host_id, const char* area, const char* command, int order);
    void (*register_option_entry)(void*, const char* host_id, const char* area, const char* value);
    void (*register_option)(void*, const char* label, const char* const* choices, size_t n, const char* host_id, const char* area, int order);
    void (*register_panel)(void*, const char* title, const char* host_id, const char* area, int order, stk_widget* (*builder)(stk_widget* parent));
    void (*register_tool)(void*, const char* name, int order, stk_widget* (*builder)(stk_widget* parent));
    void (*register_compare_mode)(void*, const stk_compare_mode*);
    /* ② UI 工厂 16 方法：panel/tool 的 builder 靠它造控件，所以必须进 ABI */
    stk_widget* (*ui_label)(stk_widget*, const char* text, const char* style);
    stk_widget* (*ui_button)(stk_widget*, const char* text, void (*on_click)(void*), int width, const char* style, const char* state);
    stk_widget* (*ui_row)(stk_widget*, const char* side, const char* fill, int expand, int padx, int pady);
    /* ui_checkbox / ui_entry / ui_text / ui_combo / ui_drop_box / pack /
       set_text / set_state / text_view / alive / ask_yes_no / ask_open_file / ask_save_file 同形 */
    void (*ui_set_text)(stk_widget*, const char* text);
    void (*ui_set_state)(stk_widget*, const char* state);
    int  (*ui_alive)(const stk_widget*);
    int  (*ask_yes_no)(void*, const char* title, const char* message);
} stk_host_api;

typedef struct stk_plugin_desc {
    uint32_t abi_version;
    const char* id; const char* name; const char* version; const char* author; const char* description;
    void (*register_plugin)(const stk_host_api* api);
} stk_plugin_desc;

STK_EXPORT const stk_plugin_desc* stk_plugin_entry(void);   /* 唯一的导出符号 */
```

### 4.2 兼容与纪律（照 1.x 的成熟做法）
- 加载：扫 `plugins/**/*.dll`（`plugins/enabled.txt` 白名单）；**单个插件加载/注册失败不影响启动**，错误进 `load_errors` → 启动弹窗可见。
- 槽位：`host` 6 个 × `location` 2 个 × `area` **10 个**（含 `AREA_BOTTOM`）；**精确匹配、不跨槽回退**；非法寻址注册时被拒并留痕。
- 排序：`order` 升序 + **注册顺序**稳定排序。
- **内置与插件同一张表**：比较模式等内置能力用与插件**同一个哨兵值**（修 1.x `"<builtin:xml>"` vs `"<builtin>"` 的缺陷，且内置优先级必须真的生效）。
- 回调异常：**绝不冒到 UI 层**，宿主捕获后写日志。
- UI 工厂语义要复刻 1.x 的两条（否则"同一份插件代码两个后端布局不一样"）：`pack()` 与 Tk 同义；`row()` 是**竖直**容器、`side=left/right` 摘进水平行子容器。

### 4.4 过滤语义差异（★ 有意差异，写在这里防后人当缺陷再修一遍）

**来源**：`01 F-10`（审计：同一查询串在**内置页**与**插件页**上各跑一次会发现命中集合不同）。

| 侧 | 实现 | 匹配依据 |
|---|---|---|
| **门面（插件页）** | `src/shell/facade_tree.cpp` 的 `FacadeTree::apply_filter_to` | 逐列比 `item->text(column)`（`contains(needle, Qt::CaseInsensitive)`）—— 即**列里看得见的那段文本** |
| **内置页（fs 页）** | `src/shell/pages/fs_page.cpp` 的 `matched_paths_` | 比**节点自己的路径**（`node->path`），命中项进 `matched_paths_`（画成加粗）、祖先链进 `filter_keep_` 撑住层级 |

**口径（两条路都成立，不合成一条）**：

1. 两边都是「**对若干字符串做大小写不敏感的 `contains`**」，**唯一区别是"比哪些字符串"**；
2. 内置页比的是**页自己知道、门面拿不到**的那样东西（节点的完整路径）⇒ **不是"门面表达能力不足"**，
   而是**页侧决定拿什么去匹配**。门面因此**不**替插件推断"哪一列是路径"（那正是"字段里藏样式"那种错：
   让宿主猜语义）；
3. 插件页要复现内置页的命中集合，**做法是插件自己拿路径去匹配、把结果写进 `TreeNodeSpec::matched`**
   —— 该字段在 P17-57 已运到（接口先到）；**"命中画成什么样（加粗等）"属呈现，归 UI 批**
   （见 §四·8③ 用户 2026-10-10 的裁定）。
4. ⇒ 本差异**记为有意差异**，**不是**待修缺陷。★ 判据侧也把它钉住了：门禁在 `doc-cite` 那一步
   要求本文件同时出现「门面匹配依据＝`item->text`」与「内置页匹配依据＝`matched_paths_`」两行字
   （少一行就红）——免得日后有人只改一边、或把这条差异**悄悄删掉当没发生过**。

## 6. 验收判据（你说的"能在真程序里量的判据"）

**J1 黄金语料逐字节差分（引擎层，最重要）**
- 语料两个来源：①**真机样本** `E:\Human\NLC Improved [OBT]`（`gamedata.sq_*`、`xrEngine.exe`/`xrEngine_patched.exe`）；②1.x 现产物（用 1.x 跑出来的解包/字库/提取结果）。
- CLI 黑盒驱动（`--dump` / `--selftest`），**不许进程内打桩**。
- **禁止代理指标**：不许用"字节数相同/条数相同/长度相同"当通过判据（1.x 的血账：v3 与 v4 差异字节数完全相同，字节数既分不出对错也证不了位置）。

**J2 行为口径对照表逐条重验**：15 组每条带可量判据，逐条给"位置 × 判据 × 实测值"，并主动点出**没查的地方**。

**J3 三档门禁 + 未覆盖清单是一等公民**：`fast` / `local` / `release`；
缺件分类＝仓库自带门禁文件缺件 **FAIL**、第三方/真机样本缺件 **SKIP**（release 档 FAIL）；
`release` 档**未覆盖清单非空即整体 FAIL**；SKIP 标识为跨文件字面量 + 防漂移锁。

**J4 注入必红**：每条锁都要"先证会红 → 再证改回即绿"；注入必须**复现机制**（写错注入＝假的漏锁）、注入后 AST 自检、还原后 sha256 核对、残留注入文本**拒绝启动**。

**J5 无 Qt 依赖锁**：`core`/`engine` 的编译单元与链接依赖里都不许出现 Qt。

**J6 真启动锁**（1.x 的已知缺口，2.0 补）：冻结/装配后**真启动一次**并断言主窗口与主循环就绪（抓"一启动就崩"）。

**J7 产物保持原样**（C3）：字库 DDS/INI、XML 改写产物、封包产物与 1.x 逐字节对齐。

## 7. 风险（按大小排序）

**R1 第三方依赖的获取（M0 第一件事，最大风险）**
需要：FreeType（字形栅格）、zlib / xz / zstd / lz4 / lzo（压缩）、PCRE2（正则）。
障碍：本机 **GitHub 被 hosts 指向 127.0.0.1**，且 **schannel TLS 整体不可用**（curl/git/PowerShell 走不通，只有 Python/Node 的 OpenSSL 栈正常）。
方案：用 Python 从**可达的国内镜像**拉源码 tarball，vendored 进 `third_party/` 并**记录 sha256**，构建离线可复现（不引入 vcpkg 之类的网络型包管理）。

**R2 字库产物逐字节（技术上最难的一条）**
Pillow 的 LANCZOS 采样相位与 FreeType 版本差异都会引入像素级偏差。对策：**先用几何判据（11 组）全部达标**，再逐步逼近逐字节；若最终仍有差异，**逐条列出差异与原因交你裁决**，绝不在判据上偷偷放宽。

**R3 360 拦包**：本机 `360tray` + `ZhuDongFangYu` 在跑，外部 exe 已被拦过一次（按哈希）。对策：引擎零外部 exe；发行包做完后用真机实测 360 的反应，再决定是否买签名证书。

**R4 `core` 无 Qt 的代价**：Qt 的 `QRegularExpression` 本身就是 PCRE2 包装，但不能用 ⇒ 必须自己 vendored PCRE2；同理 INI、路径、线程都要自己写薄封装。

**R5 工期与返工**：1.x 最大的钱花在滚动条一族返工上，2.0 的对策是 §5 的"逐条判据 + 注入必红 + 黄金语料差分"在 M0/M1 就位，而不是等 M2 才发现口径漏了。
