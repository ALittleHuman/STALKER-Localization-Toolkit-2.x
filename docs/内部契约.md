# 内部契约（维护者）

给改代码的人看的硬口径；用户文档在 `用户手册.md` / `插件开发.md` 等。

> 当前插件只支持 Python 文件/目录；`PLUGIN_API = 2` 是 **Python 插件 API 的契约版本**（API 1 仍兼容），不是二进制 ABI。
> 下面说的 “sink 键” 是 Python 插件通过 `api` 上报给宿主的结果键。

## 1. 插件 sink 键（Python API 路径）

### 1.1 `XmlCompareResult` 的 sink 键：认什么、不认什么

- `row_kind` **不落位**（结果结构里没有这个字段）——它是渲染提示，不是比较结果；
- 但**不许静默丢**：宿主不认识的 sink 键必须逐条记进 `unhandled_keys`，由调用方决定报错还是忽略；
- `ids_a` / `ids_b` 按**插件真报上来的 ID 数**算（不能取文本模式的 `id_text_*` 表——那张表在插件 sink 路径上恒空）。

## 2. 过滤语义的两条依据

- 门面侧：`item->text(column)` 是“用户看到的那一格”；筛选必须按它算，不看隐藏列。
- 内置页侧：`matched_paths_` 记录子树里命中的路径集合；父节点是否可见由它决定。

## 3. SquashFS 压缩（读/写分开写实）

- 压缩（**读**侧）：xz / gzip / lzo / lz4 / zstd 都能读；写侧只支持 xz（默认）＋ gzip，读写能力**不对称**。
- 写侧压缩器**没做**：lzo、lz4、zstd 三种（lzo 的原因是 minilzo 没有 lzo1x_999；lz4 要多写 8 字节 options 块，即 `COMPRESSOR_OPTIONS` 语义）。
- 默认压缩：写侧默认 xz；**写侧另有 gzip**（已落地）。

## 4. 文本模块 sniff 门槛

- 决定性 = 证据 >= 2 且 |score| >= 0.15（与 `sniff.cpp` 常量同值）。

## 5. 零调用但**保留**的接口（口径，2026-11-20 用户裁定）

判定规则：**预留通道保留、真死代码删除**。以下三处按"预留/通用工具"保留，别再当死代码删：

| 符号 | 现状 | 为什么留 |
|---|---|---|
| `plugin::set_host_facade()` | 零调用（内置表是唯一实现） | **宿主门面注入口**：将来 CLI/别的宿主若要换一套 host.* 实现，入口就是它。删了这条扩展通道就没了。 |
| `core::case_fold_ascii()` | 零调用（`case_fold_lower` 用得更多） | 通用工具，不是重复实现：ASCII 折叠与 Unicode 折叠语义不同，留着给"只折 ASCII"的场景。 |
| `Registry::register_format()` | 已在 2026-11-20 补上 Python 绑定（`api.register_format`） | 不再是死代码；插件可声明"这种文件我也能读"。 |

已删除的真死代码（留个记录，别再加回来）：

- CLI `--app-update`：与 `xrkit_updater.exe` 里的同一套事务重复，且 updater 从不走 CLI；
- `engine_facade_method_names()` / `host_facade_method_names()` / `ui_worker_safe_method_names()`：
  C ABI 时代的枚举辅助，`--ui-facade` 走的是 `ui_facade_method_names()`；
- `Registry::has_command()`：零调用的便捷访问器。
