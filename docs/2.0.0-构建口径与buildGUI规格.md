# 2.0.0 构建口径与 buildGUI 规格（口径 v2 —— 已按你 2026-09-27 的修正改）

> 你的要求（原话整理）：**"还是用 dist"**；版本/标记/计数＝**唯一事实来源**；**`version.json` 用树的结构
> 记录构建的历史版本**；**BuildGUI 里只能选择版本号和标记**，**序号参照 `version.json` 自动填、显示
> 下一个构建的序号**，**还要标上完整版本号**，**版本号或标记更新时序号和显示同步更新**；
> **GUI 的小组件也用通用的**；**构建的具体实现代码不要单独一份，直接引用 CLI 的就行**（否则两者结果会有差别）。

## 一、产物位置：**继续用 `dist\`**（v1 里我提的"退役 dist"作废）

```
STALKER_Toolkit_2.x\
├─ dist\
│   ├─ STALKER_Toolkit_2.0.0_BETA.4_d63f8f8.zip     ← 分发 zip（保留现有命名：版本+标记+序号+提交）
│   └─ STALKER_Toolkit_2.0.0_BETA.4_d63f8f8\        ← 同名成品目录（exe + Qt 运行时 + 空 plugins\ + README/version.txt）
├─ builds\                                          ← **编译中间物**（CMake/Ninja 的 build 树），不进分发
└─ build\                                           ← 保留现状：日常开发的两个预设目录（msvc-release / msvc-shell）
```

- **`FAIL\` 仍放 `dist\FAIL\`**：失败构建按时间戳重命名留档（日志与目录同名），照 v1 的失败流判据不变。

## 二、`version.json`：**树结构**记录构建历史（唯一事实来源）

```json
{
  "current": { "version": "2.0.0", "prerelease": "BETA", "index": 4 },
  "tree": {
    "2.0.0": {
      "BETA": {
        "1": { "built": "2026-09-27 13:02:11", "commit": "c108c24",
               "artifacts": ["dist\\STALKER_Toolkit_2.0.0_BETA.1_c108c24.zip"] },
        "2": { "...": "..." }
      },
      "RC": { "1": { "...": "..." } }
    },
    "2.0.1": { "BETA": { "1": { "...": "..." } } }
  }
}
```

- **"下一个构建的序号" = `tree[version][prerelease]` 里现有最大序号 + 1**（该版本+该标记下第一次构建＝1）；
- 每次成功构建**追加一条**到树里（时间 + 提交 + 产物路径），于是 `version.json` 自身就是**构建史**；
- **只有 buildGUI 与 `package.ps1` 读写它**（静态锁：别处不许复制版本串）；成品 `version.txt` 由它生成。

## 三、buildGUI：**只能选，不能手打**

| 元素 | 交互 | 判据 |
|---|---|---|
| **版本号** | **下拉选择**（选项＝`tree` 的顶层键 + "新建版本号"这一个显式入口） | 无法手打任意字符串；下拉项与 `tree` 键逐项一致 |
| **标记** | **下拉选择**（`ALPHA / BETA / RC` + 该版本已有的标记，保序去重） | 下拉项与既有语义一致 |
| **序号** | **只读，自动填**＝下一个构建序号 | 与 `max(tree[v][m].keys())+1` 相等；切版本/标记时**同步刷新** |
| **完整版本号** | 单独一行**只读**显示，如 `2.0.0 BETA.4` | 与 `current` 三元组拼接结果逐字符一致；上面三者任一变化它立即更新 |
| **构建按钮** | 点下去＝走第四节的动作链 | 成功后 `dist\` 里出现对应 zip/目录；树里多一条 |

**组件要用通用的**（你这条我按 2.x 既有组件库落地，不手搓）：窗口壳与分栏用 `SplitPane`/`PageBase`、
日志用 `LogBox`（攒批、不归主滚动条管）、长任务用 `TaskShell`（进度只由引擎给、失败回主线程）、
按钮/下拉/只读标签一律走主题令牌（`theme`）与既有小组件，**不新造一套样式**。

## 四、构建实现：**只有一份 —— GUI 直接引用 CLI**

**不再有第二份构建逻辑**。做法：

1. 把"构建 + 打包"做成 **CLI 动作**（`xrkit_cli --build-package --version <V> --prerelease <M> --index <N>`），
   内部**就是**现在 `scripts/build.ps1` + `scripts/package.ps1` 那条链（真编译 → 铺 Qt → 写 README/version →
   **包内 `--smoke` 自检** → 落 `dist\`），脚本本身也改成"给 CLI/给 GUI 共用"的薄封装；
2. **GUI 只调 CLI**（`QProcess`），不自己拼 cmake/ninja/windeployqt 参数；
3. ⇒ 命令行构建与 GUI 构建**必然同结果**（同一份实现），这也是你要的"不会出现两者有差别"。

## 五、失败流（照你 2026-09-24 的口述 spec，语义不变，位置改到 `dist\`）

| # | 行为 | 判据 |
|---|---|---|
| 1 | 每次开始构建**自动存**版本，并保留上一份备份 | 备份与构建前那份逐字节相同 |
| 2 | **失败 ⇒ 版本/标记/序号回退到备份** | 失败后 `version.json` 与备份**逐字节相同** |
| 3 | 失败件移入 `dist\FAIL\`、**加构建时间戳重命名** | `dist\FAIL\build_<N>_<时间戳>\` 存在且含日志 |
| 4 | **没产出任何文件 ⇒ 删掉该构建目录** | `dist\` 与 `dist\FAIL\` 下都**没有**该目录（只留日志） |
| 5 | 有错误输出 ⇒ 日志导出到 `dist\FAIL\` | 日志非空、名字与文件夹一致 |

## 六、验收判据（自测即跑；门禁加一条能红的锁）

- **形态**：成功后 `dist\` 里 zip + 目录都在，`version.txt` 与 `version.json` 的三元组一致，**包内离屏自检过**；
- **联动**：切版本/标记后，序号与"完整版本号"行**同步**变化（判据：与 `max(index)+1` / 拼接串相等）；
- **失败流**：注入失败（预设名写错）⇒ `version.json` 逐字节回退、`dist\FAIL\build_<N>_<时间戳>\` 与日志在、`dist\` 无该目录；
- **能红的锁**：断言"失败后 `version.json` 与备份逐字节相同"+"`dist\` 下无该序号目录" —— 注入旧行为必须变红。
