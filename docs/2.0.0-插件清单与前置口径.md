# 2.0.0 插件清单与前置口径（2026-11-09）

> 用户口径：「插件管理器靠这个看模组的前置；前置是否已装**通过对比插件必须留的 GH 链接**……
> 但插件可能改名，所以还是看地址判断。或者有没有更好的方案？MC 是怎么做的？」
>
> 结论：**依赖判定用稳定 `id`，不用仓库地址**；`repo` 只作插件管理器展示/更新来源。
> 这是 MC（Fabric / Forge / Modrinth / CurseForge）的共同做法。见 §4。

## 1. `PLUGIN_INFO` 字段（全部可选；缺省见右）

| 字段 | 类型 | 含义 / 缺省 |
|---|---|---|
| `id` | str | **稳定唯一键**，小写、不改名（缺省 = 文件名去 `.py`）。依赖判定只看它。 |
| `name` | str | 显示名（缺省 = `id`） |
| `version` | str | 版本串（缺省 `"0"`；点分数字比较，非数字段退化为字符串） |
| `repo` | str | 仓库地址，**仅元数据**（管理器展示/打开链接/将来更新用）；**不参与依赖判定** |
| `depends` | dict | 必需前置：`{前置 id: 版本范围}`，如 `{"demo.base": ">=1.2,<2"}` |
| `provides` | list | 本插件额外声明的 id（虚拟包/别名），依赖可命中 |
| `replaces` | list | 本插件**取代**的旧 id（改名/合并迁移：旧 id 的依赖视为已满足） |
| `PLUGIN_API` | int | 兼容旧字段：声明插件按哪一版宿主 API 写；比宿主新 ⇒ 拒绝加载 |

`requires`（列表）仍是**跨插件服务**依赖（`net.http_get/1`），与"模组前置"分开；
若写成字典形态也接受为 `depends`（兼容旧实验）。

## 2. 版本范围语法

`*` / 空 = 任意；逗号 = AND；支持 `>=`、`>`、`<=`、`<`、`==`、`=`、`!=`、`~x.y`（>=x.y 且 <x+1）。
例：`">=1.0,<2"`、`"~1.4"`、`"==1.2.0"`、`"*"`。
（点分数字逐段比较，缺失位补 0；非数字后缀忽略——够用即可，不做完整 semver。）

## 3. 启动期判定（缺前置 ⇒ 自动禁用，不留半条注册）

1. **全部** `.py` 先 import、收 `PLUGIN_INFO`（import 失败仍按 owner 回滚并记 `registration_errors`）；
2. 建索引：`id` / `provides` / `replaces` → 插件（先到先得）；
3. 对每个插件递归解析 `depends`：
   - 找不到 id / 找得到但版本不满足 / 前置自身被禁用 / 循环依赖 ⇒ **本插件禁用**；
   - 禁用 = **不调用 `register(api)`**（一条注册都不留），记 `PluginDisabledInfo`（缺哪个 id、要求什么范围、为什么）；
4. 只对启用的插件 `register(api)`；失败回滚口径不变；
5. 启动完成后：若禁用清单非空，弹**一次**「插件管理器」对话框：
   - **所有**缺前置的插件放在**同一个框**里，每个插件一块（名称/id/版本/文件 + 逐条缺失项 + repo 链接）；
   - **不出现滚动条**（不套 QScrollArea；条目多时窗口长高）；
   - 离屏 `--smoke` 不弹（`XRKIT_SMOKE`）；
6. `--py-plugins --json` 输出结构化清单（`PYPLUGINS-JSON [...]`：file/id/name/version/repo/
   provides/depends/replaces/imports），管理器**只读 JSON**，不解析人类文本。

## 4. 为什么不用仓库地址当主键（以及 MC 怎么做）

| 方案 | 问题 |
|---|---|
| **比对 GH URL** | 仓库改名/转移后 URL 变（301 只对 HTTP，清单里存的是旧串）；monorepo 一仓多插件；fork/镜像/私有仓；本地开发插件没有 URL；大小写/`.git`/末尾斜杠写法差异 |
| **比对 id**（本方案） | 由作者声明、可长期不变；改名用 `replaces`，拆分/合并用 `provides`；repo 只负责"去哪下载/看主页" |

MC 生态：
- **Fabric** `fabric.mod.json`：`id` + `version` + `depends`/`recommends`/`suggests`/`breaks`/`conflicts`
  （键是 mod id，值是版本范围）+ `provides`（虚拟 id）；
- **Forge/NeoForge** `mods.toml`：`modId` + `version` + `[[dependencies.<modid>]]`（`modId`/`mandatory`/
  `versionRange`/`ordering`/`side`）；
- **Modrinth / CurseForge**：依赖引用**项目 ID**（Modrinth 稳定 project id + slug 别名；CurseForge 数字 projectID），
  仓库/主页 URL 只是链接。
⇒ 共同点：**id 是主键，URL 不出现在依赖图里**。

## 5. 明确不做（先钉住范围）

- 不自动下载/安装/升级前置（管理器只"说明缺什么 + 给 repo 链接"）；
- 不做传递依赖的自动修复、不做版本求解器（只做"已装是否满足"的检查）；
- 不把 `repo` 当唯一来源：本地插件可以没有 `repo`，`depends` 仍按 id 判定。

## 6. 判据

- `tests/check_plugin_deps.py`（19 项）：缺 id / 版本不满足 / 循环依赖 ⇒ 自动禁用；
  provider + 正常 consumer 仍加载；`--json` 里 id/version/repo/depends/provides 都在；
- `SHELL-SMOKE` 两条：缺前置的插件在 Hub 里被计入"已禁用"且**不算加载失败**；
- 门禁步 `plugin-deps`（`run_ci.py`）。
