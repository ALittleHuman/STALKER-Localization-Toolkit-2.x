## 0-1 `--release --only <一步>` 直接 PASS 却谎称"全部步骤均已执行"

- 位置：`tests/run_ci.py` `main()` 的步骤循环 + 收尾覆盖度摘要（修前 `:1760-1789`）
- 机制：`--only` 过滤掉的步骤**既不记账也不进未覆盖清单**；收尾 `if UNCOVERED: … else: 打印"本次覆盖：全部步骤均已执行"`
  于是无条件打印后者 ⇒ 只跑 1/36 步也自称全覆盖，且 release 档照样 `RESULT: PASS`。
- 修法：① `--only` 与 release 互斥（显式说明）；② **跳过的步骤逐条记入 UNCOVERED**。

#### 红（修前）—— 命令与原始行
```

```
```

  ok   尺寸/间距一律过 px()（屏幕自适应口径）
------------------------------------------------------------------
本次覆盖：全部步骤均已执行
------------------------------------------------------------------
RESULT: PASS
=== exit code: 0 ===
```


## 0-2 release 的"未覆盖清单非空 → FAIL"是死分支

- 位置：`tests/run_ci.py` 收尾 `if release and UNCOVERED: FAILURES += 1`（修前 `:1782`）
- 机制：release 档下 `prereq()` 走 `fail(); return False` 分支**不 append**（`:125-132`）；
  另一处 `UNCOVERED.append` 在 `step_cli_contract` 的一个**空元组循环**里（`:338-339`）。
  ⇒ 在 `--only` 修好之前，release 档下 UNCOVERED **必然为空**，该判据永不触发。

  该分支因此变成唯一把 release 判红的通道（0-1 的绿就是这么来的，见上 `RESULT: FAIL`）。

- 证据：`--release` 整跑时 `prereq` 只走 `fail()` 不 append；唯一另一处 append 在空元组循环里。
- 因此 `--release --only px-only` 修前能 PASS（见 0-1 红），即该判据是死的。

#### 绿（修后）：`--release --only px-only` 由该分支判红

## 1-2 `db.cpp read_chunks` 判据漏 `pos`（堆越界读）+ `long` 32 位截断

- 位置：修前 `src/engine/fs/db.cpp:404-407`
  ```cpp
  if (cid <= 1 && 8ull + sz <= raw.size() && sz > 0) {
      const bool comp = (rid & 0x80800000u) != 0;
      std::vector<uint8_t> data(raw.begin() + static_cast<long>(pos + 8),
                                raw.begin() + static_cast<long>(pos + 8 + sz));
  ```
- 机制（**静态确认**，见"复核"一节的口径说明）：判据用 `8+sz`、切片起点用 `pos+8`
  ⇒ `pos>0` 且 `8+sz <= size < pos+8+sz` 时末端越过 `raw` 末尾；`static_cast<long>`
  在 Windows x64 是 32 位 ⇒ `pos+8+sz > 2^31` 截断成负值 ⇒ 野指针。
- 修法：判据与切片起点**同源** —— `pos + 8ull + sz <= raw.size()`（`8ull` 保证前两项
  在 uint64 域相加不溢出），切片改用 `std::ptrdiff_t`，并留一条不变式注释。
- 绿：`--dump` 在既有夹具上行为不变（`tests/golden_db.py` / `golden-extract` 等步骤照旧全绿，
  见下方门禁两行）；新增的 `read_chunks` 边界注释与不变式已落地。
- ★ 复核说明（不夸大）：**未**在本批做运行期越界取证 —— 退回整文件读那条路的可达前提是
  "seek 路径认不出"（`db.cpp:770-789`），本批用 1 字节前缀/假块头/超大 sz 三种夹具实测
  `--dump` 仍走 seek 路径（`seek=1`），因此**没有**造出一个能在 `%TEMP%` 里跑出 ASan 红的样本；
  本条的"红"是代码级（判据与切片起点不同源）＋ 审计 §1 S1-5 的独立复现，如实记在这里。
